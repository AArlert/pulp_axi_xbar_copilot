## 3. Task 3 — 三条 SPEC_ISSUE 逐条裁决

**统摄原则（三条共用，防止"主文档恒胜/细节文档恒胜"式武断）**：spec 的 checker
期望值应取**对实际例化硬件机制精确、且不会令 checker 假红（false-fire）**的那个
读法——胜出的来源落在精确性所在之处，而非固定某一层。REV-001 对 BUG-0005 的裁决
（主文档胜）与本卡 BUG-0010 的裁决（下层部件文档胜）是**同一原则**在不同来源分布
下的两次落点，非相互矛盾。

### BUG-0010 — MaxMstTrans 粒度：扁平 vs 分桶 → **裁决：SPEC_CHANGED（采分桶）**

**事实认定（独立核验 §1）**：xbar.md L46 与 axi_pkg L489-491 均为**扁平**表述；
demux.md L70-74 明述实际机制为 **`2*2^AxiLookBits` 个（约简 ID×方向）独立计数器、
各自封顶 `MaxTrans`、各带一个目标 master 端口寄存器**。基线 `AxiIdUsedSlvPorts=3<5`
（spec §0 明钉"基线即存在假冲突 stall"）⇒ 基线真有 `2^3×2=16` 个独立计数器，扁平
读法在基线即被机制违反。

**裁决**：采信 demux.md 的按（约简 ID 桶 × 方向）分桶计数模型，补齐 spec §2.1
（MaxMstTrans 字段行）与 §5.4.1。理由：
1. **机制精确性**：demux.md L70-74 是对**实际例化子模块**（axi_xbar 每 slave 端口
   例化一个 axi_demux，其单 slave 端口即该 xbar slave 端口）的精确描述；扁平表述是
   顶层配置表的**粗略概括**。
2. **不假红**：若 checker 采扁平口径，M3/M4 跨桶场景会在 DUT（真按分桶、合法接受
   >扁平上限）时**假红**；采分桶口径与实际机制一致。
3. **来源合法、非 spec-from-RTL**：分桶细节全部来自**上游文档** demux.md（spec 开篇
   已列为可信"下层部件行为佐证"，且 spec §5.2 既有条款**已引用同一 demux.md
   §Ordering and Stalls 段落**为可信源）+ axi_pkg L510 显式"see axi_demux for
   details"指针 + spec §1 拓扑——**不触碰 RTL 实现体**。
4. **BUG-0005 非矛盾**：BUG-0005 是 xbar.md(doc) vs axi_pkg(源码**注释**、且用软性
   "should")，主文档胜；本条是 xbar.md 的**粗略概括** vs demux.md 的**机制精确**，
   二者皆为 doc，精确者胜——同一"取精确且不假红者"原则。

**orch 应用范围**（rev 只出裁决结论，spec 正文编辑 + sha256 重 pin + 状态转
SPEC_CHANGED 由 orch）：§2.1 MaxMstTrans 行 + §5.4.1 改为分桶口径（每（约简 ID×
方向）计数器独立 ≤ MaxMstTrans、各带目标端口绑定寄存器）；标注该同一计数器机制即
§5.2 stall 的底层机制（换目标落 §5.2、封顶落 §5.4，二面一体，见 demux.md L74）；
依据栏记 demux.md §Ordering and Stalls→Implementation + axi_pkg L510 + §1/§5.2。

**M2 影响**：M2-TL01（收窄三元组，两读法重合）**不受阻塞、可派发**。

### BUG-0011 — MaxSlvTrans 机制在许可来源缺失 → **裁决：SPEC_CHANGED（保上界 + 机制列上游确认，解锁弱化 checker）**

**事实认定（独立核验 §1）**：xbar.md L47 明载上界**存在**且**"per ID"**；axi_pkg
L492-494 **未提 per ID**；mux.md 全文（结构上负责 master 端口侧的子模块）**无任何**
按 ID 分桶的事务计数机制段落，`MaxWTrans`（L29）语义不同（AW→W FIFO 深度）。即：
上界的**存在**与"per ID"可溯（xbar.md），但**执行机制**（哪个子模块/分组维度/是否
硬性反压/触发点）在许可来源无处可溯；读 axi_mux.sv/axi_xbar.sv 补齐属 spec-from-RTL
红线（禁）。

**裁决**：三段式，非 arch 提案的"或上游确认（落空）/或弱化"二选一：
1. **保留 §5.4.2 的可观测上界为规范**："每 master 端口、每（master 端口侧可观测的
   前缀后）ID、在飞事务数 ≤ MaxSlvTrans"——此界直接是 xbar.md L47 的近逐字重述，
   可证伪（监视计数、>6 即红）。**"per ID" 采 xbar.md 口径**（over axi_pkg 的省略，
   同 BUG-0005 精神：主文档更具体的读法胜过较含糊的源码注释）。
2. **§5.4.3 的机制主张须限定**：现"达到上限对应端口不再接受新事务"对 MaxMstTrans
   有 demux.md L74 支撑，但对 **MaxSlvTrans 无来源**——须标注 MaxSlvTrans 的执行机制
   在许可来源未定义、列为**上游确认项**（同 BUG-0004/0002 先例，不阻塞里程碑）。
3. **解锁 M2-TL02 的弱化 checker**：M2-TL02 可落地一条**保守可观测上界监视器**
   （见 §5 指导中的不假红分组约束），但**不得**断言机制级"第 7 笔在某具体通道/
   时点被拒收"。这比 arch"裁决前不落地任何东西"**多解锁了一条可证伪的弱 checker**。

**orch 应用范围**：§5.4.2 保留（可补"per ID = master 端口侧可观测前缀后 ID、采
xbar.md 口径"的澄清）；§5.4.3 加 MaxSlvTrans 机制未定义 + 上游确认项标注；依据栏
记 xbar.md L47 + "mux.md 无机制段落"缺口 + BUG-0005/0004 先例。

**M2 影响**：M2-TL02 由"完全阻塞"转为"可派发**弱化上界 checker**（机制断言仍挂
上游确认，不派发）"。

### BUG-0012 — ATOP 原子读引发跨方向假冲突读 stall，spec 未蒸馏 → **裁决：SPEC_CHANGED（补派生条款，非阻塞）**

**事实认定（独立核验 §1）**：demux.md L83-87 **完整明载**该交互（AW 注入原子读 ID
到 AR 计数器防下溢；因只比较部分 ID → 原子读可致读通道额外假冲突 stall），且明述
为正常、非退化行为。spec §5.2/§6 均未收录。**来源完整**（非缺失、非冲突）。

**裁决**：SPEC_CHANGED——把该已文档化的外部可观测交互蒸馏为 spec 派生条款。理由：
来源完整可溯（demux.md，可信源），不蒸馏则 M2-AT01 若撞见该 stall 会缺期望值来源、
可能被误判 DUT_BUG。
- **条款落点**：建议归入 **§6（ATOP）作副作用派生条款**、并在 §5.2 加交叉引用
  （因其超出 §5.2.1"仅同方向"字面框架：一次写事件 ATOP AW 引发的读方向 stall）。
- **非阻塞确认**：M2-AT01 **核心判据**（B∧R 成对 §6.3、ID 唯一 §6.4）不受影响、
  照常落地产证据；本条仅关"额外读 stall"旁证观察的判读口径。
- **仲裁前过渡处置经核验充分**：functional_coverage `cg_atop_read_interaction`

  跨方向注入，故该 stall 出现时不触发 C3.2 假红）——二者使本条在仲裁前不致令
  M2-AT01 误红。**准予按此过渡处置放行 M2-AT01**。

**orch 应用范围**：§6 增派生条款 + §5.2 交叉引用；依据栏记 demux.md §Atomic
