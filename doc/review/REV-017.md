### Item 2 — 「重开以定义 err_slv×ATOP 应答、放行激励」不可用（选项 a/c REJECTED）

REV-016 §6.2 列了三条可选面。本卡逐条判：

- **选项 a（重开、补 err_slv×ATOP 应答条款、放行激励）：不可用。** 补一条应答
  条款需要**许可来源**。REV-012 的可证伪 rationale 明写：「五份许可来源任一处
  若定义 err_slv 对 atomic-load 的应答形态，则 SPEC_ISSUE 消解」；该 grep 判据
  至今**无新证据推翻**（本卡未在 `xbar.md`/`demux.md`/`mux.md`/`axi_pkg.sv`/
  `xbar.sv` 头注释找到任何 err_slv×atomic 应答定义）。`axi_atop_filter` 自身
  RTL 确会注入 B（并按 `ATOP_R_RESP` 注入 R）——但那是**被测 RTL 的行为**，
  不是许可来源；把它抄成 checker 期望值正是 CLAUDE.md 不变量 #4 与 §4.3/§6.3
  两读互斥所禁的 spec-from-RTL。故「放行激励 + 现补条款」= 让 DV 面对一个**没有
  合法期望值来源**的判决，与 BUG-0032 当初禁它的理由**逐字同构**。放行 = 制造
  一批无源 checker，**否决**。
- **选项 c（只在稀疏 `Connectivity` 腿触发）：不可用。** 稀疏腿的 err_slv
  （`axi_xbar_unmuxed.sv:238`）同样落在 §4 clause 7 的未定义面上（REV-016 §6.2
  已指出），换腿不改变「err_slv×ATOP 应答无源」这一根，**否决**。

⇒ 唯一与不变量 #4、与 REV-012 未被推翻的事实认定一致的面是**维持约束**。

### Item 3 — 处置：**环境约束延展至 M4 + `axi_atop_filter` FSM 书面豁免**（选项 b，PASS）

裁决路径：

1. **约束延展。** §4 clause 7 的环境约束「不向译码未命中地址发起任何 ATOP」
   由 M3 **延展至 M4**。理由：约束的**目的**是让「err_slv×ATOP 应答」这一无源
   组合构造性不可触发，从而 checker 永不面对无源期望值——该目的在 M4 与 M3
   **完全相同**（M4 只换覆盖率口径，不改许可来源的沉默）。REV-013 当初收窄为
   M3 并非因 M4 豁免，而是「M4 无 artifact 承载 + BUG-0032 刻意留 M4 作重开点、
   不预裁」；**本卡即那次重开**，据 Change record #7 与 REV-013 预留路径行使
   授权，把约束的持久归宿从「M3」补齐为「M3 与 M4」。
2. **FSM 记为环境约束致不可达 + rev 签核书面豁免。** `axi_atop_filter` 的
   W/R FSM 中**仅经被禁激励可达**的状态与迁移弧（W 侧 5 状态 / 19 弧、R 侧
   2 状态 / 多弧，清单见证据 §4 第 1/2 条），在 M4 六类收敛中按 spec §0 item 4
   **既有**的「有 bin 但 <90% ⇒ 逐条修补或**出具 rev 签核的书面豁免**」分支
   处置——成因＝本环境约束（非缺口、非漏测）。**不需新造豁免机制**：§0 item 4
   已提供该出口。注意此处**不适用** §0 item 4 的「无 bin ⇒ N/A」三态规则——
   atop_filter FSM **有 bin**（7.14%），属「有 bin 但受约束不可达」，须走**书面
   豁免**而非自动 N/A。豁免后该 FSM **不计入 ≥90% 的分子与分母**。
3. **守卫被荣誉，而非解除。** 本裁决**不放行**被禁激励，故 BUG-0032 guard
   「约束不被悄悄解除」**继续有效并延展至 M4**：M4 签核的机械抽查形态不变——
   `grep` 未命中地址构造点确认 `atop ≡ '0'`，或由 SVA/covergroup 给「未命中
   地址上 `aw.atop != '0'`」计数、该数须为 0；非 0 即约束被解除、须再走仲裁。
   本裁决满足 guard 的前置要求「先取得 spec 条款再动 env」——取得的条款正是
   延展后的 §4 clause 7 + 本豁免。

## Guidance（原则 + 方向，不代写正文/代码）

- **无源即不可判，不可判即不可放行。** 冲突的解不是「想办法把 FSM 点亮」，而是
  认清点亮它=向一个许可来源沉默的组合发起激励。当激励侧一动，checker 的期望值
  就只能来自被测 RTL——那一刻覆盖率的「绿」是靠放弃不变量 #4 换来的。覆盖率是
  手段不是目的；一个**结构上只有无源期望值**的 FSM 分支，正确姿态是书面豁免 +
  记录成因，不是凑激励。
- **豁免 ≠ 降级 ≠ 遗忘。** §0 item 4 已把「有 bin 但 <90% → rev 签核书面豁免」
  和「无 bin → N/A」分成两条路。atop_filter FSM 走前者：它**有** bin、成因**已
  查实**（环境约束）、逐弧**可列**（证据 §4）、解锁条件**明确**（补许可来源 +
  重开 BUG-0032）。这四点齐备才配叫「书面豁免」，缺一条就退回「遗漏」。
- **延展约束是补齐持久归宿，不是新增范围。** REV-012 为 BUG-0032 争的就是
  「约束的持久归宿是 spec 正文，不是仅 testplan/guard」。M4 腿当初悬空是因为
  无人重开；本卡重开后，把「M3」补成「M3 与 M4」是让 spec 说完整话，不是发明
  新约束。
- **REV-013 的 (a)+(b) 要件不可只做一半。** spec 断言与 testplan 承载必须同拍
  落地，否则下一个读 §4 的人（或 M4 签核的机械抽查）会看到 spec 说 M4 有约束、
  testplan 只有 M3——那正是 Retention 漂移。故本裁决把 testplan 边列为硬条件。
