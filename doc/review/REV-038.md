### §16 三决策点逐条裁决

**D-1 可执行命令的载体 —— 批准设计首选（内联 `check=`），有条件。**
- **终态：内联在正文标记的 `check=`（设计首选侧）。** 依据：FB-23 的教训正是"复现
  命令须与它证明的数字同行 travel"——把命令从数字身边挪走（反方"全收进 guards.md/
  baseline、正文只引 guard id"）会**重造 FB-23 的失配形态**（命令与数字分离、静默
  腐烂）。F1/F7 的价值就在数字与命令同处。
- **条件**：安全由 §12 执行器契约兜底、**而非靠隐藏命令**（设计原话），故 D-1 成立
  的前提是 A-c1（收窄 `python3 scripts/<x>.py`）+ A-c3（两条 KILL 自证到位）。
- **界定**：内联（prose count/bidiff）与 guards.md（regression guard 载体，F4）**并非
  互斥**——前者是断言的复现命令同行，后者是守卫的归属表。两者各司其职，不合并。

**D-2 F6 CAP 与 `root_cause` 例外 —— 推翻设计首选，改判"全列统一 CAP、无 root_cause
例外"。**
- **终态：单一字节 CAP（2000B）覆盖 `doc/bugs.md`/`testplan.md`/`coverage-waivers.md`
  三张机器表的全部数据单元格，`root_cause` 不设例外。** 存量超限格走 F10 baseline
  （rev_ref）+ 迁往详情页。
- **推翻依据（两条，可证伪）**：
  1. `workflow/bugs.md`「The failure record」白纸黑字：详情页存在正是因为
     "3000-character table cells proved unreadable once"，"the detail page is the
     primary carrier, the row is the index"。一条 1111 字符的 `root_cause`（设计
     引为"正当长内容"）恰恰属于详情页 `## rca`、**不属于**汇总表——给它开表内例外
     等于重新合法化框架已定性的反模式。
  2. 实测（T7）：超限的大行**其 `summary` 单元格也 >2000B**（963 汉字 ≈ 2900B），而
     `summary` 是可扫描索引、**不可能**豁免。⇒ 设计的"仅 root_cause 例外"救不了大行
     （summary 照样触上限），例外只带来"一表两规"的不一致，**零收益**。统一 CAP 更
     简单（discipline §3 外科手术/最小规则），且与 F5 详情页强制同向。
- **可证伪作废点**：若能举出某列的**合法最小内容**证明既超 2000B、又无法迁入详情页，
  则该列的统一 CAP 对它作废（预期零个这样的列）。

**D-3 F7 启发式去留 —— 批准 ship（否决 deferred），但把严重度从"红"降为"warning"。**
- **终态：ship，但 F7 首版为 warning（advisory，不阻塞），非 hard-red。** 正则集关进
  `.claude/skills/doc-mechanization/SKILL.md`（§14）可迭代；升级为红是**将来**在观测到
  N 次零误报后的 rev 决策。
- **依据**：(1) 否决 deferred——触发器**已响三次**（BUG-0052 路径漂移 / FB-25 /
  C1 删 `当前已改` 快照 T8），discipline §2"触发即 ship"成立，与 REV-037 对 BUG-0052
  死引用检查"三响即建"同理。(2) 降为 warning——F7 是十族中**唯一**启发式、可误伤
  正当正文的族（设计自陈"天生必不完备"）；一个高误报的**硬门**会训练人去禁用门，

## §B 五项独立裁决

**B.1 — F10 baseline 一次性入 baseline 的边界。**
**终态：允许一次性入 baseline，但边界为"经 rev 审阅的枚举清单 + 排除在飞 bug 位点"，
非"当前所有违规一律追认"。** 规模实测：存量 checklist guard 22 条（T5）+ F6 超限格
3（T7）+ F1 散落计数数十处 + F7 ~1，量级中等、可在一张卡内评审。硬边界四条：
(a) 只准追认 docsx **落地那一 commit 已存在**的违规；(b) **任何已有 OPEN/FIXING bug 行
下令订正的位点不得入 baseline**——BUG-0052 的 7 处死引用、BUG-0061 的 3 处污染 paths
必须**修**而非豁免，否则 baseline 沦为把未闭 bug"洗绿"的通道（这是本条最锋利的一刀）;
(c) 每行 `rev_ref` 必填且指向一份**枚举了被追认位点**的 REV/BUG（批量可引一条 REV，
但该 REV 须按族列清位点数，使"多追认一处即计数不符"可证伪）；(d) prune-on-fix——已修
即须 prune（F10 反向已强制）；baseline 非永久赦免。

**B.2 — BUG-0068 两问。**

  (i) 同 bullet 上句"该台账就是那份记录本身"的**自禁重复**、(ii) grep 全仓零消费者、
