**退出码语义补验（rev 亲算）**：(b) 取的是 `subprocess` 的 `.returncode`——在 POSIX
下若子进程被信号杀死，Python 会返回**负值**（`-signum`）；若 `simv` 自身以非零码
`exit()` 则为正值。详情页 `rca chain` 把"日志尾部横幅完整（仿真跑到 `$finish`）却
退出码非零"归因为"末段清理/信号级瞬时状况"，与此一致：日志能写完整横幅说明仿真主体
已结束、`-l RUN_LOG` 已 flush，异常发生在进程收尾阶段。**但该次运行的 `rc` 具体值
（正/负、signum）当时未被记录**——regress.py 只把非零 `rc` 折叠成字面量 `"sim
process exited nonzero"`，判别性数据（信号号/stderr）已随那次运行丢失、**事后不可
还原**。此点对 Q1（是否有未尝试的低成本诊断）与 Q3（guard 措辞）均关键。

**核验结论**：BUG-0043 详情页/行内对退出码来源（d）、脚本内建 clean（a）、`rc!=0
→FAIL` 有意设计（c）、三次独立运行两清一异 + 0.4.10 第四次全量干净的事实链，经
rev 独立复算**一致无误**。唯一需订正的措辞见 §2 Q4（suspect 列）。

### Q1 — 本条是否需要新的调查，还是现有记录已足够支撑终态化？

**足够支撑终态化，无未被现有材料排除的低成本诊断步骤。** 逐一核验可能的"还没试
过"的诊断：

- **陈旧构建产物**（TOOL_ENV 常见子因）——(a) 证 regress.py 每批前强制 `make
  clean`，三次运行均从干净库起步，**已排除**。
- **编译期问题**——详情页 rca (a) 已排除（该次确实产出完整仿真报告尾部横幅，编译
  失败不会有仿真横幅），rev 复核 (d) 的 recipe 结构支持此推断（`simv` 是 `run:`
  依赖 `compile` 之后才执行的末行）。
- **判决/代码回归**——rca (b)(c) 已排除（UVM_ERROR/FATAL 计数与 SVA summary 干净，
  同一 checker 对同一激励在另两次运行给出一致干净判决；BUG-0042 新增路径在
  `FallThrough=1'b0` 基线下恒空）。**关键佐证**：若是确定性代码回归，理应每次复现，
  不会两清一异——两次干净复现本身即"非代码回归"假设的直接证伪材料。
- **唯一真正"未采集"的判别性数据 = 那次异常退出的信号号/stderr**（补验段）。但它
  **已随该次运行永久丢失**，且 regress.py 当前只保留整数 `rc` 折叠后的字面量、不留

  间歇现象（三次两清一异 + 第四次全量干净，命中频率极低且触发条件不可定位），
  重跑大概率仍绿、不构成新证据（本卡背景与 discipline 均已言明）。强行提高命中率

  没有先行改造 regress.py 采集信号也仍无法定位——而改造 regress.py 属新功能，不在
  本条自动授权范围（详情页 `## fix` 已自陈，rev 认同）。

⇒ **不存在"现有材料本该排除却没排除"的低成本诊断**。现状（频率极低 + 触发条件
不可定位 + 判别数据已丢失且不可事后还原）已足够支撑终态。**结论：pass，无需新调查。**

### Q2 — 终态处置：WONTFIX vs ACCEPTED@M\<n\>

**采纳 WONTFIX（accepted-transient）。排除 ACCEPTED@M\<n\>。**

**为何是 WONTFIX：**
1. **无可修缺陷、无待办工作。** `rc!=0 → FAIL` 是 (c) 证实的**有意设计**（`vcs-2018.mk`
   头注释原则："abnormal process exit is never evidence of a clean run"）——门禁**正确
   地**做了它该做的事，TB/脚本侧**无 bug 可修**。这不是"修不动"，是"没有 fix 对象"。
2. **TOOL_ENV 的终态对应。** `workflow/bugs.md` 终态对应表：`WONTFIX ↔ 任何
   cost/benefit 说停的类别，记录仍需 rca + guard-or-rationale`。本条 rca 已填、
   guard（checklist 永久观察机制）已在，要件齐备。TOOL_ENV 的处置指引本身（"clean
   rebuild + minimal repro + record so the next person greps it"）**不要求 rev
   仲裁**——见 Q4 对"为何本条仍需一次正式记录背书"的判断。
3. **先例吻合。** BUG-0030（k）是同类 TOOL_ENV/env-quirk：不可机械复现、guard 只能是
   checklist 性质的永久记录，最终 WONTFIX/suspect=TB。本条与之同构。

**为何不是 ACCEPTED@M\<n\>：**
ACCEPTED 的语义是"analyzed, **scheduled** debt"——须有到期里程碑 + **可证伪的
解锁/复议条件**。本条**没有可排入日程的工作**：没有计划中的 fix，没有"到 M5 会
变得可诊断"的机制变化，没有一个"届时若 X 成立则复议"的可证伪门槛可挂。若强设
ACCEPTED@M5，到 M5 复议时因"什么都没变"只会原样再判 WONTFIX——这正是 `docs.py`
ACCEPTED 契约与 REV-011 §2.3/G1 红线所禁的"用状态表达一个永不到期的软承诺"
（"ACCEPTED must name a falsifiable due condition; WONTFIX may not mean 'later'"）。
把"复现一个间歇现象"排成到期债，是把不可调度之事伪装成可调度——不诚实。**故
ACCEPTED 不适用；WONTFIX 是准确的终态。** （机器上 ACCEPTED@M5 因 5<4 假而不过期、
(i) 可通过门禁——但"能过机器门"不等于"语义正确"，rev 判据是后者。）

**结论：pass —— 终态 = WONTFIX（accepted-transient）。**

### Q3 — WONTFIX 下 `## regression_guard` 措辞是否需调整

**需调整——现措辞读作"仍在观察中"，与"已终态化"冲突，须收紧。** 现 `note`
（"后续任何 `make regress` 若再次出现…先按本条比对…若发现可复现的触发条件才需要
把本条…升级…并考虑要不要真正修"）作为**永久 grep/比对机制本身是对的**（与 BUG-0030
guard 同型、应保留），但三处须改：

1. **声明终态。** 开宗明义本条已 WONTFIX（accepted-transient）、非 OPEN 观察态。
2. **明确复现不重开本行。** 未来若再现同型现象，动作是"在本页追加一次出现记录 +
   比对现象一致性"，**不重开 BUG-0043 行**；只有**定位到可复现触发条件**（特定 TEST
   组合 / 特定资源压力窗口）才构成离开 WONTFIX 的**可证伪解锁条件**——届时开**新**
   bug 行（带确定性 repro）承接，本条作为 `## similar` 先例被引。
3. **把"机械化 TODO"写诚实（guard 契约："what it should become, or why it
   cannot"）。** 现 guard 隐含"考虑给 regress.py 加自动重跑"——rev **反对将其列为
   fix 方向**：详情页 `## fix` 已正确指出自动重跑会**掩盖** TOOL_ENV 根因而非解决它
   （放宽 gate 侧，discipline rule 2）。**不可机械化为确定性 SVA/script repro**（间歇、
   触发条件不可判定）——这一点应明写为"why it cannot"。**唯一有价值的可机械化方向**
   是**诊断采集**而非重跑：本卡 §1 补验发现，那次异常的判别性数据（进程死亡信号号 /
   stderr）当时未被留存、事后不可还原，因 regress.py 只把非零 `rc` 折叠成字面量。
   guard 可把"下次再现时采集 `rc` 符号/signum 与子进程 stderr"记为一条**待兑现的
   低成本观测改进**（供 orch 评估，属新功能不在本卡授权内），使下一次再现能一次定位
   "信号杀死 vs 自身非零 exit"——**这才是让本 guard 从"留意"升级为可行动的方向**，
   而非重跑。

**建议文本（orch 应用，rev 不越权直接改该文件）：**

```

type: checklist
paths: sim/Makefile (`run:` 目标)、scripts/regress.py
ref: 无可执行的确定性复现命令（间歇性现象，本条 WONTFIX 终态）
note（终态说明）: 本条已 WONTFIX（accepted-transient）——`rc!=0→FAIL` 是有意

丢失且不可事后还原，命中频率极低、触发条件不可定位，cost/benefit 判定停手。
note（复现处置）: 后续任何 `make regress` 若再现"日志内容干净但 `[sim process
exited nonzero]`"型 FAIL，先按本条比对现象一致性（同 VM、瞬时退出码异常、日志
内容本身无错误字样），吻合则在本页**追加一次出现记录**——**不重开本行**。
note（可证伪解锁）: 仅当定位到**可复现触发条件**（特定 TEST 组合 / 特定资源

先例；WONTFIX 本身不因单纯再现而反转。
note（不可机械化理由 + 唯一可行改进）: 本现象**不能**机械化为确定性 SVA/script
repro（间歇、触发不可判定）。**不建议**给 `run:` 加自动重跑——那会掩盖 TOOL_ENV

现 regress.py 只保留折叠后的整数 `rc`，丢弃了进程死亡信号号 / stderr；下次再现前
若低成本地让 regress.py 记录 `rc` 符号（POSIX 负值=被信号杀死）与子进程 stderr，

```

**结论：需调整，建议文本如上。**

- **终态不得表达"以后再做"（Q2 复述为原则）。** WONTFIX 与 ACCEPTED 的分界不是
  "会不会再看"，而是"有没有可调度的工作 + 可证伪的到期条件"。本条无二者 ⇒ WONTFIX。
  把不可复现的间歇现象塞进 ACCEPTED 只是给 OPEN 换个名字拖过签核——机器（h）能被
  ACCEPTED@M5 骗过（5<4 不过期），但那是 gate 的宽处，不是 rev 判据的宽处。
- **guard 的"机械化 TODO"要么给出脚本/SVA，要么写清为何不能（Q3）。** 本条正确的
  写法是双写：why-it-cannot（间歇不可判定 ⇒ 无确定性 repro）+ 一条真正低成本的观测
  改进（下次再现采集信号号/stderr）——而**不是**含糊的"考虑要不要加重试"。重试是
  掩盖 TOOL_ENV 根因的放宽侧动作，详情页已正确拒绝，guard 不应给它留口子。
- **粗/细分离的诚实。** suspect=TB 是扫描列的粗粒度妥协，不代表这是 TB 代码缺陷；
  真相在详情页 `## taxonomy`=TOOL_ENV。保留这一分离、别为省事把 class 也读成 TB。
