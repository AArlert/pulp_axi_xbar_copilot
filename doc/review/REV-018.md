### 第 3 项 — 提案 1（`FallThrough` 维度归属）：**裁 (a) 增维**

- **理由**：`FallThrough=1` 是 §2.1 spec 合法字段值，其 fall-through 组合分支
  （`axi_demux_simple` 内）是**真实、可达、spec 合法**的 DUT 逻辑，仅从未被置位
  激励。**书面豁免应留给「环境约束致构造性不可达」的逻辑（如 atop_filter FSM，

  「懒得测就豁免」，侵蚀 §0 item 4「有 bin 但 <90% ⇒ 逐条修补*或*书面豁免」里
  「修补」应作首选的纪律。取 (a) 让 M4-FT01 成为该维度的代表配置点（沿用 M3
  已用的「声明式子集：每维每取值至少一次」路数，一个 `FallThrough=1` 配置点即
  足，非全交叉），既给 FT01 spec 归属、又以真实场景收敛该分支，优于豁免。
- **orch 应用（走 spec 修改记录 + 重 pin，rev 不代改正文）**：§0 #3 矩阵尾部

  豁免台账为此分支留豁免行。

### 第 4 项 — 提案 2（§4 clause 7「译码未命中」范围）：**裁 (b) 确认宽读为有意保守**

- **理由**（不是「维持现状省事」，而是有正向依据）：
  1. **运行时可变性耦合**：§3.4.2 default port 使能位/索引运行时可变，且
     **M4-RC01 本卡即注册了「运行中关闭 default port」**。取 (a)（允许对「未命中
     但经 default port 路由」地址发 ATOP）要求 env 逐拍确知某地址「安全地经
     default 路由」；一旦 RC01 中途关掉该 default port，原「安全」地址瞬变为
     err_slv 路由——(a) 把一个**移动靶**引入约束，(b) 用「对**任何**未命中地址
     一律不发 ATOP」保持约束在运行时可变下**恒稳、无耦合**。
  2. **零功能增益**：(a) 放开的唯一路径「ATOP 经 default port 抵达真实 master
     端口」的 ATOP 语义已由 M2-AT01/M3-AT02（ATOP 打命中地址）覆盖；且 atop_filter
     在 err_slv 内、default-port 路径本就不经它（arch 自述，核实成立），故 (a)
     对 M4 六类收敛**不解任何缺口**。
  3. arch 自评低优先、非阻塞，与上述一致。
- **结论**：宽读法保守安全、维护成本更低、运行时稳健且不遮蔽任何**未覆盖**的
  功能面。**不生成**「ATOP 经 default port 路由」候选行。若将来覆盖率分析证明
  存在真实缺口需该路径，按 BUG-0032 既有重开路径再议（同 REV-012 可证伪
  rationale 机制）。
- **本卡选择明确裁决而非待议的理由**：正因与本卡同批注册的 M4-RC01 存在运行时
  耦合，留两可会给 M4-RC01 的 env 构造埋下歧义，现在钉死「一律不发」最简、最稳。
- **orch 应用（走 spec 修改记录 + 重 pin）**：§4 clause 7 的「译码未命中地址」
  **保持宽读不改语义**，仅**追加一句 rationale 明注**其为有意保守（成因＝运行时
  可变下的恒稳性 + 该路径 ATOP 语义已由命中地址场景覆盖、零功能增益）。

### 第 5 项 — atop_filter FSM「不提案」判断：**成立（PASS）**

该 FSM 书面豁免本体是 M4 签核 artifact（REV-017 条件 3），非本卡产出，正确
留待签核，本卡不重复出具。

## Guidance（原则 + 方向，不代写 checker/RTL/TB）

- **覆盖率是动机，spec 是判据——两者别混进同一个断言。** M4-AW01/M4-FT01 都是
  「结构缺口驱动的功能激励」：正确姿态是 spec 性质当判决门 + 结构角落当非判决
  cover。一旦把「重试路径已进入」「W 与 AW 同拍」写成 pass 判据，期望值就落到
  被测 RTL 上（不变量 #4），且撞 §5.5.4/§7.4.3 的「非可锁定外部行为/禁固定拍数」
  红线。M2-WO01 已立此先例，四条新行须一体遵循。
