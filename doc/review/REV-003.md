## 2. 逐项核验

### 2.1 VCS-2018.09-SP2 拒绝是否真实可复现 —— 通过（独立复现）

用与 `scripts/make/vcs-2018.mk` 完全同源的编译旗标（`-full64 -sverilog
-timescale=1ns/1ps -assert svaext -debug_access+all -kdb +vcs+lic+wait` +
`--no-as-needed` LDFLAGS + novas PLI）编译一个最小探针（interface + 独立 module +
`bind <interface> <module>`），报错逐字匹配：

```
Error-[IIM] Illegal instantiation of module
  Instantiation of module 'chk' is illegal.
  Interface "my_if" has a module instantiation which is not allowed.
```

与 `tb/sva/axi_chan_sva.sv` 头注释、`tb/sva_bind.sv` 头注释中记录的错误签名
（`Error-[IIM] ... Interface has a module instantiation which is not allowed`）
一致。判定：DV 的工具限制主张**属实**，非误读或可绕过的用法错误——这是 VCS
O-2018 对"module 直接 bind 进 interface 作用域"的已知限制类别，任何后续在本项目
中对任意接口做 `bind <interface_type> <module>` 的尝试都会撞见同一限制。

### 2.2 直接例化是否保真（断言内容 + 观测信号范围不变）—— 通过

- `tb/sva_bind.sv` 的两个 generate 循环位于 `tb_top.sv` 第 97 行，晚于第 46-48
  行 `slv_if`/`mst_if` 例化，例化顺序合法；每端口一份 `axi_chan_sva` 实例，端口
  数（6 slave + 8 master）与 C1.2 基线一致。
- `axi_chan_sva` 的泛型 `interface axi` 端口仅通过内部 `assign` 读取与
  `slvport_if`/`mstport_if`（`tb/axi_if.sv`）同名的通道信号（`aw_*`/`w_*`/
  `b_*`/`ar_*`/`r_*`/`clk_i`/`rst_ni`）；这些接口本身是 TB 侧信号总线，经
  `` `AXI_ASSIGN_TO_REQ``/`` `AXI_ASSIGN_FROM_RESP `` 等宏与 DUT 的
  `slv_req`/`slv_resp`/`mst_req`/`mst_resp` struct 端口做接线（`tb_top.sv`
  55-62 行），并非对 `i_xbar_dut` 内部信号的穿透读取——`axi_chan_sva` 与 DUT
  之间隔着 TB 自己的连线层，观测边界与"外部可见 AXI4 通道信号"的设计前提相符，
  未见 DUT-internal reach-through。
- 断言集（C2.1 握手稳定 / C2.2 复位空闲 / C2.3 LAST-vs-len / C2.4 禁固定拍数 /
  C2.5 禁仲裁序）在 `axi_chan_sva.sv` 内容与挂接机制无关——`bind` 与直接例化
  两种机制对同一份 module body 是等价的信号连接方式，不改变 assert property 的
  文本、触发条件或 `disable iff` 语义。挂接机制替换是纯粹的连接语法差异，不是
  断言内容差异。
- 结论：DV「机制替换、断言内容/DUT 可观测行为未变」的自述**核实成立**。

### 2.3 证据侧交叉印证 —— 通过

`doc/evidence/v0.1.0/M1-01.log`：line 1 `make run TEST=m1_01_smoke_test SEED=1`
