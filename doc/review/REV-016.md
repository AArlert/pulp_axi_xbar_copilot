## 3. 卡片问题 3 — "等"字边界：**已经涵盖**（本裁决是**澄清**，不是范围扩张）

三条独立依据，指向同一读法：

1. **item 4 自身的中心语是"实例"，枚举是举例。** L25 原文"DUT 范围 =
   `axi_xbar` 及其**全部强制内部子模块实例**"——限定词是"**全部**"与"**强制**"
   （= 该配置下必然被例化），冒号后的名字串以"等"收尾，是**举例**而非定义。
   若读作闭合清单，"全部"二字即成赘语。
2. **item 5（L26）已经把判据写死为"是否被例化"，且明文含"间接"。** 原文：
   "…及其余**不被 `axi_xbar` 例化**的 `vendor/axi/src/` 模块（**仅当作为
   `axi_xbar` 子模块被间接例化时才计入 #4 口径**）"。"间接例化即计入 #4"
   是 pinned spec 已有的、无歧义的句子——`addr_decode_dync` 正是被
   `addr_decode` 间接例化的 `axi_xbar` 子模块。**item 5 的这一句本身就已经
   排除了"闭合清单"读法**，只是它藏在"范围外"行里，而 item 4 的枚举句在视觉上
   压过了它。BUG-0038 的真实病灶是 **item 4 与 item 5 的表述不对称**，不是
   spec 真的沉默。
3. **REV-001 §3.3 C2 的原始裁决意图是"按例化关系归类"。** L103-107 的论证
   是：`axi_xbar` **恒例化** `axi_xbar_unmuxed`，故它与"**从不被 `axi_xbar`
   例化**的 `axi_lite_xbar`/`axi_interleaved_xbar` 性质完全不同"；L109 更
   直白："覆盖率 ≥90% 口径**必然把它们纳入层次**"。C2 采用的判据是
   **例化关系**，不是**名字是否被列出**，也不是**文件位于哪个上游库目录**。
   把同一判据递归应用一层，`addr_decode_dync`/`axi_demux_simple` 必然在内。

**故裁决：§0 item 4 的"等"字兜底 = 例化闭包**，`addr_decode_dync`、
`axi_demux_simple`、`axi_atop_filter`（`ATOPs=1` 时）、`axi_multicut`
（`PipelineStages>0` 时）以及这些模块内部例化的 common_cells 原语
（`spill_register`/`rr_arb_tree`/`fifo_v3`/`counter` 等）**均已在范围内**。

**同时明确两条边界**，防止澄清被读成新政策：

- **判据只有一条：是否出现在 `axi_xbar` 顶层实例的子树内**。与文件属于
  `vendor/axi/src/` 还是 `vendor/common_cells/src/` 无关——REV-001 的判据里
  从来没有"库目录"这个维度，item 5 现文那句"`vendor/axi/src/` 模块"是**举例
  时带出的目录名**，若被读成"只有 axi 库模块才可能计入"，将与 C2 亲自救回的
  `addr_decode`（common_cells 模块）自相矛盾。这条不一致由 P-REV016-2 消除。
- **若有人认为"通用库原语不该受 ≥90% 约束"**，那是一条**实质性的新政策**
  （缩小 pinned 范围），必须走它自己的 spec 变更提案，**不能**藏在本次澄清里。
  本裁决不予采纳，理由：`doc/milestone.md` L61-62 已经给了正确的出口——
  "缺口逐条或修或**书面豁免（豁免须 rev 签核）**"。通用原语的不可达参数化
  （如 `spill_register` 的 `Bypass` 分支、`fifo_v3` 的深度边界）恰恰是
  **可达性豁免**的教科书对象，写一次不可达性论证即可，而不是把它们从范围里
  抹掉——后者会让"没测"与"测不到"在仪表盘上再次同形，正是 BUG-0038 guard

## 4. 卡片问题 4 — 判定可判定性：**逐（模块,类型）判，空白 = N/A（既非恒真也非恒假），且 N/A 必须具名留痕**

`doc/milestone.md` L57-62 的 M4 门是"六类 ≥90%"，`make cov` 只产 urg 报告
（sim/Makefile:108-109），**当前不存在任何机械化的覆盖率门**——所以本条给的是
一个"人工执行也不含糊、将来机械化时可直接照抄"的口径：

**判定单位** = （模块, 类型）二元组。模块 = 例化闭包（§3）中的成员；数字取
**该模块在 `axi_xbar` 实例子树内全部实例的合并值**（urg module 页；若该模块
在子树外另有实例，须改用实例/层次报告限定到子树，不得默认 module 页只含子树
实例）。类型 = `line/cond/fsm/tgl/branch/assert` 六者。

**三态规则**：

| 报告形态 | 判定 | 后续动作 |
|---|---|---|
| 该（模块,类型）**无 bin**（报告空白） | **N/A** —— 既不计入分子，也不计入分母 | 必须在覆盖率记录里逐条写明**已核实的**成因（"模块体无过程语句、仅例化子模块"/"本模块无 FSM 构造"/"本流程下连续赋值不计 line bin"…），成因须可复核 |
| 有 bin 且 ≥90% | PASS | — |
| 有 bin 且 <90% | FAIL | 逐条修补，或写 rev 签核的书面豁免（milestone.md L61-62） |

**明令禁止的三种记法**：空白记作 **0%**（会制造无法关闭的假缺口）；空白记作
**100%** 或直接省略不列（会把"没有测量对象"洗成"已达标"）；以及**用某模块
的六类全 N/A 去代表其子模块已达标**。

**对本议题两个 wrapper 的具体结论**：

- `addr_decode`：Line/Cond/Branch/Assert = **N/A**（成因已核实，§1.1(i)：
  模块体只有一个子例化）；Toggle 有 bin（证据 §3.3 L150-165，43.90~48.78%）
  ⇒ **须判 ≥90%，当前 FAIL**，进缺口清单。真正的判决压力转移到闭包内的
  `addr_decode_dync`（§1.1(j) 真逻辑所在），它必须出现在重测报告里。
- `axi_demux`：Toggle 同理须判（62.01~63.19%，当前 FAIL）；Line/Cond/Branch
  记 N/A **之前必须先核实成因**（§1.2：该模块有 4 条连续赋值，"结构性空白"

## 6. 卡片问题 6 — `axi_atop_filter`：**归属同一"等"字问题，本裁决一并覆盖**；但其**可达性**是另一个议题，必须单独登记

### 6.1 归属（本卡覆盖）

`axi_atop_filter` 在 `ATOPs=1` 时由 `axi_err_slv` **无条件**例化
（`axi_err_slv.sv:45-58`），而 `axi_err_slv` 由 `axi_xbar_unmuxed` 每 slave
端口无条件例化（:195）——即在 `ATOPs=1` 的配置下它是**强制内部子模块**，
按 §3 的闭包口径**在范围内**，无需为它单开仲裁。证据 §3.7（L213-215）把它
判为"'等'字兜底范围内"这一**结论**正确，**理由（例化父模块）错误**（§1.3）。
`ATOPs=0` 配置点（cfgD）下不例化 ⇒ 该配置点的闭包成员表里没有它，这与"强制"
定义自洽（闭包按配置求值，见 P-REV016-1 措辞）。

### 6.2 可达性（**不在本卡范围**，必须另案）

本卡认定层次事实时顺带撞见一个会直接决定 M4 能否收敛的事实，按
discipline.md §3"mention it"= 必须落台账的规则，写在这里：

- **证据 §4 第 1 条（L238-247）给出的根因不成立。** 它称"全部 ATOP 序列只用
  `ATOP_LOAD_ADD`，AtomicLoad 类不带 W burst，故 `ABSORB_W`/`BLOCK_AW`/
  `HOLD_B`/`INJECT_B`/`WAIT_R` 从未被激励"。rev 亲读
  `axi_atop_filter.sv:137`：离开 `W_FEEDTHROUGH` 的**唯一**条件是
  `slv_req_i.aw_valid && slv_req_i.aw.atop[5:4] != axi_pkg::ATOP_NONE`。
  而 `tb/seq_lib.sv:375-377/1475-1477` 的 `ATOP_LOAD_ADD` = `{ATOP_ATOMICLOAD,
  …}`，`axi_pkg.sv:415` `ATOP_ATOMICLOAD = 2'b10` ≠ `axi_pkg.sv:400`
  `ATOP_NONE = 2'b00` —— **现有编码完全满足该条件**。读侧同理
  （:142 `aw.atop[ATOP_R_RESP]`，`axi_pkg.sv:447` bit5，AtomicLoad 置位）。
  故"换成 AtomicCompare 类编码就能补上"这一方向是**错的**。
- **真正的必要条件**：该 DUT 层次内 `axi_atop_filter` 的**全部**实例都在
  `axi_err_slv` 里（§1.3）。要进入那些状态，必须让一笔 `atop != 0` 的 AW
  **抵达某个 err_slv**，即（基线全连接下）**打到译码未命中地址**；或（稀疏
  `Connectivity` 配置点下）打到未连接的 (i,j) 对（`axi_xbar_unmuxed.sv:238`
  那个 err_slv）。
- **而这正是 pinned spec §4 clause 7（L163-176）以环境约束明令禁止的组合**：
  "M3 全部场景**不向译码未命中地址发起任何 ATOP**…使上述未定义情形**构造性
  不可触发**"（BUG-0032 裁决，REV-012/REV-013）。REV-013 把该约束从 `M3/M4`

  "**M4 覆盖率收敛若需触发该组合须重开仲裁**"。

即：**M4 六类基线里最大的单一缺口（atop_filter FSM 7.14%，证据 §4 第 1/2 条）

**本卡不予裁决**（越界：那是 BUG-0032 的重开，需要独立的许可来源核查与
