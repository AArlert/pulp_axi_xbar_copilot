## 逐条核验记录

**V1 — axi_err_slv 恒定输出 = Kind-A（A-1/A-2/A-3）：亲验证实。**
`axi_err_slv.sv:25` `RespData=64'hCA11AB1EBADCAB1E`（编译期参数常量），`:196` `err_resp.r.data=RespData` 无条件赋值；`:23` `Resp=RESP_DECERR`(2'b11)，`:145/:197` `b.resp/r.resp=Resp`；`r`/`b` 先 `'0` 再仅赋 id/data/resp/valid，`user` 恒 0。`vendor/axi/src/axi_xbar_unmuxed.sv:195-211` 核实两处 `axi_err_slv` 例化点均**未 override** `RespData`（`Resp` 显式设为默认同值 `RESP_DECERR`，`RespData` 缺省沿用）。结论：为 1 的位永 1、为 0 的位永 0，toggle 结构不可达。报告 A-1/A-2/A-3 分类成立。

**V2 — axi_mux `r.data[63:0]` 由 Kind-B 降级为补场景：反驳理由亲验，且比报告更强。**
`tb/mstport_agent.sv:244-253` slave agent 驱动 `r.data = predict_beat_data(...)`，`tb/xbar_types_pkg.sv:374-384` 该函数 `return {beat_a, beat_a}`（32-bit 地址镜像 → 64-bit）。故本 TB 的 `r.data` **完全由读地址决定，无任何不透明随机载荷**。反驳成立且证据充分：
- 判据(2)不成立最硬的一点——toggle 覆盖每位只需见 0 与 1 两极性，**all-0/all-1 两个饱和向量即可翻遍全部 64 位双向**，根本不需"海量互异取值"。这不仅推翻本候选，更揭示 REV-024 §2.1 判据(2)"扫大量互异取值"的措辞对 **toggle 覆盖**本身是过强的——纯 toggle 的载荷位恒为定向可达（2 向量），Kind-B 的"随机方法论用途"实质只对更丰富的 bin/cross/value 覆盖成立。
- 附带订正报告一处内部不一致（非阻塞）：报告称"判据(1)成立(纯载荷)但判据(2)不成立"。但其自身论据（`r.data` 实为地址镜像）恰恰使判据(1)也不成立——在本 TB 下 `r.data` 语义上是地址派生位（REV-024 §2.1 反向排除的"地址/rule 多样性"类）。结论（NOT Kind-B → 补场景）不受影响，反而两判据双失、更稳。

**V3 — W.data「无缺口」的成因亲验证实。**
`tb/seq_lib.sv:32-35` `item.wdata.push_back({$urandom(),$urandom()})` → 写载荷用随机 64-bit 驱动，故 toggle ~100%。这与 `r.data`（确定性地址镜像 → 55-87%）的不对称完全自洽，佐证报告"W.data 非缺口、R.data 是定向可达缺口"的判断，且反驳 REV-024 §2.2/§5 把 W.data 与 R.data 打包进 Kind-B 的假设。

**V4 — size[2] Kind-A 候选：结构事实证实，但登记须跨配置确认（条件项）。**
本 TB `DATA_WIDTH=64`（wdata/rdata 均 64-bit 亲验）→ 合法 AxSIZE≤3'b011，`size[2]=1`（≥16B）恒为协议违规、合法激励不可达。**在 64-bit 基线下** A-5 成立。但 spec §0 多配置矩阵（cfgA-E）可能含更宽总线；`urgReport_baseline` 只是 64-bit 基线。报告自己也标"待结构确认、勿自裁"——正确。A-5 转正前须确认全部受验配置数据总线宽度均 ≤64（否则更宽配置下 size[2] 可达，不得记 Kind-A）。

**V5 — 有无「夹带」（把 ID/地址/控制误判为纯载荷）：无，且方向偏保守。**
逐行核对分类表：mux `id[7:0]`→无缺口、`addr`→补场景、`W.data`→无缺口、err_slv 入侧 `w.data`→无缺口，均未混入 Kind-B。唯一的载荷候选 `r.data` 被主动降级。报告整体比 REV-024 **更收窄**，无控制/地址位泄漏进豁免。降级到"补场景"是安全方向（要求补定向工作，而非 silent exclude / 免除达标）。

**V6 — urg 引用具体性。**
`sim/out/urgReport_baseline/mod{12,19,32,39}.html` 四文件均存在。报告给出了模块→mod 号映射与具体 bin 数（W.data 128/128、demux r.data 8 位/16 bin 87.5% 等）。引用具体到位号/bin，足以支撑"补场景"清单派卡；对 Kind-A 的最终判据是 RTL 结构（已亲验），非 urg 数字。

## 最终裁决

**这份分解报告可采纳，作为 REV-024 §5「逐位 toggle 分解前置」的兑现。其核心结论——M4 阶段合法 Kind-B 豁免集 = 空集——经独立核实成立，且证据比报告自述更强（V2）。**

具体裁定：

1. **不新增任何 Kind-B 行。** `doc/coverage-waivers.md` Kind-B 模板行维持为模板、不实例化任何具体信号（尤其不得填 mux W/R.data）。REV-024 §5 的前置已兑现，结论是唯一有结构依据的候选（mux R.data）不成立。**本次分解不产出 CW-003+ 的任何 Kind-B waiver-id**——这不是流程未走完，而是走完后的正确空结论。

2. **Kind-A（A-1/A-2/A-3）结构事实经本卡亲验证实**，可据本 REV 转正登记（不再另需 per-item 阅 RTL）：
   - `axi_err_slv` `slv_resp_o.r.data[63:0]`（`=RespData` 编译期常量，`axi_err_slv.sv:25/196`）
   - `axi_err_slv` `r.resp[1:0]`/`b.resp[1:0]`（`=Resp=RESP_DECERR`，`:23/145/197`）
   - `axi_err_slv` 出侧 `r.user`/`b.user`（`err_resp='0` tie-off，`:191/143`）

   解锁条件（可证伪）：xbar 例化改为可变 `RespData`/`Resp`，或该参数被证实运行时可变。均与既有 `doc/coverage-waivers.md` 待建档项一致。**由 orch 应用登记为正式 Kind-A 行（引 REV-025），不由 rev 改文件。**

4. **清单 B（综合报告 §3）各条**（mux/demux `r.data` 定向饱和读、地址/rule 多样性、AXI 属性字段、握手背压 + Cond L112、ID/FSM、`default_mst_port_i`、`rst_ni`）维持 REV-024 清单 B 结论：逐条派 DV 定向覆盖卡，不因本裁决免除。其中 mux/demux `r.data` 为由 Kind-B 降级而来的重点定向项，定向构造 = all-0 → all-1 饱和读（每位双向）即闭。
