## 1. IF-146 else 触达路径 —— 独立确认：唯一路径 = `addr_map_i` 取 X

IF 条件（`addr_decode_dync.sv:146`）：`!$isunknown(addr_map_i) && ~config_ongoing_i`。
else（IF 取 false）须 `$isunknown(addr_map_i)` 为真 **或** `config_ongoing_i` 为真。

自顶向下逐级核实 `config_ongoing_i`（沿 xbar 实际例化闭包）：

1. `axi_xbar_unmuxed.sv:101/116` 例化 **`addr_decode`**（`Napot` 缺省 0，普通
   range 变体），非 napot、非直接 `addr_decode_dync`。
2. `addr_decode.sv:35-89` 端口列表**根本不含** `config_ongoing_i`——无法从 xbar
   侧连接；`addr_decode.sv:106` 将内部 `i_addr_decode_dync.config_ongoing_i` **硬接
   字面 `1'b0`**（唯一驱动源；交叉核对 `addr_decode_napot.sv:89` 亦 tie-off）。
3. 故 `config_ongoing_i ≡ 1'b0` → `~config_ongoing_i ≡ 1`（常量 1，恒不致 IF false）。

**结论**：else 的**唯一**触达路径是 `$isunknown(addr_map_i)` 为真，即 `addr_map_i`
含 X/Z。`config_ongoing_i` 对该 branch 缺口的贡献 = **0**（此点与 REV-028 §2(b)
一致，本卡独立复算成立）。

**per-item verdict**：else 触达路径认定 **pass**（RTL 亲验 `addr_decode.sv:106`
tie-off + `addr_decode_dync.sv:146` 条件常量传播）。

## 3. spec 对"地址表须为已知值"的假设 —— 隐含且一致
