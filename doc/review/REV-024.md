## 2. 卡片问题 2 —（本卡最重要）逐条划界：哪些确属 BUG-0047 方法论受限，哪些只是普通"需补场景"

### 2.1 划界判据（先立标尺，防止被措辞带走）

一个 (模块,类型) 缺口才算 **BUG-0047 方法论受限（Kind-B）**，须**同时**满足：

1. **载体是宽数据"载荷"位**——W.data/R.data（64-bit）等**取值语义上是被搬运的
   数据、不对应任何控制/路由决策**的位；或宽 addr/id 中**纯载荷性、与任何 rule
   /路由无关**的位。
2. **纯定向不经济**——要让这些位双向翻转，必须**扫大量互不相同的数据取值**
   （这正是约束随机的用途），而非"再写几条构造特定控制场景的定向用例"就能补上。

**反向排除（凡命中即 NOT BUG-0047，维持"需补场景"或其它豁免类，不受本裁决
豁免）**：控制/使能/模式选择信号、**窄配置索引**、握手/背压路径、FSM 状态、
Cond/Branch/Line 缺口、assert 缺口、**地址/rule 多样性不足**类 Toggle、
实例级颗粒度（N 个实例只测了 1 个）、恒定输出位（结构不可达，另属 Kind-A）。

**方法论学纠偏（记录保真度，须回改 BUG-0047 表述——见 §7 taxonomy 字段）**：
BUG-0047 `## rca` L57 与 bugs.md 行称此类缺口"位翻转**组合数随总线宽度指数
增长**/组合爆炸"。**这是失实的框架**：Toggle 覆盖是**逐位、每位 2 个方向**，
目标数**随位宽线性增长**（2×width），非指数/组合。真正的不经济不是"组合爆炸"，
而是"**定向用例只用少数固定数据取值，故多数载荷位从未见双向翻转；扫够足量
互异取值把 64 位都翻遍，是随机廉价、定向昂贵**"。这个纠偏**不是措辞洁癖**：
"指数不可达"会把它错误地推向**永久结构不可达豁免**；而正确框架（"可达但纯
定向不经济"）恰恰支撑本裁决的**临时、可 M5 解锁**处置——两者解锁条件不同，
不能混。

### 3.2 落地形态（对 3a/3b/3c/3d 的独立取舍）

- **3a（把 spec §0 三态扩为四态）——不采纳（DECLINE）**。理由（外科手术 +
  最小改动，`discipline.md` rule 2/3）：spec §0 item 4 的三态是**测量读数规则**
  （无 bin=N/A / ≥90%=PASS / <90%=FAIL），而"方法论受限 vs 结构不可达"是

  **已经容纳**这两种豁免；新增的只是"书面豁免须声明种类"这一**豁免内容要求**，
  而豁免内容要求现落在 **milestone.md L60 + REV-016 §9（非-pin 面）**，非 pinned
  spec 正文。把它塞进 pinned 三态表会**混淆测量与处置**、并触发无谓的 spec 重 pin。
  故**保留 spec §0 三态原样不动**，改以"豁免种类"承接（见 3c）。
- **3b（milestone.md M4 出口订正）——采纳**。给 ready-to-apply 草案，见 §4.2。
- **3c（新建 `doc/coverage-waivers.md`）——采纳**：本裁决即 REV-016 §9.5 点名
  "该建它"的触发点。给结构草案（含 Kind-A/Kind-B 两类，解锁条件各异），见 §4.3。
- **3d（每条 Kind-B 须可证伪解锁）——采纳、且设为硬要求**（呼应 rubric #8
