## Scope A — 逐项裁决

**独立复核的实物（非采信 orch 摘要）：**

1. `doc/evidence/v0.0.2/signoff-M0.md` —— 该签核记录**本身已把此缺口作为具名残留风险 R1 登记在案**（§3 残留风险表，R1 行，严重度"中"），并明确判为"不阻塞"，理由三条：SVA 两腿制 fail-closed、签核人已独立复跑源日志确认 178296/178296 与 0 failed、line-1 复现命令自洽。**关键事实：M0 签核是在完全知晓此缺口的前提下作出的，不是在被它蒙蔽的前提下作出的。**

**A-裁决：赞同"不追溯重生成三条证据 + 不改动 signoff-M0"，但纠正 BUG-0008 的终态。**（判决 = pass，附一处状态纠正）

理由（基于实物，非 orch 归纳）：

- **不重生成是对的，且有一条比 orch 更强的论据：signoff-M0 的 R1 已把"该段为空"这一具体字节形态写死在签核文本里。** 一旦重生成，R1 的描述（"`## Key check lines` 段为**空**")当即变为事实错误——用一处"已登记、已评估、非阻塞"的摘要缺口，换来一处新的"签核记录 ↔ 它所指向证据"的字节级不一致。净效果更差。orch 的推荐（"改写已签核指向的产物损伤更大"）方向正确，但没点出这条：signoff 不只是"指向"这三个文件，它**逐字描述**了这三个文件此刻的字节形态，所以重生成会主动令签核文本失真。
- **签核记录应保持不动，无需 amend / supersede / 附重签说明。** 追溯重签的唯一正当触发是"签核基于错误或缺失的事实"。此处事实无误：R1 已如实记录缺口，判决（PASS）建立在独立复跑的源日志之上而非空摘要段之上（`six_questions` Q5 Judgment 在 signoff §4.5 已达标）。既无隐藏缺陷需要纠正，重签只会引入前述新的不一致。故三文件与签核记录**均留原样**。
- **不变性优先。** 覆盖已签核产物的字节，等价于在 sha256 spec pin 之后悄改被 pin 对象——与 `discipline.md` rule 3（外科手术式改动、不动非本次任务所需）及 gate 完整性一致。签核指向的证据是"已冻结"的。

**一处纠正（我独立于 orch 的贡献）：BUG-0008 现为 `OPEN`，与"决定不作为"的处置自相矛盾。**

- 卡片转述 orch 意见为"keep BUG-0008 open"。但仲裁一旦作出"不重生成"，剩余唯一 remediation（重写三文件）即被否决，处置已定论 → **必须转终态，不能停在 OPEN**。`OPEN` 意味着待办；一个已裁定"不做"的行却挂 OPEN，会让下一个 `make next` 读者误以为仍有动作待执行。
- 推荐终态 **`WONTFIX`**，依 `failure_taxonomy.md` 终态对应表："`WONTFIX` ↔ 成本/效益判定停手的任何类；记录仍需 rca + guard-or-rationale"。BUG-0008 详情页已具备：rca（`evidence.py ≤0.2.0` 双重窄化）、rationale（`## rerun` 段的不重写理由）、regression_guard（框架侧保险丝测试 `test_plain_nonuvm_verdict_line_captured` + 本仓库侧"抽检须实际打开证据确认关键行非空"的习惯守卫）。三要件齐备，`WONTFIX` 可直接成立。
- `CLOSED`（TOOL_ENV worked-around）亦可辩护——工具缺陷本身已在框架 0.2.1 修复且本仓库已 pull 至 0.3.0、M1+ 改用 UVM tb 不再复现。但 `CLOSED` 更适合"缺陷已消除"的语义；此处三条历史文件是**经权衡后主动留残**，用 `WONTFIX` 表达"这三个产物我们选择不修"更诚实。BUG-0008 详情页 `## rerun` 把 `CLOSED` 只绑定在"若重生成"路径下，也与"既不重生成、就不该走 CLOSED"自洽。**首选 `WONTFIX`；`CLOSED` 为可接受次选；`OPEN` 不可接受。**

（施加权归 orch：把 BUG-0008 行状态由 OPEN 改为 WONTFIX，并在 root-cause 列引本记录；三 `.log` 与 signoff-M0 不动。）

## 指导（原则与方向，不写实现）

- 已签核证据是冻结产物：任何"用更新工具重生成历史证据"的冲动，先问"签核记录是否逐字描述了被改对象的现状"——若是，重生成会主动令签核失真，默认不动。
- 仲裁一旦定论"不作为"，对应 bug 必须落终态（`WONTFIX`/`CLOSED`），不得以 `OPEN` 表达"决定不做"——`OPEN` 是待办信号，会污染 `make next`。
- canon 收成本地重述时的验收线：通用规则可全交 canon（canon 为超集即可），但工程特定的仪式/例子/绕过史必须在本地保留句里留有落点，且该保留句要能独立被 grep 到。
