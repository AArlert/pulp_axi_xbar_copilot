## 2. 关键事实的独立核验

### 2.1 lint 两条修复的真伪（BUG-0014 / BUG-0019）

两条的共同症状是"编译在到达 `../tb/` 过滤逻辑前中止"。判据因此不是"lint 通
过"（它现在因 BUG-0021 恒红），而是**中止点是否消失、过滤逻辑是否真正执行**。
V1/V2 给出的三项事实互相独立：

1. `grep -cE '^Error-\[' out/lint.log` = 0 ⇒ 两条的错误签名（`SE` /
   `NOODV`+`ZMMCM`+`CEPO`+`TCF-ICTC`）全部消失；
2. `Top Level Modules:` 只剩 2 项 ⇒ BUG-0019 的多顶层枚举确实被 `-top` 压住，
   而不是被别的中止点提前遮蔽（这正是 BUG-0019 当初被 BUG-0014 遮蔽的形状）；
3. 过滤逻辑在真含 `../tb/` 的 flist 下命中 285 条并 exit 1 ⇒ true-positive 分支
   工作正常，即两条修复**没有连带放宽判据范围**（BUG-0014 `## regression_guard`
   要求的正是这一点，本卡据此确认该 guard 被遵守）。

### 2.3 BUG-0027 修复未削弱判决力（本卡独立论证，非采信详情页）

修复把完成记录的认领由"最后匹配"改为"最早匹配"。担心方向是：会不会把某个旧
写法能抓到的真乱序漏掉？逐项排除：

- 跨**不同**完整 ID 的 §5.2.3 检测（M2-OR01 的判据本体）：同 bucket 内该 ID 只有
  唯一记录，两种取法同解，判决力不变。
- 同一完整 ID 多笔在飞：正确归属只能是**最早**那笔（spec §1/§5.2.3 同 ID 同向按
  接受序返回）。旧写法把完成认领成最新那笔后，会把"比最新那笔更老、且异目标"的
  同 ID 记录判成乱序——而按正确归属，此时应比较的是**最早那笔**的目标。若某更老
  的异 ID 记录与最早那笔**同目标**，旧写法报、新写法不报，**新写法是对的**
  （§5.2.3 约束的是跨 master 端口的完成乱序，同目标不在其内）。
- 判决仍可证伪：V7 显示去掉 `break` 立刻产 336 条报错、且 `route/resp/worder`
  仍全绿 ⇒ 该判据既非恒真也非与其它判据同源。

另核验 scoreboard 的 §5.2.3 判据**不共享 BUG-0024 的容量缺陷**：
`or_open_q[k]` 是 `or_open_rec_t [$]` 队列（`scoreboard_refmodel.sv:137`），每笔
被接受的事务各占一条（`:413` push_back），故同完整 ID N 笔在飞被完整表达。
**这是 M2-TL01/TL02/OR03 判决锚点仍然有效的结构性根据**。

## 3. 卡片明文要求单独回答的四个交叉问题

### 3.1 Q1 — BUG-0021 + BUG-0022 ⇒ M2 全程没有可信的 lint 门禁，是否可接受？

**对 M2 已登记证据的有效性：可接受，且理由是结构性的，不是宽容。**

1. `make lint` **从来不在**任何证据链门禁里：`make docs-check`、
   `make evidence`、`make regress`、`make signoff-check` 四条路径本卡逐一读过
   （`scripts/make/core.mk`、`evidence.mk`、`scripts/docs.py cmd_signoff()`），
   无一消费 lint 结果。M2 的判决可信度由别的东西承担：`sva_enforce` 两腿制
   fail-closed（`svacheck.judge`）、scoreboard 零失配、逐场景 evidence 记录、
   11/11 回归。lint 恒红既不曾放行过任何证据，也不曾伪造过任何 PASS。
2. lint 本该交付的**实质价值已经以人工方式交付了**：BUG-0021 的分诊逐条读完
   259 条告警，挑出 11 条真缺陷（F1/F2/F3）并修复复验，并给出了"误差方向单侧"
   的书面论证。本卡对该论证的两个承重环节做了独立复核：(a) F1 只能造假红
   ——post-NBA 与 preponed 的差集只会新增 seq 更大的候选或清掉被
   `cand != completing_id` 排除的自身表项，不能把真实乱序变成合规；(b) 七条
   证据全部 `0 with failures`（本卡 V4 重跑后仍然如此）⇒ 不存在"被放过的失败"。
   结论成立。
3. 当前实测残余 **285** 条（V2），`Lint-[SVA-NSVU]` = **0**，真缺陷类未新增。

**作为长期状态：不可接受的只有 BUG-0022。** 一个会假绿的门禁比没有门禁危险
（discipline rule 2 的 gate 例外条款正是为此写的），而它的修复面只有
`sim/Makefile` 数行、且该文件不在框架快照内。更关键的是：BUG-0021 一旦转
WONTFIX，其替代守卫只能是"每里程碑跑一次强制重编 lint、与登记基线做差分、
新增类别/站点必须分诊"——这条守卫**完全依赖 BUG-0022 被修好**，否则一次
"根本没执行"的 lint 会被读成"无新增告警"，与 BUG-0028 的"分母静默缩水"
是同一个失效家族。

### 3.2 Q2（附带）— BUG-0020 为何不能 WONTFIX

WONTFIX 的判据是"成本/效益判定停手"。这里两侧都不支持停手：成本是
`sim/Makefile` 一条**可选**的 `WAVE=1` dump 路径（该文件可改、`make fw-check`

### 3.3 Q3 — `w_lost_now`/`r_lost_now` 的反向极性是否满足 REV-009 §3.1

**满足，但须附两个条件。**

REV-009 §3.1 要求的是：一个**自引用（per-full-ID、不经 sibling 枚举）**的检测点，
并用 BUG-0023 已验证过的定量前后法确认它不是空守卫。逐项核对（本卡亲读
`stall_sva.sv:192-233 / 315-340`）：

- 自引用性 ✓：`w_n[]/w_uni[]/w_utgt[]` 由独立 `always_ff` 按**完整 ID 自身**
  维护，不经 `sibling_id()` 枚举，正是 REV-009 §2.3 指出的缺失可观测量。
- 达标 cover 与缺陷见证被**正确地分成了两件事** ✓：`aw_stack_diff_now`/
  `ar_stack_diff_now`（24/24）承担 REV-009 §3.1 的"角落被激励触达"，
  `w_lost_now`/`r_lost_now`（456/162）承担"缺陷此刻确实发生"。极性相反的是
  后者，而 REV-009 §3.1 的"修复后可命中"要求原本就是针对前者写的。
- 定量证伪 ✓：DV 记录的 scratch 实验（单 bit → 456/162；就地改计数器 → 0/0，
  其余 cover 不变）与本卡 V6 的独立观察互为佐证（重新引入 BUG-0023 后
  `lost` 由 456/162 升至 864/426，即该信号确实随"丢记录"的多寡单调变化，
  不是恒真/恒假）。

**条件 C1（关闭判据必须是合取式）**：一个"修好后必须归零"的 cover，其零值与
"激励根本没跑到那里"、"模块被摘掉"在报告上同形——这正是 BUG-0022/BUG-0028
的失效家族。故 BUG-0024 的关闭判据不得只写 `w_lost_now==0`，必须是**同一次
TEST+SEED 内**：`w_lost_now==0 && r_lost_now==0` **且** `aw_stack_diff_now>0
&& ar_stack_diff_now>0` **且** `w_collide_q>0 && r_collide_q>0`（正向见证仍在），
**且**既有 assert 无新增失败。

**条件 C2（防止守卫在修复中退化为恒真）**：`w_lost_now` 的定义是
`∃i: w_n[i]>0 && !w_id_open[i]`。若修复采取"把 `w_id_open` 直接等价成
`w_n>0`"的写法，该表达式立刻结构性恒假，见证归零将**不证明任何事**。故修复卡
必须在修复后**重新证伪**这对见证（例如令其比对一个与判决表来源独立的在飞集
合），而不是引用修复前的证伪结论就算数。这一条请写进 BUG-0024 的
`## regression_guard`。

### 3.4 Q4 — BUG-0018 / BUG-0025 的里程碑归属

**BUG-0025：是 M3 的硬前置，且比详情页所述更靠前——它的一半需要先仲裁。**

本卡亲读 `stall_sva.sv:99-100`：

```systemverilog
always_comb aw_hit = decode_mst_port(aw_addr, ADDR_MAP, 1'b0, '0, aw_tgt);
```

`en_default` 参数被**硬编码为 `1'b0`**。于是被跟踪表丢弃的不止 error slave 流
量，还包括 spec §3.3.2 定义的 **default master port 路由流量**。二者的 spec 地位
不同，必须拆开处置：

- **default port 半边 = 纯 TB_BUG，无需仲裁。** default master port 是一个真实的
  master 端口（spec §3.3.1/§3.3.2），§5.2.1 的"目标为不同 master 端口"对它直接
  适用。跟踪表把它当"未命中"丢弃，是实现与 spec 不符，改法明确。
- **error slave 半边 = 真 SPEC_ISSUE，须先仲裁。** §5.2.1 以"master 端口"为约束
  单位，而 §4.1 的 per-port `axi_err_slv` **不是**外部 master 端口；§4.5 只给了
  "响应 ID/握手遵循 AXI4 一般规则"。即：spec 对"error slave 的响应能否越过同
  ID、同方向、目标为正常 master 端口的更老响应"**未作定义**——taxonomy
  `SPEC_ISSUE` 的教科书签名（"spec.md … does not define the behavior at all"）。
  按 discipline rule 1，DV 不得自行取舍。

**归属裁决**：BUG-0025 的 SPEC_ISSUE 半边必须在 **M3 场景被设计之前**（不是被
派发之前）完成仲裁——M3 的判据形态取决于仲裁结论；TB_BUG 半边随修复卡落地。
另：该修复卡的守卫**不能**复用现有 `w_lost_now`（§2.2 结论 3 已证其对本条不敏感），
必须新建。

**BUG-0018：不是 M3 前置，是 M4 前置。**

它的影响面本卡独立复核后确认严格限于 covergroup 采样，判决路径安全，且论证比
详情页给的更硬：

1. `ro.accept_time` 携带的是**真实 AW 握手时刻**（`slvport_agent.sv:376`
   `a.accept_time = $time` 在 AW 捕获处赋值，`:418` 在 `w_last` 发观测时原样
   转抄），故 scoreboard §5.2.3 的排序键**不受迟到影响**，是精确值；
2. 迟到会不会造成漏检？不会：同一 slave 端口的 W burst 按 AW 顺序发出（AXI4），

   晚于它自己的 `w_last`。⇒ 任一完成到来时，所有更老的同向写都已在队里。

代价确实落在 M4：这几个 cross bin 是**可达但未被采样**的，M4 收敛时不能用
"不可达"豁免掉（那正是覆盖率被掏空的方式）。故：**M3 场景派发不被本条阻塞，
M4 收敛冲刺前必须修**，且修复卡须按详情页 `## regression_guard` 的要求**逐 test
看、不看 merged 报告**。
