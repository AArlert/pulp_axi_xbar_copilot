**算术自验（"无场景触及"的定量证明）**：8 条 rule 的 `end_addr` 取值集 =
`{1..8}×0x1000_0000` = `{0x1000_0000, 0x2000_0000, …, 0x8000_0000}`。最高值
`8×0x1000_0000 = 0x8000_0000`，在 32 位 `addr_t` 内**不溢出、不回绕到 0**
（注释 L232 "keeps every rule inside the 32-bit address space with no
wraparound" 与此算术一致）。`ADDR_MAP_OV1` 把 HIGH_RULE 改到 region 0：
`end_addr = REGION_SIZE = 0x1000_0000`（非 0）；其 `start_addr` 改为 region 0 的
`'0` —— 注意这是 **`start_addr=='0`**（合法起址），**非 `end_addr=='0`**（哨兵），
两者无关。故**任一配置下、任一地址表内，无一条 rule 的 `end_addr` 等于 0**。
`NO_ADDR_RULES`/`REGION_SIZE`/`ADDR_W` 均为固定 localparam，配置矩阵（cfgA–D）
只改 `idx` 映射与端口数、不改这三者，故无配置能令顶端 rule 的 `end_addr` 回绕到 0。

**tb 全域构造点扫描**：`grep -rn "end_addr\|ADDR_MAP\|\.end" tb/` 命中的所有
`end_addr` 写入点（`tb/tb_top.sv` L86 仅打印、`tb/sva/axi_xbar_stall_sva.sv`
L128-129 取 `ADDR_MAP[CFG01_MOVED_RULE]` 的 start/end 做窗口只读引用、
`tb/scoreboard_refmodel.sv` L349 赋 `ADDR_MAP`、`tb/seq_lib.sv` L894/1183/1719
分别赋 `ADDR_MAP_V1`/`ADDR_MAP_OV1`）**无一处**新造 `end_addr=0` 的 rule 或
依赖"延伸到地址空间末端"语义——全部消费 §1(g)(h) 的三张有限区间表。

**核验结论**：BUG-0045 详情页/行内对 (a)(b)(e)(f) 的原文、行号、机制转述，经

## 2. 逐条结论（本卡六问 1-6 + 需裁决的四问）

### Q1（taxonomy 终判）— 是否维持 SPEC_ISSUE？

**维持 SPEC_ISSUE，但须限定为"沉默/未定义"这一支，且性质为潜伏（latent）、非当前活跃。**

成本阶梯逐级复核：
- **TOOL_ENV — 排除**：静态阅读缺口，与 seed/机器/build 无关。
- **TB_BUG / CONSTRAINT_BUG — 排除**：refmodel `decode_mst_port`（f）期望值 spec
  派生、非抄 RTL；其"未实现哨兵分支"是**忠实映射了 spec 的沉默**（spec 无该
  条款 ⇒ refmodel 结构性无该分支），这是 spec-from-RTL 红线的**正确遵守**，
  不是 TB 错误期望值。故非 TB_BUG。
- **SPEC_ISSUE — 命中，但限"does not define the behavior at all"支**：
  `workflow/bugs.md` SPEC_ISSUE 判据两支——(i)"spec.md contradicts upstream
  documentation"或(ii)"does not define the behavior at all; DUT and TB each
  defensible under a different reading"。本条命中 **(ii) 的前半（完全未定义）**：
  spec §3.2（e）对 RTL 及 RTL 自身文档（a-d）均载的哨兵分支完全沉默。**但 (ii)
  后半"DUT 与 TB 各在不同读法下都站得住"当前不成立**——因为无任何地址表构造
  `end_addr=='0`（§1 算术自验 + 扫描），DUT 与 refmodel 对**每一个实际出现的
  地址**判决完全一致，不存在两个互斥读法产生分歧的现场。故这是**潜伏型
  SPEC_ISSUE**：分歧是**潜在**（一旦有场景触及即刻现形），**非当前存在**。
- **DUT_BUG — 排除**：DUT 输出无任何 spec 违例（无场景触及该分支，功能零分歧）。

**这一"潜伏 vs 当前"区分决定处置路径**（正是本卡背景与需裁决问题 1 所点）：
若当前活跃（已有场景令 DUT/TB 分歧），则须走 SPEC_ISSUE 标准处置——**立即**
仲裁补 spec + re-pin + 同步 checker；因当前**仅潜伏**，标准处置的"立即补 spec"
一支**触发条件尚未满足**（deferred ledger：trigger 未 fire），故走"接受为
scheduled debt、到期再决"这条更诚实的路径（见 Q3）。

### Q2（是否真的无场景触及）— BUG-0045.md "目前无任何测试场景构造此类地址表"是否属实？

**属实，经 rev 独立核实，非采信转述。** 见 §1 算术自验（8 条 rule 的 `end_addr`
∈ `{0x1000_0000..0x8000_0000}`，最高值 `0x8000_0000` 不回绕到 0）+ tb 全域
`end_addr`/`ADDR_MAP` 构造点扫描（三张表全派生自 `gen_addr_map`，无一置
`end_addr=0`；`ADDR_MAP_OV1` 改的是 `start_addr='0` 非 `end_addr='0`）。
`NO_ADDR_RULES`/`REGION_SIZE`/`ADDR_W` 固定 localparam，配置矩阵不改之 ⇒ 无
任何配置能触及哨兵分支。断言真实无误。**结论：pass。**

### Q3（处置路径三选一或更优）— 采纳 (b) ACCEPTED@M5，排除 (a) 与 (c)

**采纳 (b) `ACCEPTED@M5`（residual risk，到期里程碑 M5，点名本 REV-021）。**

**排除 (a)「现在就补 spec §3.2 + Change record + re-pin + 派卡同步 refmodel」——
现在做属投机/装饰性改动，且会引入不可证伪的 refmodel 代码。** 理由三重：
1. **deferred ledger（discipline rule 2）**：机制在 trigger fire 时落地，非
   "看起来有用"时落地。当前无场景需要哨兵语义，trigger 未 fire。
2. **若现在补 spec 条款 + refmodel 分支，该 refmodel 分支将是无场景激励的
   死代码**——`review.md` Q2 可证伪性："a checker that cannot fail is
   decoration"。无 `end_addr=='0` 场景，新增的 refmodel 哨兵分支**永不被执行、
   永不能被证伪**，其正确性无人背书。这比"沉默"更糟：把一段无源、未验证的
   期望值逻辑塞进单一真值源 refmodel。**正确的时序是：当 M5 决定覆盖哨兵时，
   spec 条款 + directed 场景 + refmodel 分支三者同批落地**，使该分支一出生即
   可证伪（有场景令其判反即红）。现在单补 spec+refmodel 违反这一时序。
3. spec re-pin（change record + sha 更新 + 重 pin）是重操作，为零当前覆盖付出
   不成比例代价。

**排除 (c)「WONTFIX（永久不覆盖的边界情形）」——会把一个 RTL 全链路一等公民
特性永久埋没，与 M5 立项意图相悖。** 理由：
1. `end_addr=='0` 哨兵**非**冷僻角落——它在 RTL 匹配（L112）、合法性断言
   `check_start`（L148）、重叠断言 `check_overlap`（L157）**三处**均有专设支持
   （§1 a-d），是模块文档化、断言背书的受支持配置。对这样一个特性下 WONTFIX
   等于宣布"本项目永不验证 axi_xbar 一个已文档化的地址译码分支"。
2. status 语义硬约束（`workflow/bugs.md`）："WONTFIX may not mean 'later'"。
   本 rev 判断此缺口**应当在 M5 复访**（见下），即"later"，故 WONTFIX 是**误标**。
3. 近期提交显示 **M5 = 验证方法学拓展里程碑**（`docs(m5): …验证方法学拓展提案
   过 rev 门禁，M5 立项`）。"是否覆盖已文档化但尚未激励的 DUT 特性分支"正是
   方法学拓展里程碑的天然议题。把该决策留给 M5 做一次自觉的再裁决，比现在
   永久 WONTFIX 埋没它诚实得多。

**(b) 为何最诚实**：`ACCEPTED@M<n>` = "analyzed, scheduled debt"，未到期不阻塞
签核、到期阻塞、点名 REV 记录（`workflow/bugs.md` status 语义）。它把缺口**保持
可见**并**强制在 M5 做一次自觉再决**，而非现在投机改 spec（a）或永久埋没（c）。
到期里程碑取 **M5**（方法学拓展里程碑，覆盖完备性在其 charter 内），在 M4 签核时
`M5 > M4` ⇒ **unexpired，满足 `make check MILESTONE=4` 机器条件 3**（"所有 bug 行
须为终态或 ACCEPTED-unexpired 且点名 REV"），正是本卡背景所需。

**可证伪的解锁条件（rubric #8"accepted debt is real debt"要件——哪个事实被
推翻即令本裁决作废）**：
> **支撑事实**：tb 全域无任一地址表构造 `end_addr=='0` 的 rule（三张表均派生自
