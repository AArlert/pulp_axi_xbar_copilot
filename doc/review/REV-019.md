### 决策点 2 — 约束随机架构（C2.1–C2.7）：CONDITIONAL PASS

- **B0.1 红线守住（主判）**。合法性边界确实编码进硬约束、非 scoreboard 事后兜底：
  `atop!='0 → addr 命中 rule`（C2.2/C2.5，`§4 clause 7` 宽读 REV-018）、
  `ATOPs==0 → atop=='0`（C2.5，`§6.2`）、稀疏 Connectivity 不译码到非连通端口
  （C2.2 cfgD，`§8.3`）、UniqueIds 前置（C2.3，`§5.3.1`）。逐条 spec 引用核对准确。
- **针对 regression guard（BUG-0032/0039）的定向核实：C2.2/C2.5 的"未命中地址+非零
  atop"组合确被构造性堵死**。硬约束 `atop!='0 → addr 命中某条 rule` 与随机 addr 生成
  在同一 `randomize()` 内联立求解——求解器不可能产出"未命中地址且 atop!='0"的解，
  因为该组合被约束判为 unsat。这不是文字声明，是约束联立的构造性性质：只要该 constraint
  真的进了约束块（DV 落地须核），组合即不可达。与 `§4 clause 7` 环境约束（宽读，
  不论 default port 使能）语义一致。**通过**。
- **C2.6 集中 ID 分配器堵住跨事务不变量**。正确识别单条 item 的 `randomize()` 兜不住
  `§5.3.1`（UniqueIds）与 `§6.4`（ATOP 全方向唯一）的跨事务性质，复用 `uvm_env.md`
  C6.7 已确立的单一分配器（核实 C6.7 原文确立"集中、不由各序列各自猜"）。`§5.3.3`
  正确用作"不满足则未定义 ⇒ 是硬约束非偏好"的依据。设计方向成立。
- **SP-1 有界处理合理**：`atop` 升 rand 但界定 `{'0} ∪ 合法 atomic-load 编码`，不放开
  store/swap/compare。核实 `§6.3` 确实只规定 atomic-load 的 B+R 应答义务，§6 无其余
  子类型应答条款——故有界子集零 spec 改动、scoreboard 有 oracle；放开须先补 spec。
  判断正确。
- **条件（behavior-leak 精度，见 §3 guidance G-4）**：C2.1 的 env 约束 rationale 断言
  "crossbar 只按 AW.addr 单次译码（不逐 beat 重译码）"是一处 spec 未载的 DUT 行为
  claim。它未被写成 checker 期望值（只用于论证"burst 不跨 region"这一无论 DUT 如何
  译码都安全的激励限制），故非硬 behavior-leak，但 arch 不应在 design-prompt 内嵌
  无源 DUT 行为断言。
- 判决：**CONDITIONAL PASS**，条件 = 修 C2.1 表述（G-4）+ SP-1 登记（见决策点 SP-1）。

### SP-1（ATOP 非-load 子类型应答义务缺失）：成立的 SPEC_ISSUE；仲裁可延迟、但登记不可延迟

  决定放开时再走 spec 修改记录。此判断我**同意**。
