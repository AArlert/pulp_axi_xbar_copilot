## 2. 逐项 verdict

### 2.1 Q1 — w_open[3]（值≥8）是否存在硬性不可达理由？ → **ISSUE：无。是激励产物，非结构不可达**

**先辨计数器**（卡片明确要求，REV-007 §5 支撑）：spec §5.4.2「基线见证达
8>6」讨论的是**每桶 AW ID 计数器**（`i_aw_id_counter`，pop 于 B 响应，
axi_demux_simple.sv L226-227；满量程 15 = §5.4.1），**不是** `w_open`
（`i_counter_open_w`，pop 于 W burst 末拍 w_cnt_down，L236-249）。二者虽
同宽（IdCounterWidth=idx_width(MaxMstTrans=10)=4 位）、同在 w_cnt_up 上加，
但**下沉事件不同**：aw_id_cnt 靠 B 排空、w_open 靠 W 排空。故 spec 那句
「8>6」**不构成 w_open 可达 8 的证据，也不构成其不可达的证据**——它说的是
另一个计数器。DV 转述把「8>6」与 w_open 相关联是**张冠李戴**。

**w_open 的真实封顶不是 MaxSlvTrans=6**：

1. 计数器自身范围到 15——demux AW 门（L168）仅在 `w_open == 4'hF(=15)` 时
   拒收，**不在 8 设限**。bit3 是合法计数区间内的位。
2. w_open 的实际上界 = **下游 AW 吸收深度 + demux 自身 lock（1）**，而下游
   吸收 **> MaxSlvTrans=6**：
   - mux `i_w_fifo` 深度 = MaxWTrans = MaxSlvTrans = **6**（axi_mux.sv
     L317-319；W 未排空的 AW 计在此）；
   - demux→mux 之间还有 `axi_multicut(NoCuts=PipelineStages=1)`
     （axi_xbar_unmuxed.sv L218），每通道 1 个 `spill_register`，a/b 两级
     **容量 2**——这 2 个在途 AW 已被 demux 前推（w_cnt_up 已计入 w_open）
     但尚未进 mux w_fifo；
   - 叠加 demux 锁定态的 +1。
   故 W 全程被扣住时，w_open 稳态可达 **6 + 2 + 1 ≈ 8~9**，**结构上足以
   翻 bit3**。
3. mux w_fifo 满是**可恢复背压、非死锁**：`!w_fifo_full` 才收 AW（L301），
   而 W 末拍无条件弹出 w_fifo（L360-366，与 full 无关）。只要驱动按 AW
   接受序排空最旧 W（drive_burst_wopen 本就如此），w 流即恢复、fifo 即弹出。
   ⇒ `slvport_agent.sv:417-419` 注释「LEAD≥FIFO 深度即 deadlock」**不准确**：
   真正的驱动自死锁阈值是 LEAD 超过**整条下游吸收深度（≈8）**而非
   MaxSlvTrans=6；驱动只要不一次性开窗超过吸收深度就绝不死锁。

**观测峰值 5 = 驱动自设 LEAD 的产物，非 DUT 封顶**：
`drive_burst_wopen` 取 `lead = MaxSlvTrans-1 = 5`（slvport_agent.sv
L441-442），并以「过深即 deadlock」为由封窗。峰值 5 恰等于 LEAD=5，
即**激励窗口本身**把 w_open 钉在 5，比真实吸收深度低约 3。

**跨 config 维度进一步否证「结构不可达」**：MaxMstTrans=10 / MaxSlvTrans=6 /
PipelineStages=1 在**全部** config 硬编码（bit3 在每个 config 的 demux 实例
都存在），但 **LatencyMode 逐 config 变**（cfgA NO_LATENCY … cfgB
CUT_ALL_PORTS，xbar_types_pkg.sv L40/55/115）——spill 缓冲随之变，下游
吸收深度、w_open 上界因此是**配置相关量**，CUT_ALL_PORTS 侧更宽。一个随
config 浮动的量，不可能是「无论测试序列如何设计都不可达」的结构常量。

**结论**：w_open[3] 不存在协议/RTL/环境层面的硬性不可达理由。它与
coverage-waivers.md 现有 Kind-A 先例（CW-003/004/005/007 均为**参数
tie-off 恒定位**、CW-006 未定义热复位语义、CW-002 scan 出范围）**性质不同**
——那些是物理恒定/范围外，w_open[3] 是**定向可达的控制计数位**，只是当前
驱动窗口太浅。**两种可能性之别对裁决的意义**：若真结构不可达 → Kind-A；
既是激励产物 → 必须驳回豁免、转补场景（否则用永久豁免掩盖一个本可关闭的
定向缺口，违反 discipline rule 4「目标须能表述成一条会过的 gate」）。

**驳回豁免，转「需要新的/加固激励」的待办**（供 orch 排队；rev 不写激励）：

**加固卡 A — 关闭 w_open[3]**（写方向）。构造要点：
- 目标 gate（可过的判据）：merged 基线 `mod12.html` 中 `w_open[3]` 由 No→Yes；

- 备选/叠加：在 **CUT_ALL_PORTS**（cfgB 一类）更宽 spill 的 config 上跑，
  吸收深度更大，w_open 越 8 的裕度更足；该 config 维已在矩阵内，无需新增
  DUT 配置。

  Cfg.PipelineStages）与经验探测**推导，**不得**抄任何 RTL 内部信号值
