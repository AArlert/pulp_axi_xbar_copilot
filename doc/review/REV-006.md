### 编辑 1 — §5.2.1（收窄"接受边界"字面表述）

- **落点**：`doc/spec.md` §5.2 第 1 条（现 L171-173）。
- **原文**：
  > 1. 同一 slave 端口收到**两个同 ID、同方向**（同读或同写）、但目标为**不同 master 端口**的事务时，第二个事务在第一个完成前不被接受；期间该 slave 端口的 AW（写）或 AR（读）通道被 stall。
- **新文**：
  > 1. 同一 slave 端口收到**两个同 ID、同方向**（同读或同写）、但目标为**不同 master 端口**的事务时，第二个事务在第一个完成前**不被转发到其目标 master 端口**；期间核心判决逻辑 stall 该方向的 AW（写）或 AR（读）。其**外部可锁定后果**是响应保序：第二笔的响应（B/rlast）不早于第一笔的响应返回（§5.2.3）。
  > **接受边界即时性说明（BUG-0013 裁决，REV-006 §2.2/§3）**：基线 `LatencyMode=CUT_ALL_AX`（§7.2）在核心判决逻辑**之前**启用 `SpillAw`/`SpillAr` 弹性缓冲（demux.md §Configuration："one spill register ... before the demultiplexer"；§Pipelining：每通道加一拍、不损吞吐）。因此第二笔在外部 slave 端口的 **AW/AR 握手接受时刻**可早于核心判决逻辑比对第一笔——"接受握手被即时 stall"**不是可锁定的外部行为**，属 §7.4 延迟不敏感插桩的时序表现（窗口深度随启用的 `LatencyMode` 位变化、许可来源未给固定拍数）。故 checker/SVA 的保序 stall 判决门**必须锚定完成序**（§5.2.3：同一低位 ID 桶、同方向、不同目标的两笔若均被接受，其 B/rlast 完成顺序须与接受顺序一致），**不得断言第二笔的接受握手迟于第一笔的完成**。
- **理由**：合并 arch 蒸馏时旁落的两处许可来源（xbar.md L84-86 Ordering 叙事 + demux.md L31/L37 SpillXX 缓冲层），把"accept"回归其 xbar.md L86 语义（forward 进交换网络），消除字面读法对基线配置的假红。
- **依据栏**：xbar.md §Ordering and Stalls（L84-86）+ demux.md §Configuration（L31）/§Pipelining（L37）+ spec §7.2/§7.4 + `axi_demux.sv` L89-116/L189-209 结构佐证。

### 编辑 2 — §7.4 增第 5 条（接受/拒收边界即时性 = 延迟不敏感，通用化）

- **落点**：`doc/spec.md` §7.4，接现第 4 条之后新增第 5 条。
- **新文**：
  > 5. **接受/拒收边界的即时性是延迟不敏感表现（BUG-0013 裁决，REV-006）**：slave 端口侧 spill register（`SpillAw`/`SpillAr`，基线 `CUT_ALL_AX` 启用）位于核心判决逻辑（demux 计数/比较，demux.md L70-74）**之前**（demux.md §Configuration L31、`axi_demux.sv` L89-209 结构），会在核心判决之前对 AW/AR 提供弹性缓冲。故**外部 slave 端口 AW/AR 握手的接受（或拒收）时刻本身**——无论是 §5.2 的保序 stall、还是 §5.4.3 的"达到上限即拒收"——均为延迟不敏感时序表现，**不得作为 checker/SVA 的判决锚点**。判决须落在延迟不敏感的可观测量上：保序 stall 落**完成序**（§5.2.3）；事务上限落"**限内不假 stall**（弹性缓冲只会使接受更早、不会更晚，故限内的边界 stall 仍是真失败）**＋上限最终被守**（容忍弹性缓冲窗口深度，不断言第 N+1 笔在某具体时点被拒于外部边界）"。窗口深度随 `LatencyMode` 变化、许可来源未给固定拍数（§7.4.3）。
- **理由**：BUG-0013 的机制是 §5.2.1/§5.4.3 共用的 `axi_demux_simple`-在-spill-register-之内结构的一般表现（见 §4）；将原则一次性沉淀入既有 §7.4 延迟不敏感条款，避免 M2-TL01/TL02 各自独立撞见、各写一套不一致处置（Retention）。此为对既有 §7.4 原则的**澄清**（延迟不敏感 → 含接受/拒收边界即时性），非发明新的规范约束。
- **依据栏**：demux.md §Configuration（L31）/§Implementation（L70-74）+ `axi_demux.sv` 结构 + spec §7.4.2/§7.4.3 既有原则。

## 4. 指导（原则与方向，不写实现）—— 延伸仲裁范围

**核验结论先行**：延伸范围两条的判断，均以 §1 亲验的 RTL 结构为据。

### 4.1 C5.3（MaxMstTrans / MaxSlvTrans，M2-TL01/TL02）—— **判定：MaxMstTrans 侧同类，MaxSlvTrans 侧证据不足**

- **MaxMstTrans（M2-TL01）是同一类交互**：MaxMstTrans 由 `axi_demux_simple` 的**同一组**计数器强制（demux.md L70-74；spec §5.4.1 分桶口径），而该计数器同样在 `SpillAw`/`SpillAr` **之后**。故当某桶计数达 `MaxMstTrans` 时，demux_simple 内部拉低 ready，但 spill register 仍能在反压传出前把第 `MaxMstTrans+1` 笔 AW **接受进缓冲**——与 BUG-0013 同形的"外部接受边界滞后于核心计数器状态"。**指导**：M2-TL01 的可证伪内容应放在 **(i) 限内不假 stall** 方向（弹性缓冲只使接受更早、绝不更晚，故限内出现边界 stall 是真失败，此向可锚外部边界、且不假红）；若需上限守卫，**须按 §7.4.5 锚延迟不敏感量**（在飞/完成记账，容忍弹性缓冲窗口），**不得**断言"第 `MaxMstTrans+1` 笔在外部边界某具体时点被拒"。注意基线 `CUT_ALL_AX` 同时切 `MuxAw/MuxAr`（master 端口侧亦有缓冲），故任何"精确外部拒收时点"读法双重不可靠——更坚定支持锚完成/在飞侧。
- **MaxSlvTrans（M2-TL02）不在本卡结论范围**：其执行机制在许可来源未定义（BUG-0011 裁决，spec §5.4.3 上游确认项，mux.md 无机制段落）。既无机制来源，rev **不就其接受/拒收边界即时性下结论**——M2-TL02 仍按 REV-005 §3/条件 C2 的"保守可观测上界监视器（每 master 端口×每前缀后 ID×每方向 ≤ MaxSlvTrans，方向分计、绝不假红）"落地即可；该弱监视器本就不断言任何具体拒收时点，天然不撞 BUG-0013 类边界问题。

### 4.2 C1.5（运行时重配置窗口，M2-CFG01）—— **判定：不同类，现有 design-prompt 锚点正确，不泛化**

- **RTL 证据**：路由 select 由 `axi_xbar_unmuxed.sv` L101-134 从 `addr_map_i` **组合译码**于 demux slave 边界，并在 `axi_demux.sv` L102-114/L145-157 的 `i_aw_select_spill_reg`/`i_ar_sel_spill_reg` 与 AW/AR **同拍锁存**——即**路由决策在边界握手时刻被冻结**。而 §3.4 的重配置约束本就锚在**边界 `valid` 期间不得改表**。
- **结论**：一笔在边界被接受的事务，其路由 select 已随之锁死；此后改 `addr_map_i` **不会**重路由这笔已缓冲的事务。故 C1.5 **不存在** BUG-0013 式"接受边界提前于核心决策导致误判"的误路由危害。`scoreboard_refmodel.md` C1.5 现已把参考模型的表版本译码锚在"**每笔事务 AW/AR 握手完成时刻**生效的表版本"——与 RTL 的 select 锁存点**精确一致**，判定正确、无需改动。
- **不泛化**：唯一须保持的纪律是——重配置"全部 slave 端口 AW/AR 空闲"窗口须以**外部可观测 valid/握手**判（§3.4 本就如此），而非以任何"内部计数器/流水已空"的假设判；只要维持此边界锚点，spill 层不构成额外危害。**证据不足以把 C1.5 归为 BUG-0013 同类，据此明确不归并**，避免泛化过头。

### 4.3 C5.4（W 通道次序，M2-WO01）—— **判定：机制相关但非新增可执行实例；已由更强的先在条款 §5.5.4/C6.2 覆盖，非 §7.4.5**

（coordinator 追加范围；针对性 RTL 核验，不沿用 §1 印象。）

**核验目标问题（coordinator Q1/Q2）：spill register 是否扰动"不同 slave 端口之间 AW 接受时刻的相对序"、进而扰动 mux round-robin 的服务序这一外部可观测量？**

**RTL 核验（新读，锚行号）**：
| 来源 | 行 | 事实 |
|---|---|---|
| `axi_xbar_unmuxed.sv` | L95 `gen_slv_port_demux` + L178 | **每 slave 端口一个独立 `i_axi_demux` 实例**，各自 `SpillAw = Cfg.LatencyMode[9]`（DemuxAw，基线 `CUT_ALL_AX`=1）——即**各源 slave 端口的 `SpillAw` 弹性缓冲相互独立** |
| `axi_mux.sv` | L264-281 `i_aw_arbiter`（`rr_arb_tree`）：`req_i(slv_aw_valids)` / `gnt_o(slv_aw_readies)` | round-robin 仲裁的 `req_i` = `slv_aw_valids` |
| `axi_mux.sv` | L211-259 `gen_id_prepend` + L244 `.mst_aw_valids_o(slv_aw_valids[i])` | `slv_aw_valids[i]` 来自 `axi_id_prepend` 的 `mst_aw_valids_o`，其输入是 `slv_reqs_i[i].aw_valid`（L229）= mux 的 slave 端口输入 = **该路 demux 的 master 端口输出**（在 demux 的 `SpillAw` + `axi_demux_simple` 核心判决**之后**） |
| `axi_id_prepend.sv` | 全文无 `always_ff`/`posedge`/spill/fifo | ID 前缀单元**纯组合**、无存储、不重排 |

**Q1/Q2 回答**：
1. **arbiter 的 `req_i` 不取自外部 slave 端口握手**，而取自**各路 demux 的 master 端口输出**（经组合 `axi_id_prepend` 直连；中间"另有一层"=组合 ID 前缀，无存储）。各源 demux 的 `SpillAw` 独立，故两个不同 slave 端口的 AW **到达 arbiter 的相对先后**确可偏离其**外部接受相对序**（各自 spill 一拍 + 各自核心判决是否 stall，如一路撞 §5.2.1 同桶 stall 而另一路不撞）。
2. **但"谁先被 round-robin 服务"这一外部量本就非可锁定**：`rr_arb_tree` 的服务序由其自身优先级轮转决定（xbar.md L107-109），**即使零 spill，服务序 ≠ 到达序**。spill 不是使其非可锁定的原因，round-robin 优先级机制才是——spec §5.5.4（C4）与 design-prompt C6.2 **早已**把它划为"禁断言"，比 §7.4.5 更强、且先在。

**据此判定**：C5.4 与 BUG-0013 **共享底层现象**（外部接受边界/相对序滞后并重排于核心判决），**但不是一个需要新防护的可执行实例**：
- **跨源维度**：由 **spec §5.5.4 / design-prompt C6.2**（"禁断言 round-robin 具体发生序、不得断言某一拍被授权端口；只准从性质推导：保序/W 随 AW 同序不交织/无饿死"）**先在且更强地覆盖**——一个正确的 C5.4 checker **本就被禁止**锚定跨源仲裁/服务序，故不存在会因 spill 假红的合法 checker。§7.4.5（本卡新增）是互补的边界即时性澄清，但 C5.4 跨源维度的**操作条款是 §5.5.4/C6.2，非 §7.4.5**。
- **源内维度**：C5.4 合法断言的"W burst 随**其自身** AW 同序、burst 内不交织"（§5.5.1）经 spill register **保序**（skid buffer 于单通道严格保序；`axi_demux_simple` 的 W-select FIFO 按**后-spill** AW 序入队 = 外部 AW 序，因 spill 保序）——延迟不敏感、单源、无扰动。

**发现（design-prompt 措辞防护缺口，非 spec 变动、非 bugs.md 行）**：`scoreboard_refmodel.md` **C5.5(b)** 现措辞 *"校验 C5.4 的'master 端口侧观测到的 burst 完成序 == 各源 AW 接受先后序'"* **歧义**：字面（跨源读法）会断言"跨不同源 slave 端口的服务序 == 跨源 AW 接受序"——这既**违反同文件 C6.2 / spec §5.5.4**，又正是被本节 RTL 核验确认会受"独立 `SpillAw` + round-robin 轮转"双重扰动的量。C5.5 自称"期望值仍完全来自 §5.2/§5.5、不引入新行为假设"，而 §5.5.4 恰恰禁止该跨源断言——故字面跨源读法与 C5.5 自身声明矛盾，应收窄为**源内读法**。**推荐 orch 令 arch 补一句防护措辞**（非阻塞，同 REV-005 §4 条件性质）：

- **落点**：`doc/design-prompt/scoreboard_refmodel.md` C5.5 第 (b) 用途句。
- **原文**：
  > (b) 校验 C5.4 的"master 端口侧观测到的 burst 完成序 == 各源 AW 接受先后序"。
- **建议新文**：
  > (b) 校验 C5.4 的**每一源 slave 端口各自**的 W burst：其在 master 端口侧被服务/完成的先后与**该同一源**的 AW 接受先后一致（W-burst 随其 AW 同序，§5.5.1），且 burst 内不与他源交织。**不得**据此断言**跨不同源 slave 端口**之间的 burst 服务序 == 跨源 AW 接受序——跨源仲裁发生序非可锁定外部行为（C6.2 / spec §5.5.4），且受各源独立 demux `SpillAw` 弹性缓冲与 mux round-robin 优先级轮转双重扰动（接受边界即时性另见 spec §7.4.5、REV-006 §4.3）。
- **理由**：C6.2 已正确禁断言跨源序，但 C5.5(b) 字面读法诱导 M2-WO01 的 DV 误建被禁 checker；收窄措辞使源内/跨源边界显式，防同类交互被独立重踩（同本卡为 C5.3 补指针的套路）。
- **不需新 spec 条款**：spec §5.5.4 已正确、完整地治理跨源维度；本项仅 design-prompt 措辞卫生。
