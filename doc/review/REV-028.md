## 1. `config_ongoing_i` 可达性 —— 结构不可达，**独立确认成立**

按 xbar 实际例化路径逐级核实（自顶向下）：

1. `axi_xbar_unmuxed.sv:101/116` 例化 **`addr_decode`**（非 napot、非 dync），
   `Napot` 未传参 → 缺省 0（普通 range 译码）。
2. `addr_decode.sv:35-89` 的端口列表**根本不含** `config_ongoing_i`——它不是
   `addr_decode` 的对外端口，无法从 xbar 侧连接。
3. `addr_decode.sv:106` 将内部 `i_addr_decode_dync.config_ongoing_i` **硬接
   字面常量 `1'b0`**。这是唯一驱动源。
4. urg 实例名佐证路径正是
   `…i_xbar_unmuxed…i_axi_{aw,ar}_decode.i_addr_decode_dync`（mod20.html:80/89）。

**结论**：从 xbar 顶层到 `i_addr_decode_dync.config_ongoing_i`，**无任何参数、
端口或运行时可控路径**能使其取非 0——唯一驱动是字面 `1'b0`。交叉核对
`addr_decode_napot.sv:89` 亦 tie-off `1'b0`，故两个 wrapper 变体都不暴露该信号；
只有**直接例化 `addr_decode_dync` 并驱动该端口**才可能翻转它，而 xbar 例化闭包
内**不存在**这样的例化点。**结构不可达 = 成立（Kind-A 之性质）**。

**逐条 per-item verdict**：
- 可达性主张 **pass**（RTL 亲验，`addr_decode.sv:106` + `axi_xbar_unmuxed.sv:101/116`）。

## 2. 覆盖率残余精确归因 —— 缺口候选的"锅"大半不在 `config_ongoing_i`

独立核实 `config_ongoing_i` 在六类里的**全部**覆盖率足迹（mod20.html 亲取）：

| 类型 | `config_ongoing_i` 足迹 | 现状 | 归因 |
|---|---|---|---|
| LINE | L116/117/119 赋值行执行 | 100%（1/1） | 无残余 |
| COND | `~config_ongoing_i` 子条件 | 100% | 常量传播后被折叠出 COND 域，无残余 bin |
| **TOGGLE** | `config_ongoing_i` 端口 | **No/No/No** | **2 死 bin（1 bit×2 向），tie-off 致 |
| FSM | 无 FSM 构造 | N/A | — |
| **BRANCH** | L119 三元 `config_ongoing_i ? …` | **报告中不存在该支路** | **被常量折叠**，贡献 0 个未覆盖 bin |
| ASSERT | L133 `\|\| config_ongoing_i` | 100% | 常量 0 项，assert 归约为 `$onehot0`，已覆盖 |

**关键独立发现（两点，均与卡片标题的"config_ongoing_i 缺口"框架相左）**：

**(a) Toggle 缺口已被 ≥90% 门吸收，非 `<90%` 缺口。**
(addr_decode_dync, Toggle) 合并值 = **92.00%**（Total Bits 100/92，mod20.html:1046-1049），
**已过 spec §0 item 4 的 ≥90% 门**。其 8 个死 bin 组成 =
`addr_i[2:0]`（No/No/No，6 bin，地址对齐/多样性——REV-024 §2.2 行 6 的"需补场景"
桶）+ `config_ongoing_i`（No/No/No，2 bin，tie-off）。`config_ongoing_i` 的 2 bin
**在分母内被如实计数**（非 silent exclude），且被 8% 余量吸收。

**(b) 该模块真正的 `<90%` 数字是 BRANCH 83.33%，而它并非 `config_ongoing_i` 所致。**
Branch 唯一未覆盖 bin = **IF-146 的 else 支**（mod20.html Branch 表 IF 146 = 2/1）。
其条件 `!$isunknown(addr_map_i) && ~config_ongoing_i` 取 false 需
`$isunknown(addr_map_i)` 为真 **或** `config_ongoing_i` 为真；因 `config_ongoing_i≡0`
使 `~config_ongoing_i≡1`（常量 1，恒不致 false），**else 支唯一触达路径是
`addr_map_i` 出现 X**。故 `config_ongoing_i` 对该 branch 缺口的贡献 = **0**；
L119 的 `config_ongoing_i` 三元早已被常量折叠、根本不在 branch 分母里。

**其他闭合路径（卡片要求 #2）核实**：
- `config_ongoing_i` **Toggle**：**无任何其他闭合路径**——字面常量，无激励可翻，
  亦无间接定向构造能触达其 =1 派生态（match 时 matched_rules=0 / dec_valid=0 /
  idx=default_idx 三态全需 config_ongoing_i=1，结构禁止）。
- IF-146 else（真正的 `<90%`）：闭合路径存在但**与 config_ongoing_i 无关**——须
  令 `addr_map_i` 取 X（未配置窗口/X 注入）。此路径是 `ifndef SYNTHESIS` 的
  地址表 sanity 断言守卫（`proc_check_addr_map`）的跳过分支，注 X 覆盖它无任何
  功能语义（X-theater），且 REV-024 §2.2 行 6 给它开的"地址/rule 多样性→补场景"
  处方**不能闭合它**（更多样的已知地址仍使 addr_map 保持 known → else 永不取）。

**逐条 per-item verdict**：
- Toggle 残余归因 **pass**（config_ongoing_i 2 死 bin，已在 92% 门内）。
- Branch 残余归因 **issue（对既有划界的订正）**：83.33% 缺口=IF-146 addr_map-X，

## 3. 裁决 —— **驳回 Kind-A 登记（不改 `doc/coverage-waivers.md`）**，但非"责成定向闭合"

`config_ongoing_i` **性质上确为结构不可达（Kind-A 之质）**，然其**处置不是登记
一行 Kind-A 豁免**，理由四条（`discipline.md` rule 2/3 + 豁免本自身范围）：

1. **无 `<90%` 门失败可开。** 豁免是"为通不过的门开口"的 gate 制品
   （`discipline.md` rule 2 唯一例外恰是 gate；但此处无失败 gate）。
   `config_ongoing_i` 的唯一未覆盖足迹（Toggle 2 bin）落在 **(addr_decode_dync,
   Toggle)=92.00% ≥ 90%** 的**已通过**门内。
2. **非 silent exclude。** 该 2 bin 在分母内被如实计数为未覆盖，未被任何
   exclude 文件排除——`workflow/bugs.md` L229 的"silent exclude 必须配豁免行"
   前提**不触发**。
3. **豁免本范围限定。** `doc/coverage-waivers.md` 抬头明文限于"覆盖率缺口
   （有 bin、`<90%`）"；(addr_decode_dync, Toggle) 非 `<90%`，不在登记面。
4. **登记反而误导。** 为一个已过门的 (模块,类型) 补 Kind-A 行，会暗示存在
   一个失败 gate（实则没有），属 `discipline.md` rule 2 禁止的思辨性制品；
   且 `config_ongoing_i` 的 branch 足迹已被折叠、对真正的 `<90%`（Branch）零贡献。

**故：不新增 CW-008，不改 `doc/coverage-waivers.md`。** 这一"驳回"**不等于
"责成继续用定向场景闭合"**——对字面常量而言定向闭合不可能、亦无必要（门已过）。
正确处置是：**如实记录 config_ongoing_i 结构死、但已被 92% 余量吸收，无需任何
台账动作**。

**与 REV-024 的关系（卡片要求核实）**：REV-024 §2.2 行 6 **通篇只谈 `addr_i` 与
rule 表 start/end 的"地址多样性"**，**从未提及 `config_ongoing_i` 恒接 1'b0**——
即划界时**不知**此事。本裁决**补充**（非推翻）REV-024：config_ongoing_i 是其
多样性分析未枚举的一个独立结构死位；且自 REV-024 的 53-57% 基线以来定向工作已
落地、Toggle 升至 92%，该死位无需单独动作。REV-024 对"地址多样性→补场景"这一
**Toggle** 处方仍成立（`addr_i[2:0]` 那 6 bin 属之）。

**Guard 合规**：BUG-0047 guard 禁止将 REV-024 "需补场景"条目**改记 Kind-B**（须
先逐位分解）。本裁决**不登记任何 Kind-B、亦不登记 Kind-A**，零改动，完全合规；
亦未触碰 REV-024 对地址多样性部分的"需补场景"结论。

**逐条 per-item verdict**：
- Kind-A 登记请求 **驳回**（不改 coverage-waivers.md；依据：92% ≥90% 门已过 +
  豁免本 `<90%` 范围 + discipline rule 2）。
- Kind-B **不适用**（本卡缺口非宽载荷位；且无需任何豁免）。
