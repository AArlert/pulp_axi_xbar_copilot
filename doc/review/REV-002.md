## 2. behavior-leak 猎捕 —— 通过

逐个数字化约束（C1.1…C6.3）核对：**未发现**"把 spec 未载的 DUT 外部可见行为写成绑定

M1-02 不制造同 ID 未决对）明确标为**环境纪律**而非 DUT 行为断言，处置正确。M2/M3
语义（decode error / stall / 保序上限）在 refmodel §2/§5 与 sva_bind §3 **成文但显式
延后激活**，未在 M1 越权断言。

抽查了三处最容易滑成 leak 的地方，均判定为 AXI4 基线（spec §1「实现完整 AXI4」）之
合法推论，非新增行为：
- refmodel C4.1/C4.2/C4.3（写/读 payload、burst 属性路由前后一致）—— crossbar 定义
  性行为，spec §1「全连接 crossbar+完整 AXI4」+ §5.1「仅 ID 高位被前缀」共同蕴含
  payload 透传，非新增；
- uvm_env C4.1 / testplan M1-01「响应码 OKAY」—— happy-path 的 OKAY 由 TB slave
  agent 产生、经 xbar 原样回送，属 §1 透传，非 DUT 生成新响应码；
- sva_bind C2.3（RLAST/WLAST 与 burst 长度一致）—— AXI4 握手基线（§1），见 §3.4 note。

两处**引用瑕疵**（属 design-prompt 文本缺陷，非 DUT 行为越线，不阻塞放行，建议作者/DE
落地前顺手订正）：

- **N1（C2.2 引用错配）**：C2.2「复位后空闲：`rst_ni` 有效期间及释放当拍所有 `*valid`
  为 0」引「spec §2.3、**§3.1（复位语义）**」。经核 spec §3.1 是**地址表结构**，无任何
  复位语义。该断言本身是 AXI4 复位基线（VALID 复位期须撤销），真正锚点应为 §2.3
  （`rst_ni` 异步低有效）+ §1/§4.5（AXI4 协议基线），**§3.1 的括注属误引**。行为无误、
  仅引用需改。
- **N2（C2.3 锚点偏窄）**：C2.3 把 RLAST/WLAST 与 burst 长度一致引「§1、**§4.3**（beat
  数正确的一般化）」。§4.3 是 **decode-error slave 专属**的 beat 数条款；把它"一般化"到
  所有正常 burst 虽已自注、且并列引了 §1，但主锚点应为 §1（完整 AXI4 握手基线），§4.3
  仅宜作旁证。建议以 §1 为主引、§4.3 降为参考。

两处均不改变可交付 SVA 的实际断言集（握手稳定性/复位空闲/LAST 一致性/延迟不敏感/禁仲裁
序），故 `sva_bind.md` 判 PASS-with-notes，可与其余三文件同批放行。

## 5. vendor 升级 memo 事实核验 —— 三类结论逐条证实

方法：`git ls-remote` 取 v0.39.10 tag（SHA `a8c53cee…`），从
`raw.githubusercontent.com` 拉取该 tag 下 7 个 spec 蒸馏来源文件，与本地 vendored 快照
及 upstream v0.39.9 逐文件 `diff`。

- **"逐字节相同"实测**：`doc/{axi_xbar,axi_demux,axi_mux}.md`、`src/axi_pkg.sv`、
  `src/axi_demux.sv`、`src/axi_mux.sv` —— 本地快照 vs v0.39.10 **全部 `diff` 空（IDENTICAL）**，
  与 memo §2 表逐行相符。据此 memo §4 关于 #406（`axi_demux_id_counters` 拆分）"不进入
  `axi_xbar` 强制子模块例化树"的论断成立：`axi_demux.sv` 逐字节未变 ⇒ 未引用任何新独立
  module，覆盖率层次（spec §0 item 4）不变。
- **`axi_xbar.sv` 唯一上游实质差异实测**：upstream v0.39.9 vs v0.39.10 的纯上游 `diff`
  **恰为**删除 `pragma translate_off / ifndef VERILATOR / ifndef XSIM` 保护下的
  `check_params` initial 断言块（校验 `$bits(slv_ports_req_i[0].aw.id)` 与
  `slv_ports_resp_o[0].r.id` 等于 `Cfg.AxiIdWidthSlvPorts`），与 memo §3（#407「Remove
  redundant assertions」）**逐字一致**；该块为 elaboration 期类型宽度自检，非功能/时序/
  响应行为，删除不改 spec §1–§8 任何外部可见行为——判定成立。
- **本地 P-002 隔离实测**：本地 `axi_xbar.sv` vs upstream v0.39.9 的 `diff` **恰为** P-002
  三处宽度改写（`AddrMapMsb` localparam + `axi_xbar`/`axi_xbar_intf` 各一处 `addr_map_i`
  端口宽度由 `[Cfg.NoAddrRules-1:0]` 改 `[AddrMapMsb:0]`），与 VENDOR.md P-002 记录一致；
  本地快照**不含** #407 删除（仍保有 check_params 块），证实 memo §2 脚注"diff 中相关行
  是我们的补丁、与上游演进无关"成立。
- **Defer 结论研判**：收益对 `axi_xbar` 验证为零（7 个蒸馏来源全不变，spec 正文/sha256
  pin 无需动）；成本为 P-002 行号漂移重做 + M0 sanity 重跑 + 重 pin。`doc/spec.md` 的
  sha256 无需变更这一判断，与"蒸馏来源逐字节不变"实测一致。**Defer 于 M1 合理、不阻塞**。
  一点非阻塞观察：memo §4 把 #406 归于 v0.39.10 CHANGELOG，而本次比对显示其未落到
  `axi_demux.sv`（该文件跨版本逐字节相同）；load-bearing 的"byte-identical ⇒ 不进例化树"
  结论不受影响，CHANGELOG 归属细节不追究。
