## Guidance（原则 + 方向，不代写正文）

- **忠实渲染 ≠ 逐字照搬模板的范围令牌。** 仲裁裁决被应用为 spec 正文时，模板
  提供的是**四段形态**，不是里程碑范围。范围须回到该 bug 自身已批处置与其活
  约束载体去取——BUG-0032 的处置锚在 M3（裁决确认句 + fix 文 + testplan/env 皆
  M3），且 M4 被显式留作 reopening 触发点。把范围写成 M3/M4 会在 spec 里凭空
  绑定一个**无 M4 artifact 承载、且 bug 明确留待重开**的约束，这正是 Q1 所防的
  "越裁决发明"。
- **若 arch 确实主张 M4 腿**（依 §8.4 parity），那是一次**独立的范围决定**，须
  (a) 在裁决中显式授权、(b) 同步在 M4 config-matrix testplan 行落地同一约束，
  使 spec 断言有 artifact 背书。二者当前皆不具备，故本轮取最小忠实渲染 = M3。
- reopening 路径不因收窄受损：part ④ "若强行违反本约束触发该组合时…作为上游
  确认项另行追踪" 已承接 M4 覆盖收敛若欲触发的情形；BUG-0032 guard（checklist）
  继续守 "约束不被悄悄解除"。
