## 1. BUG-0025 的 SPEC_ISSUE 仲裁（本卡的核心交付）

### 1.1 问题陈述（去掉转述后的原始问题）

两问，REV-010 §3.4 把它们合并成一问，本卡先拆开：

- Q-a：spec §5.2 的保序约束是否适用于**译码未命中**事务？
- Q-b：**error slave 响应**与「同 ID、同方向、目标为正常 master 端口的更老响应」
  之间的次序关系是什么？

### 1.2 裁决（三层，逐层给许可来源）

**第 1 层 — default master port 半边：不存在 spec 缺口，§5.2 直接适用。**
xbar.md L35 原文 "any address … is routed to **the default master port** instead
of the decode error slave"；spec §3.3.2 同述。它是一个**真实 master 端口**
（§2.3 `default_mst_port_i` 取值即 master 端口索引），§5.2.1 的"目标为不同
master 端口"对它字面适用，§5.2.4 同理。REV-010 §3.4 的这一半结论**成立**，
本卡复核后维持：**纯 TB_BUG，无需仲裁**。

**第 2 层 — 完整 ID 维度：可断言，且 spec 现文已足够，无须新增行为条款。**
这一层是本卡与 REV-010 §3.4 的**分歧点**。REV-010 判「§4.5 只给了『响应
ID/握手遵循 AXI4 一般规则』⇒ 未作定义」。本卡亲读三份许可来源后不同意该
读法：AXI4 的"一般规则"里**明确包含**同 ID 同方向响应保序，而这一点并非要
读者自行补全——**许可来源自己写出来了**：

> xbar.md L86: "The reason for this ordering constraint is that **AXI
> transactions with the same ID and direction must remain ordered**."

crossbar 的 slave 端口本身就是一个 AXI4 slave 接口（spec §1：实现完整
AXI4；xbar.md §开篇同述），该接口上出现的两笔**完整 ID 相同**、同方向事务，
其 B/rlast 完成序必须与接受序一致——这条义务**只依赖接口，不依赖内部路由**，
因此与该事务被送去 master 端口、default master port 还是内部 err_slv 无关。
§4.5 把 err_slv 响应显式拉回"AXI4 协议一般规则"，正是把它纳入而非排除。
⇒ **Q-b 在完整 ID 维度上有确定答案：error slave 的响应不得越过同一 slave
端口上同完整 ID、同方向的更老响应。** checker 必须把译码未命中事务纳入这
一维度（今天它被整条丢弃，是漏检）。

**第 3 层 — 低位 ID 桶维度（完整 ID 不同）：许可来源确实未定义，不可断言。**
§5.2.1/§5.2.2 的桶级约束以"**不同 master 端口**"为条件；§4.1 与 xbar.md L33
把 err_slv 定为"每 slave 端口**内部的**模块"，不是 master 端口；demux.md
§Ordering and Stalls（L54-76，本卡全读）与 mux.md 对 err_slv **一字未提**
（grep 空集）。而 AXI4 对**不同 ID** 之间不设次序义务，故第 2 层的兜底在这
里不成立。⇒ 这一层是**真 SPEC_ISSUE**（taxonomy "does not define the behavior
at all"），且**不得**用断言表达：无来源的断言在 M3 错误路径场景会假红——这
正是 BUG-0013/REV-006 已经付过一次学费的形状（字面读法 → 确定性假红 →
降级为 cover）。

**归属结论**：Q-a 的答案是"分层适用"（第 1、2 层适用，第 3 层未定义）；
Q-b 的答案见第 2、3 层。**SPEC_ISSUE 半边到此仲裁完毕**，不再是 open 的
spec 债（rubric 第 6 条意义上：本记录即其书面裁决）。落地需要一条**成文
条款**，理由是第 3 层的"不断言"必须**可引证**——见 §1.3。

### 2.2 但 (b) 不是零工作量 —— 本卡的新发现（推翻三处记载）

`doc/bugs/BUG-0024.md`、`doc/bugs.md` 行、REV-010 §1 均断言本条"方向是**漏检
（假绿侧）**，不会造成假红"。本卡按 `stall_sva.sv:129-134` + `:273-283` 结构
推演，**该断言不成立**——存在一条**假红**路径：

- 登记侧对同一完整 ID 的每次 AW 接受都**覆写** `w_id_seq[aw_id] <= w_seq_ctr`
  ⇒ 表里留下的是该 ID **最新**一笔的序号；
- 而 AXI 同 ID 同向按接受序完成 ⇒ 实际完成的是该 ID **最老**那笔；
- `w_reorder()` 用 `w_id_seq[cand] < w_id_seq[completing_id]` 判"更老"，
  **完成侧用的是被覆写后的（更大的）序号** ⇒ 判"更老"的门槛被抬高。

构造（单 slave 端口，桶 0，完整 ID X=0x0 / Y=0x8）：
`AW X→tgtA (seq0)` → `AW Y→tgtB (seq1)` → `AW X→tgtA (seq2，§5.2.4 合法堆积，
覆写 seq[X]=2)` → `B for X（实为 seq0 那笔）`：此时 `w_id_open[Y]=1`、
`tgt[Y]=B≠A`、`seq[Y]=1 < seq[X]=2` ⇒ **报 SVA_OR_W_REORDER**。而真相是该笔
X 在 Y **之前**被接受，先完成完全合规。**假红。**

现有 9+1 个场景没撞上它，是因为唯一有堆积的 OR03 只用单一完整 ID（无兄弟
候选），TL01/TL02 的兄弟全部同目标（`tgt !=` 恒假）——**M3 的多桶 + 目标切换
场景同时具备这两个要素**。

**影响评估**：假红**不会**制造假 PASS，故 **M2 七条证据与 REV-010 "对已登记
证据无影响"的结论不受动摇**（本卡确认）。受影响的是修复方案：(b) **不能只写
文档**，必须让判决在其声明范围之外**真正解除武装**（模块内已有独立于判决表的
在飞计数 `w_n[]/r_n[]` 可作为该前提的来源），否则一条"声明不判"的断言仍会开火。
