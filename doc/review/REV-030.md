### 2.2 [Kind-A→CW-009]——demux Cond `w_open==15` bin：登记，pass

`axi_demux_simple.sv:168` 主表达式 term2 `(w_open != {IdCounterWidth{1'b1}})` 取 0 需 `w_open` 达全一=15。`IdCounterWidth=idx_width(MaxMstTrans=10)=4`（`sv:69`）故全一=15；但 `w_open`（`i_counter_open_w`，记已路由而 W 未完成的 AW 数）可达上界结构封顶远低于 15——下游 `axi_mux i_w_fifo` 深度 = `MaxWTrans=Cfg.MaxSlvTrans=6`（`axi_mux.sv:319/46`+`axi_xbar.sv:141`），W 不排空则 mux w_fifo 满 6 笔后 `aw_ready` 拉低、demux 锁定第 7 笔（`w_cnt_up` 已 +1，`sv:181`）即无法再路由、`w_open` 冻结；加 `PipelineStages=1` 缓冲上界 ≈9 < 15。经验佐证：`slvport_agent.sv:448–466` `drive_burst_wopen` LEAD=10 全 SEED 净完成、LEAD=11 自死锁触 watchdog（AW→W 链在 ~10 处即无空间）。**结构不可达成立 → 登记 CW-009（Kind-A）**，解锁 = 配置把 AW-ahead-of-W 缓冲深度提至 ≥ `2^idx_width(MaxMstTrans)−1`。**pass。**

### DV-C（#17）— axi_mux `mst_req_o.b_ready` 写响应背压

### DV-E（#16）— axi_demux_simple `ar_id_cnt_full && aw.atop[ATOP_R_RESP]` 双 1 交叉

- **目标 bin**：`axi_demux_simple.sv:168` Cond 缺口 5 之 4（主表达式 `1 1 0` + `(!(ar_id_cnt_full && atop[R_RESP]) || !AtopSupport)` 取 0 + `!(…)` 内层 AND=1 + 内层 `(ar_id_cnt_full && atop[R_RESP])` 双 1）。
- **可行性终判（本卡卡片点名，rev 独立核实）**：**可行，非结构性时序矛盾**。理由链：
  1. `ar_id_cnt_full` = `i_ar_id_counter.full_o` = `|cnt_full`（`axi_demux_simple.sv:557`，**全桶 OR**），某桶满 = `&in_flight`=15（L615）。urg 亲证内层 `1 0` bin **已 Covered**——即 `ar_id_cnt_full=1` 单独在现 env（M2-TL01/M3-TL01 同桶压力，`resp_hold>0` 令 R 不排空、AR 计数器 pop 于 R 末拍）**已被触达**；`atop[R_RESP]=1` 单独亦 Covered（M2-AT01 atomic-load）。**唯一未测 = 二者同端口同拍共存**。
  2. **无死锁**：填桶用从机侧 `resp_hold`（`mstport_agent.sv:40`，时间驱动、自动释放），与 driver 线程解耦；atop 写呈现后因 term3=0 被 stall（`aw_ready` 低），待 `resp_hold` 释放 → R 排空 → AR 计数器落 → `ar_id_cnt_full`→0 → `aw_ready` 升 → atop 写放行。stall 是**合法 DUT 行为**（防 atop 注入令 AR 计数器溢出，`sv:165–167` 注释自述），非挂死。cond bin 在 stall 窗口内即命中（L168 组合式，`atop[R_RESP]` 一旦驱高且 `ar_id_cnt_full=1` 即评估 1&1）。
  3. **注入桶无关**：guard 检的是**全桶** `ar_id_cnt_full`，故 atop 写的 `aw.id` **无需**与被撑满的 AR 桶同桶——任一 AR 桶满即挡任一 atop 写，构造自由度更大。
  4. **阻塞驱动疑虑排除**：基础 `drive_read`/`drive_write` 虽单笔阻塞，但 `drive_burst`（同向多笔在飞）与 `drive_pair`/fork 模式证明 env **支持同端口并发驱动**；#16 需一条**新混向 primitive**（fork：撑满同桶 AR 群 + 在满窗口内呈现 atop 写），非现有 primitive 能直出——但这是**加驱动能力**，非结构矛盾。故**判定为需 DV 卡、非 SPEC_ISSUE、非 TB_BUG**。
- **构造**：宿主 = 新行（如 M4-BP04）或扩 M3-AT02/M2-TL01。step：(a) 单端口用 `resp_hold>0` + 同桶 ≥15 笔读撑满 AR 计数器（M2-TL01 机制）；(b) 满窗口内 fork 呈现一笔 atop-load 写（M2-AT01 机制，`aw.atop[ATOP_R_RESP]=1`）；(c) 释放背压全排空。
- **判决门**：scoreboard 路由/数据/响应正确 + atop 的 B 与 R 两通道均返回（SPEC-6.3）+ 一条**非判决 cover** 见证"`ar_id_cnt_full=1` 时一笔 atop 写在同端口在飞"；红线：不得断言 stall 解除具体拍/计数值（SPEC-7.4.5，有效上限非字面 MaxMstTrans，BUG-0016）。env：本卡**含** atop 写但打在**命中**地址（非未命中，避 BUG-0032/SPEC-4 clause 7 约束）。**估级 L2**（新混向 primitive + atop-under-full 的 scoreboard 覆盖）。
