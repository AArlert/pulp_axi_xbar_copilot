## Guidance（原则与方向，不写实现）

**G1 — 底板的价值全在"可机械复核"，一个已知错值就削掉一半。** §6.3 被里程碑
文件指定为未来签核核读 UNOWNED=∅ 的底板；底板里任何一个字段与原始 urg 不符，
下一位复核者要么信错、要么被迫重做全表——正是本 bug 的成因。原则：**底板字段
只放能从原始报告一条命令复算出来的量**；`counter` 的"例"列既已被 REV-031 §6
订正为 12，底板不应继续写 108。方向留给卡E：或订正该格、或删掉"例"列（它不参与
任何判定），二选一，不要留"正文对而表格错"的态。冻结的 final-sweep 正文按
FB-23"冻结记录不回改"维持原样，只在底板侧对齐。

**G2 — "rev 签核书面豁免"的签核是可查的引用，不是口头存在。** M4 出口第三条 (b)
的字面要求就是 rev 签核；一条 rev 记录列写着"待 rev 卡填"的豁免，在签核核对时
无法机械确认它被签过。原则：**每条 CW 行的 rev 记录列必须指向一份实有 REV 文件
与章节**。CW-002 的实质裁决已在 REV-024 §4 + REV-026（先例引用），方向是把引用
补进列里；同时把它的 (模块,类型) 列扩到它实际被引用的模块页（或反过来，把 §6.3
里越界的引用去掉）——两者取其一，不要两边不一致。这是卡E 的核项，不是新裁决。

**G3 — bin-scoped 豁免必须在自己的 (模块,类型) 列点名它承接的每个模块页。**
这是 spec §0#4"判定单位 =（模块,类型）二元组"+ BUG-0038"不得以父模块豁免代表
子模块"的直接推论，也是 CW-010/012/013 已经在用的写法。CW-007 是唯一没跟进的
一条。原则：**豁免的作用域以它自己那一行为准，引用方不能替它扩权**——否则
"某格有归属"就退化成"某处提过它"，而后者正是 BUG-0049 被漏掉的机制。方向：
要么扩 CW-007 的 (模块,类型) 列并补一句 `rr_arb_tree` 的 size[2] 位归因，要么在
§6.3 去掉该 token（该格本就由 CW-010 + DV-A + DV-F 承接）。

**G4 — 记录的完整性是它作为一手材料的前提。** REV-033 是 CW-014 与 spec 修改
记录 #12 共同引用的一手件；文件尾的工具标记不改变结论，但它说明"落盘后无人
`tail` 过一眼"。原则：**记录类文件落盘即属证据链，提交前至少看一眼首尾**。
方向留给 orch：这是纯清理（删两行尾巴），不涉及内容改动，因此不触"冻结记录
不回改"——被冻结的是判断与论证，不是工具垃圾。

**G5 — N/A 的"已核实成因"是 spec 明文要求的判定要件，写错等同没写。**
spec §0#4 让 N/A 不进分子分母，代价就是必须给出经核实的结构成因；成因一旦被
同一份报告的另一节证伪（如 N/A⁶ 说"无 if"而 Line/Branch 表列着 IF-37/IF-38），
这一格的三态判定就失去支撑。原则：**N/A 的成因要能被原始报告正向支持，而不是
只在直觉上说得通**。方向给卡E：对 59 个 N/A 格做一次"成因 vs urg 明细"的抽样
反证（`stream_register` Cond 已知需重述），不必逐格重写。

**G6 — 本卡的方法本身值得固化。** 本次 UNOWNED=∅ 的判定被压成了一条可粘贴、
确定性、退出码即判据的命令（见关闭证据首行），输出签名 `RESULT CELLS=132
LT90=30 UNOWNED=0`。提案 §8.2 把 UNOWNED=∅ 诚实地划为"人核、机核可选待建"；
现在它的机核原型已经存在。原则：**人核项一旦被压成确定性命令，就该往门里挪**。
方向留给 orch/arch 判断是否值得建一张 tooling 卡把它挂进 `make check`——注意
`workflow/discipline.md` §2 的例外条款：门不是过度设计。
