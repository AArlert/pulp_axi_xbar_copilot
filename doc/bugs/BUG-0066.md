# BUG-0066 — `scripts/regress.py:50` unconditionally `make -C sim clean`s away the M4 coverage-evidence base

## symptom

`make regress` (`sim/Makefile`'s `regress:` target forwards to
`python3 ../scripts/regress.py`) called
`subprocess.run(["make", "-C", str(sim), "clean"], check=True)`
unconditionally as its very first action, before running a single test in
the regression list. `sim/Makefile:187`'s `clean:` target is
`rm -rf $(OUT)` (`$(OUT)` defaults to `sim/out`) — a bare `make regress`
therefore deleted the entire `sim/out/` tree in one shot, including all 7
`cov.vdb` coverage databases (baseline + `m0/` + `cfgA`..`cfgE`) and
`sim/out/urgText6/`, with no confirmation and no way to opt out.
`sim/out/` is `.gitignore`'d (line 3) — none of that has a
version-control backup, and it is M4 signoff's entire coverage-evidence
base.

            unconditionally, before iterating the regression list
anomaly:    sim/Makefile's clean: target (`rm -rf $(OUT)`) removes every

            $(OUT) alike — it does not distinguish "stale incremental

            guarding against) from "signoff evidence with no other copy"

            regress.py's clean call was never revisited when that

## fix
commit: <待 orch 回填>
what: `scripts/regress.py`'s unconditional `make -C sim clean` call is
now gated behind an explicit opt-in — `--wipe` CLI flag or `COV_WIPE=1`
environment variable. The default path skips the clean entirely and
prints why (`"regress.py: skipping \`make -C sim clean\` (default,
BUG-0066)..."`). When the wipe *is* requested, a new `_wipe_targets()`
helper globs `sim/out/**/cov.vdb` + checks `sim/out/urgText6` and prints
the exact list of paths about to be destroyed before `make -C sim clean`
actually runs. `python3 scripts/regress.py --help` documents both
branches and the rationale for each. `sim/Makefile`'s `clean:` target
itself is untouched — the defect was in the caller, not the target (this
card's exclusion zone). New permanent regression coverage:
`scripts/tests/test_regress.py` (6 test cases, wired into `make
selftest`), which builds a fake `sim/Makefile` with `run:`/`clean:`
targets shaped like the real one and asserts the *actual filesystem
effect* (files present/absent after the run), not just what argv
regress.py happens to build.
