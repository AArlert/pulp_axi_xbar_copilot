# BUG-0034 — R burst 重建 checker 在合法跨 ID 交织下误报（TB_BUG，REV-015 终判）

- **状态**: TB_BUG（REV-015 终判；DUT_BUG candidate 被否决，taxonomy 改判
  TB_BUG——待派独立 TB 修复卡，见 `## fix`）
- **suspect**: TB（DUT_BUG candidate 已被 rev 独立复核否决；DUT 行为与其
  自身上游文档一致，不发起上游 issue）
- **发现**: M3-AT02（配置点⑤落地卡，DV）构造 spec §6.5 跨方向假冲突时；
  DUT_BUG candidate 由三工具交叉诊断卡提出，经 REV-015 复核改判 TB_BUG
- **严重度**: 中；已用单拍构造绕过，M3-AT02 已转绿，不阻塞 M3；R burst
  重建 checker 的多拍交织覆盖缺口须在 M3 签核时披露（见 `## regression_guard`）

## symptom

M3-AT02 需在同一 slave 端口令一笔要求读响应的原子操作（`aw.atop` =
ATOMICLOAD，目标 mstB）与一笔**低 `AxiIdUsedSlvPorts=3` 位相同、完整 ID
不同、目标 mstA ≠ mstB** 的普通读在飞重叠，使 spec §6.5 所述影子 AR 假冲突
真实发生。当两腿的读 burst 均为**多拍**（leg A read `AxLEN=3` → 4 拍）时，
slave 端口 R 通道观测到四路 checker 报错同时命中（单拍构造下全部为 0）：

- `tb/slvport_agent.sv:521` `MON_RNOAR` — R beat 找不到匹配的已接受
  AR/atomic-load AW。
- `tb/sva/axi_chan_sva.sv:252` `SVA_RLAST_LEN` — RLAST 落在错误 beat
  index（`RLAST beat index 2 != AxLEN 3`、`index 1 != AxLEN 0`）。
- `tb/scoreboard_refmodel.sv:931` `SB_RBEATS` — 普通读 id 的 R beat 数被
  截短（`beat count 3 != 4`、`2 != 4`），另有游离 beat。
- `SB_ATOP_DANGLING` — atop 的 R 半永不返回（B seen=1, R seen=0），
  `SB_RESP_ROUTE`/`SB_RESP_DANGLING` 连锁。

**REV-015 终判**：这四路不是四个独立信源，是同一个"R 永不交织"重建假设
在四处的同一次失效（见 `## rca`）；线上物理层收发计数全对，无数据丢失。

## first_anomaly

signal: `tb_top.slv_if[0].r_id` / `r_valid` / `r_last`
time: 185ns（`m3_at02_atop_read_test` SEED=1，交织窗口 165–205ns 内）
how_found: xdebug `event.export`（clock=`slv_if[0].clk_i` posedge/before，
expr=`rvalid && rready`）导出逐拍表，见下：

| time | r_id | r_last |
|---|---|---|
| 165ns | 0x00 | 0 |
| 175ns | 0x00 | 0 |
| **185ns** | **0x08** | **1** |
| 195ns | 0x00 | 0 |
| 205ns | 0x00 | 1 |

id0（4 拍普通读）第 3 拍前，id8（atop，单拍含 r_last=1）被逐拍插入。
xwave（独立实现，同一 FSDB，`event.config.load`+`event.export` 同表达式
同窗口）给出同一 r_id 序列 `00000, 00000, 01000(last), 00000, 00000(last)`
——两个独立 FSDB 解析器逐拍一致，排除单一工具解析错误的可能。

DUT 内部信号（同批 xdebug 追加取证）：R mux 选中端口 `genblk1.r_idx` 在
165/175ns=0(mst0)、**185ns=1(mst1)**、195/205ns=0(mst0)；arbiter `lock_q`
全程 0；`ar_id_counter.occupied` 恒 `0x01`（该桶全程被占用，两笔同桶读
并发在飞于不同 master port）——两笔读的完整 ID 为 `0x00`/`0x08`，互不相同。

**taxonomy 判定过程（曾经的候选结论，已被 REV-015 否决，保留作对照）**：
诊断卡最初以为"两个独立 FSDB 解析器给出一致的物理 beat 序"就足以否证
TB_BUG、坐实 DUT_BUG——这一步是范畴错误：两个解析器证明的是**物理 beat
顺序为真**，不证明"该顺序构成协议违反"，也不证明"scoreboard 的判决正确"。
观测一致 ≠ 观测解读正确，REV-015 复核指出正是这个陷阱。

**REV-015 订正**：上两条援引里，"§1/§5.5.3 禁止读数据交织"**不成立**——
spec 钉定本中禁止交织的条款只覆盖 **W 通道**（§5.5.1）；R/响应侧
§5.1.4 + 上游 `vendor/axi/doc/axi_mux.md:18` **明文允许**不同完整 ID 的
响应交织（框定为性能特性）；§5.5.4 明文**禁止** checker 断言 round-robin
发生序/beat 级授权时点。§6.5 的援引本身没错，但据此推出"DUT 违反 §6.5"
是误读——上游 `axi_demux.md` §Atomic Transactions 原文把这一交互框定为
"额外假冲突 stall（性能）"而非正确性问题，与 §6.5 一致，非矛盾。
