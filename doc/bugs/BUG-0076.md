# BUG-0076 — M5-AT03 激励缺 atomicload 阶段，cp_atop_subtype 四 bins 声称与证据矛盾

## symptom

testplan M5-AT03 行判据要求"`cg_atop` 的 `cp_atop_subtype` 四 bins
（atomicstore/atomicload/atomicswap/atomiccmp）在本行运行后须全部命中"，
该行已 ✅。但证据 `doc/evidence/v0.5.12/M5-AT03.log` 的 FCOV_SUMMARY 聚合值
`cg_atop: samples=18 inst_cov=93.75%` 经代数反推（其余 3 个成员均 100%，
`(100+100+X+100)/4=93.75 ⟹ X=75%`）表明 `cp_atop_subtype` 只命中 3/4 bins。

## first_anomaly

signal: `cg_atop.inst_cov=93.75%`（doc/evidence/v0.5.12/M5-AT03.log L31）
time: n/a（证据静态复核）
how_found: M5 收口审计的证据链反稀释核查（0.5.15）交叉计算聚合覆盖率发现；
表面读 FCOV_SUMMARY 不可见——打印函数恰好不输出 `cp_atop_subtype` 自身系数
（报告盲点，同步修复）。

## repro

`make run TEST=m5_at03_atop_subtypes_test SEED=1`（修复前代码态），观察
FCOV_SUMMARY `cg_atop` 聚合 93.75%；源码走查 `tb/seq_lib.sv`
`slvport_at03_atop_subtypes_seq::body()` 仅 Phase A(store)/B(swap)/C(cmp)
三阶段，结构上从不产生 `ATOP_ATOMICLOAD` 编码。

## taxonomy

TB_BUG——激励生成器与本场景自身判据声明不符（atomicload bin 结构性缺失），
且 FCOV_SUMMARY 打印函数缺该 coverpoint 使缺口在摘录层不可见。反稀释纪律
（milestone.md 四条第 2 条）下该行本不应翻绿。

## rca

```
observed:   cp_atop_subtype 只命中 3/4 bins，行判据声称 4/4
anomaly:    激励只有三阶段；打印盲点掩盖了缺口
chain:      M5-AT03 场景为 BUG-0044（store/swap/compare 应答义务缺 spec）
            而设，注册行文照抄了"四 bins 全命中"的完整性目标，但激励设计
            只做了 BUG-0044 的三个新增子类型（atomicload 已由 M2-AT01 充分
            覆盖的思维定势）；FCOV_SUMMARY 只打印 cp_src/cp_r_resp/x_cross
            三个成员，聚合值的稀释无人换算
```

## fix

1. `tb/seq_lib.sv`：`slvport_at03_atop_subtypes_seq` 增加 Phase D
   （atomicload，`{ATOP_ATOMICLOAD, LITTLE_END, ADD}`，§6.3 B+R，ID
   `slv_port_idx+24`）。
2. `tb/functional_coverage.sv`：FCOV_SUMMARY 的 `cg_atop` 段补印
   `cp_subtype`，消除报告盲点。

## reverify

修复后 `make run TEST=m5_at03_atop_subtypes_test SEED=1`：`cp_subtype=100.00%`
（四 bins 全命中），UVM_ERROR/FATAL 0；多种子回归全绿。evidence 列由
`make evidence` 回填。
