# BUG-0047 — M4「六类含 Toggle ≥90%」与「M5 前仅定向、随机不得替代 M4 定向关闭」的可行性张力

## symptom

无仿真失败触发——这是 M4 完整签核卡（rev，REJECTED verdict）人工抽查
过程中浮出的一处**判据本身的可行性冲突**，不是某次运行报的红。
`doc/milestone.md` M4 出口条件字面写"六类口径…≥90%"，六类含 Toggle；
`doc/evidence/v0.4.9/M4-coverage-baseline.md` 显示多处 Toggle 缺口
（`axi_xbar` 顶层 40.74%、`axi_mux` 55~58%、`addr_decode_dync` 53~57%、
`axi_demux_simple` 68~69% 等）在现有定向场景矩阵下长期停滞——较
v0.4.0 基线几乎没有提升（唯一例外是 `axi_xbar` 的
`en_default_mst_port_i` 单一信号方向，由 M4-RC01 定向补齐）。这类缺口
的天然解法是约束随机大范围扫描地址/数据/ID 位组合，但
`doc/milestone.md` M5 节明文"定向优先（M4）、随机后（M5）是证据链
项目的正确顺序——随机只能加固/发现，不能替代 M4 的定向关闭"，且 M5
排在 M4 签核之后启动（REV-019 裁决）。即宽总线 Toggle bin 的天然解法
在 M4 阶段被架构性排除。

## arbitration

**REV-024 终判：维持 SPEC_ISSUE（planning-gap 型），处置 = 治理文档订正
（非 pinned-spec 行为条款改动、不重 pin）。** 逐条独立划界（核对
`M4-coverage-baseline.md` §6 九行 + RTL 结构）后确认：**本条的方法论
受限面远比表面窄**——证据里 ~6 类"可达未测"缺口中，**仅宽 W/R.data
载荷位翻转属方法论受限**（当前只有 `axi_mux` Toggle 子集有明确结构
依据，`axi_mux.sv:33/39` 承载 64-bit `w_chan_t`/`r_chan_t`）；
`addr_decode_dync`（地址/rule 多样性不足，`axi_xbar.sv:92` 证
`default_mst_port_i` 是 6×3-bit 窄索引非载荷）、各 Cond/Branch/Assert、
握手背压、实例级颗粒度**均不属，维持需补场景**——这条划界正是防止
本条被误用来"顺带"豁免那些其实只是没写场景的缺口。

**采纳用户方向**（"定向能做到的都做到、真正做不到的不强制 90%"），
**但严格限定在上述划界后的窄子集**。落地形态：

- **不扩展 pinned spec §0 三态**（更外科、免重 pin）——三态是测量读数
  规则，"方法论受限 vs 结构不可达"是 FAIL 的处置（豁免）种类，二者
  正交；豁免种类要求改落 `doc/milestone.md` M4 出口条件（已追加子项）
  + 新建 `doc/coverage-waivers.md`（Kind-A 结构/环境不可达永久 / Kind-B
  方法论受限延后 M5 临时，两类各自的可证伪解锁条件不同）。
- **Kind-B 豁免须可证伪解锁**：M5 决策点 2（约束随机激励层）落地 +
  决策点 5（cov_loop）对具体 bin 重新测量，若仍 <90% 才可讨论转永久或
  补定向；被推翻即作废 = 任一 M5 随机跑使该 bin ≥90%。**不是**"以后
  M5 会处理"的软承诺。
- **本裁决不预先授予任何 Kind-B 豁免**——须先有逐信号/逐位 toggle
  分解证据（区分"宽载荷位"与"定向可达位"）才能正式登记进
  `doc/coverage-waivers.md`。M4 签核 REJECTED 判决因此**整体仍然成立**
  ——本裁决只给出合法出口框架，不清空残余。
