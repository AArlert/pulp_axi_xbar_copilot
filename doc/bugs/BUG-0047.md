# BUG-0047 — M4「六类含 Toggle ≥90%」与「M5 前仅定向、随机不得替代 M4 定向关闭」的可行性张力

## symptom

无仿真失败触发——这是 M4 完整签核卡（rev，REJECTED verdict）人工抽查
过程中浮出的一处**判据本身的可行性冲突**，不是某次运行报的红。
`doc/milestone.md` M4 出口条件字面写"六类口径…≥90%"，六类含 Toggle；
`doc/evidence/v0.4.9/M4-coverage-baseline.md` 显示多处 Toggle 缺口
（`axi_xbar` 顶层 40.74%、`axi_mux` 55~58%、`addr_decode_dync` 53~57%、
`axi_demux_simple` 68~69% 等）在现有定向场景矩阵下长期停滞——较
v0.4.0 基线几乎没有提升（唯一例外是 `axi_xbar` 的
`en_default_mst_port_i` 单一信号方向，由 M4-RC01 定向补齐）。这类缺口
的天然解法是约束随机大范围扫描地址/数据/ID 位组合，但
`doc/milestone.md` M5 节明文"定向优先（M4）、随机后（M5）是证据链
项目的正确顺序——随机只能加固/发现，不能替代 M4 的定向关闭"，且 M5
排在 M4 签核之后启动（REV-019 裁决）。即宽总线 Toggle bin 的天然解法
在 M4 阶段被架构性排除。

## fix

无 spec/RTL/TB 改动（现阶段）——本条尚未经 rev/arch 正式仲裁裁决，是
M4 签核卡的附带发现，交由后续裁决卡处理。待决路径（供后续裁决卡参考，
非本条自行拍板）：

1. **(i) 成本豁免扩展**：arch/rev 裁决是否扩展 REV-016 §9 的三态判定
   框架，新增"可达但成本不成比例"这一档——需给出可证伪的成本论证
   （例如：穷举某总线全部位翻转需要的最小定向场景数 vs 项目实际能
   负担的场景数量级），而非笼统说"随机更省事"。
2. **(ii) 判据口径重议**：走 spec §0 变更提案流程，考虑是否把 Toggle
   类型的判据从"六类统一 ≥90%"改为对特定宽总线信号单独降标或标注
   "M5 前 partial"，需 rev 门禁通过 + 重 pin。
3. 二者都不做的第三条路（供裁决卡评估，非本条预设结论）：接受 M4
   在 Toggle 类型上暂不达标、把这部分残余风险显式写入 M4 signoff
   记录的"残余风险"清单（`workflow/review.md` 允许 signoff 记录
   残余风险，不要求所有风险清零），留给 M5 的覆盖率驱动闭环
   （`scripts/cov_loop.py`）自然收敛后再补一次 M4 Toggle 类的
   事后确认。
