# BUG-0025 — 译码未命中的事务不入跟踪表，其完成不参与乱序检查（漏检）

## symptom

`tb/sva/axi_xbar_stall_sva.sv` 的跟踪表登记条件带 `aw_hit` / `ar_hit`
（地址译码命中某个 master 端口）：

```systemverilog
if (aw_valid && aw_ready && aw_hit) begin   // aw_hit==0 的事务不入表
  w_id_tgt[aw_id] <= aw_tgt; ...
end
```

译码未命中的事务（走 default port 或 error slave）因此从不进入在飞集合。
当它的 B/R 完成返回时，`w_id_seq[b_id]` 为 X ⇒ 与其它候选的序号比较恒假
⇒ 该完成**不参与任何乱序检查**。

安全但漏检：不会假红（X 比较恒假 ⇒ 不触发断言），但本该被检出的
"error slave 响应越过更老的正常响应"这类乱序会静默通过。

## taxonomy

TB_BUG

## rca

1. 跟踪表的登记条件要求译码命中（`aw_hit`），意图是"只跟踪有明确目标
   master 端口的事务"——因为 §5.2.1 的判据需要比较目标端口。
2. 但注销条件（B/R 握手）**不带**对称的过滤：任何完成都会去查表。
3. 未登记事务完成时读到的是未初始化的 `w_id_seq`（X），后续的序号比较
   恒为假 ⇒ 静默跳过。
4. 净效果：译码未命中的那一类事务对乱序检查完全不可见。

### 范围订正（REV-010 §3.4，2026-07-28——**本页原 rca 低估了缺陷范围**）

rev 亲读 `tb/sva/axi_xbar_stall_sva.sv:99-100`：

```systemverilog
always_comb aw_hit = decode_mst_port(aw_addr, ADDR_MAP, 1'b0, '0, aw_tgt);
```

`en_default` 参数被**硬编码为 `1'b0`**。故被跟踪表丢弃的**不止 error slave
流量**，还包括 spec §3.3.2 定义的 **default master port 路由流量**。二者的
spec 地位不同，**必须拆开处置**：

- **default port 半边 = 纯 TB_BUG，无需仲裁**：default master port 是一个真实的
  master 端口（spec §3.3.1/§3.3.2），§5.2.1 的「目标为不同 master 端口」对它
  直接适用。跟踪表把它当「未命中」丢弃是实现与 spec 不符，改法明确。
- **error slave 半边 = 真 SPEC_ISSUE，须先仲裁**：§5.2.1 以「master 端口」为
  约束单位，而 §4.1 的 per-port `axi_err_slv` **不是**外部 master 端口；§4.5 只给了
  「响应 ID/握手遵循 AXI4 一般规则」。即 spec 对「error slave 的响应能否越过同 ID、
  同方向、目标为正常 master 端口的更老响应」**未作定义**——taxonomy `SPEC_ISSUE`
  的教科书签名。按 `workflow/discipline.md` rule 1，DV 不得自行取舍。

## fix

未派发。修复方向（不预设实现）：使登记与注销的过滤条件对称，或让未命中
事务也以可区分的方式入表。**须先确认 spec 立场**：§5.2 的保序约束是否
适用于译码未命中（走 default port / error slave）的事务——若 spec 未明确
规定，本条应先走 SPEC_ISSUE 仲裁再定修法，不得由 DV 自行取舍
（`workflow/discipline.md` rule 1）。

严重度低（当前）：M2 场景全部为译码命中路径，本条在当前激励下不产生任何
差异。**但 M3 里程碑的主题正是"错误路径/decode error"**——届时它会从
"理论漏检"变成"真实盲区"，且盲区恰好落在该里程碑要验的东西上。故
建议在 M3 场景派发**之前**处理。
