# BUG-0001 — VCS-2018 编译上游 tb_axi_xbar 失败：genvar 环内 $sformatf 参数被判非常量

## symptom

`cd sim && make smoke TEST=upstream_sanity SEED=1` 在 compile 步即报 2 个
Error-[NCE]（Non-constant expression），make 返回 255；simv 未生成，仿真
未运行（sim/out/upstream_sanity_1.log 不存在）。报错原文（sim/out/comp.log）：

```
Error-[NCE] Non-constant expression
  The following expression should be a constant.
  Expression: $sformatf("axi_logger_master_%0d", i)
  "../vendor/axi/test/tb_axi_xbar.sv", 301
  Source info:       .LoggerName( $sformatf("axi_logger_master_%0d", i)),

Error-[NCE] Non-constant expression
  The following expression should be a constant.
  Expression: $sformatf("axi_logger_slave_%0d", i)
  "../vendor/axi/test/tb_axi_xbar.sv", 337
  Source info:       .LoggerName( $sformatf("axi_logger_slave_%0d",i)),

2 errors
```

## first_anomaly

signal: n/a（编译期失败，未进入仿真，无波形）
location: vendor/axi/test/tb_axi_xbar.sv:301 与 :337 —— generate for
（genvar i，gen_master_logger / gen_slave_logger）内 `axi_chan_logger`
实例的参数覆盖 `.LoggerName( $sformatf("axi_logger_master_%0d", i) )`
及 slave 侧同型写法
how_found: make smoke 的 VCS 编译日志 sim/out/comp.log（Error-[NCE]）

## rca

1. 上游 tb（axi v0.39.9 随包发布，上游 CI 工具链下可编译）在 generate
   循环内用 `$sformatf`（常量函数，实参含 genvar）覆盖 module 的 string
   参数。
2. VCS-MX O-2018.09-SP2 的 elaboration 常量表达式求值不支持该形态，判为
   非常量 → Error-[NCE]，编译中止。
3. simv 不生成 → M0-01 场景无法运行。

与 seed/stimulus 无关的编译期确定性错误；匹配 taxonomy 中 TOOL_ENV 判据
「clean lint yet compile-time weirdness / 已知工具（VCS O-2018）能力
特征」。非 DUT 行为问题（DUT axi_xbar 本体未涉及），非本仓库自研 TB
代码问题（本仓库 tb/ 尚无交付物）。

## fix

commit: -（未修复，DV 无权改 vendor/ 与 scripts/）
what: 建议走 DE vendor 工具兼容补丁卡（CLAUDE.md §6：P-xxx 登记 + rev
评审），将 LoggerName 覆盖改写为 VCS-2018 可求值的常量形态（或等效
兼容 workaround）；属兼容性补丁，不改 DUT 行为。

FIX_READY（DE，P-001，见 vendor/VENDOR.md）：tb_axi_xbar.sv:301/337 两处
`.LoggerName( $sformatf("axi_logger_{master,slave}_%0d", i) )` 改写为可常量
折叠的拼接 `.LoggerName( {"axi_logger_{master,slave}_", 8'(8'h30 + i)} )`，
消除两处 Error-[NCE]。最小探针实测：`$sformatf(genvar)` 直用 / 经 localparam
string 中转 / `string'(byte)` 强转在 O-2018.09-SP2 常量求值下均失败（NCE /
NYI），唯拼接形态可折叠。行为等价：LoggerName 仅用于日志目录 `./axi_log/
<LoggerName>/`（axi_test.sv 的 axi_chan_logger 仅在路径串里引用，不参与激励/
判决）；tb 配置 TbNumMasters=6、TbNumSlaves=8（下标 ≤7，单十进制位）下拼接
结果与原 %0d 逐字节相同，simv 实跑已核对（独立最小探针 + 目标文件重编）。
验证：本 BUG-0001 的两处 Error-[NCE]（301/337，$sformatf/LoggerName）已消除
——`make compile` 日志中该两条报错已不再出现，文件已解析并 elaborate 越过
301/337。重跑/证据归 DV，状态置 FIX_READY 不置 CLOSED。

注意（越出本卡范围、勿在本卡内动）：修掉 301/337 后 `make compile` 仍不
通过，暴露出**另一处独立**的 VCS-2018 NCE——`Cfg.NoAddrRules-1`（xbar_cfg_t
结构体成员参数选择）出现在 **DUT 源** `vendor/axi/src/axi_xbar.sv:84`
（module axi_xbar）与 `:190`（module axi_xbar_intf）的端口位宽处，经 tb 的
axi_xbar_intf 实例 elaborate 触发（共 6 条 Error-[NCE]）。此前被 301/337 的
2 条错误掩盖（原 comp.log 报 2 errors 即中止）。它与本 BUG-0001 根因不同
（结构体成员参数选择在端口位宽处折叠失败，同 floo P-001 的 TCF 类，而非
genvar-$sformatf 类）、文件不同（DUT 源，本卡明令不得动 vendor/axi/src/）。
应另开 DE vendor 工具兼容补丁卡（新 BUG + P-xxx）处理，由 rev 裁定。
