# BUG-0009 — `mstport_monitor` AW→W 写 burst 错配（M1-02 落地时发现）

## symptom

`make run TEST=m1_02_id_prefix_test SEED=1` 修复前跑出 4 笔 route 假失配
（`SB_NOPEND`/`SB_WDATA_LEN` 类）+ 结束时 7 笔 `SB_DANGLING`（slv 侧请求
从未观测到匹配的 mst 侧请求）。同一激励在 DUT 侧完全正确：resp-route
（C3.2，见 BUG-0009 引入前一并新增的判据）96/96 match，B/R 全部按 ID 前缀
高位正确回送到源 slave 端口，零跨端口错送。即失配只出现在"请求侧配对"
判据，"响应侧路由"判据零失配——两条独立判据的分歧本身就指向 checker
（TB 侧）而非 DUT。

## first_anomaly

signal: `tb/mstport_agent.sv` 内 `mstport_monitor.run_phase` 的
`w_id`/`w_len`（旧实现，单槽变量）
time: 首次分歧出现在某 master 端口收到第二个 `aw_valid && aw_ready` 握手、
而首个 W burst 尚未收满 `w_last` 的那一拍——此时旧代码用新到的 AW 元数据
覆盖了仍在收集中的 `w_id`/`w_len`/`w_addr`
how_found: M1-02 激励构造为多个 slave 端口在同一轮共享同一低位 ID、各自
指向不同 master 端口（testplan.md M1-02 主判据），因而比 M1-01（各端口
独立随机 ID、写 burst 汇聚时序较松）更容易在同一 master 端口触发写 burst
紧密汇聚/AW-W 解耦；DV 交付时对照 scoreboard 请求侧配对失配与新增的
resp-route（C3.2）判据零失配，判定失配集中在 mst 侧写观测的 monitor 输出
本身，反查 `mstport_agent.sv` 单槽变量在 AW 早到时被覆盖

## taxonomy

TB_BUG

`mstport_monitor` 对 AW/W 的配对假设（"下一个 AW 一定对应下一个 W burst，
且两者时序耦合"）在 master 端口处不成立——mux 处 AW 可与其 W 解耦（提前
或滞后接受），且多个 slave 端口的写 burst 会在同一 master 端口汇聚；这是
"monitor samples the wrong edge / 配对逻辑错误"一类，命中
`workflow/taxonomy/failure_taxonomy.md` 的 `TB_BUG` 判据原文
（"monitor samples the wrong edge"）。非 DUT_BUG：DUT 侧行为（W burst
按 AW 接受序、不交织，spec §5.5.2）本身没有违反 spec；也非 TOOL_ENV：
与 seed/工具版本无关，是 checker 建模缺陷，任何 seed 只要触发"AW 早到
第二次"的时序都会复现。

## rca

1. `mstport_monitor.run_phase`（旧实现）用单槽 `w_id`/`w_addr`/`w_len`/
   `w_size`/`w_burst` 变量：每次 `aw_valid && aw_ready` 握手都无条件覆写
   这些变量，并不检查上一笔写 burst 是否已通过 `w_last` 收尾（`w_busy`
   仅用于门控 W 收集起点，未阻止 AW 覆写）。
2. Master 端口的 `axi_mux`（DUT，vendor 快照）允许 AW 通道与 W 通道解耦
   前进——第二个 slave 端口的写请求可以在第一个写 burst 的 W 数据还没发
   完时就完成 AW 握手（多 slave 端口写请求在同一 master 端口汇聚是设计
   常态，非违规时序）。
3. 二者叠加：第二个 AW 握手覆写了仍在收集中的第一笔 burst 的元数据，
   随后到达的 `w_last` 用被覆盖的（错误的）`w_id`/`w_len` 生成
   `axi_req_obs`，把第一笔 burst 的 W 数据打包成第二笔 burst 的元数据
   （或反之）——mst 侧写观测的 beat 数/ID/地址与实际不符，个别情形下
   （W 收尾早于本应晚到的 AW 覆写前）mst 侧观测发布时间甚至早于对应
   slv 侧观测（因果倒置），scoreboard 的 `pending_by_id` 查找必然落空。
4. M1-01 未暴露：其激励各 slave 端口用独立随机 ID（`$urandom_range`），
   写 burst 汇聚时序较松，AW 早到-覆写窗口在该激励分布下未被命中；
   M1-02 同低位 ID + 8 轮并发在共享 master 端口紧密汇聚，命中概率显著
   提高（4 route 失配 + 7 dangling 实测）。

## fix

commit: 5dc53f9
what: `tb/mstport_agent.sv` 的 `mstport_monitor` 改用 AW FIFO 队列
（`aw_q[$]`）配对 AW→W：每次 AW 握手把元数据 push 进队列尾部，每次新
W burst 起始（`w_valid && w_ready` 且 `!w_busy`）从队列头部 pop 一条
（W burst 按 AW 接受序、不交织，spec §5.5.2 保证 FIFO 序即正确配对
序），若 W 到达时队列为空则 `uvm_error("MON_WNOAW", ...)` 主动报错而非
静默用陈旧/错误数据配对；镜像 `mstport_responder.w_collect_loop` 已有的
同类队列写法。同一 commit 顺带修复 `tb/scoreboard_refmodel.sv` 的
`pending_by_id` 键（原仅按 mst-side id 索引，M1-02 同一 slv-side id 分别
用于一笔写一笔读会在该 map 里别名——加方向位 `{is_write, mst_id}` 作为
新键，读写两个独立 AXI 通道不再互相覆盖）。
