# BUG-0077 — M5 soak 层无未命中激励，M5-SK03"命中与未命中均覆盖"声称与证据矛盾

## symptom

testplan M5-SK03 行 must-reach 声明"唯一 slave 端口须对全部 8 个 master 端口
均产生流量，命中与未命中（err_slv）路径均需覆盖"，该行已 ✅。但证据
`doc/evidence/v0.5.8/M5-SK03.log` 显示 `decerr(§4): resp=0`、
`cg_decerr_shape: samples=0`、`cp_route=33.33%`（三值 coverpoint 只中 1 bin）
——未命中路径全程零覆盖，与行文直接矛盾。按反稀释纪律（milestone.md 四条
第 2 条"到不了即该行不成立，哪怕零 mismatch"）该行本不应翻绿。

## first_anomaly

signal: `decerr(§4): resp=0`（doc/evidence/v0.5.8/M5-SK03.log L40）
time: n/a（证据静态复核）
how_found: M5 收口审计的证据链反稀释核查（0.5.15）逐行核对 must-reach 与
证据数据发现。

## repro

`make run TEST=m5_sk03_soak_test SEED=1`（修复前代码态）：`xbar_soak_seq`
的地址生成（round 0 peak / target sweep / random rounds）全部落在命中
region（`tgt*REGION_SIZE + addr_base`，region 0-7），结构上从不产生未命中
地址。milestone.md M5 设计要点声明的"未命中权重"旋钮从未落地。

## taxonomy

TB_BUG——soak 激励层结构性缺失未命中支路，场景行文声称的覆盖维度激励从未
构造。同源影响 SK01/SK02/RN01（各行未声称未命中覆盖，故不构成其行文矛盾，
但同补）。

## fix

`tb/seq_lib.sv`：`xbar_soak_seq::body()` 在 target sweep 后增加 decode-miss
leg——每端口单笔写+单笔读，region 索引取 `NO_ADDR_RULES`（基址
`0x8000_0000`，落在全部生成地址表的 rule 窗口之外），`atop` 恒 `'0`
（spec §4 clause 7 宽读），`en_default='0` 下由本端口 err_slv 以 DECERR
应答，判据复用 M3-DE01 既有 SB_DECERR 族（不新增判决维度）。

## reverify

修复后 `make run TEST=m5_sk03_soak_test SEED=1`：`decerr(§4): resp=2`、
`cg_decerr_shape samples=2`（cfgA 单端口 w+r），UVM_ERROR/FATAL 0；
baseline SK01 同验证 `resp=12`（6 端口 × 2）。多种子回归全绿。
