# BUG-0043 — `make regress` 一次运行里 `m1_02_id_prefix_test` 以
"sim process exited nonzero" 判 FAIL，日志内容干净，不可复现

## symptom

orch 独立复验 M4-FT01/BUG-0042 交付物（DV 自报 `make regress` 24/24 PASS）
时亲跑 `cd sim && make regress`（未手动先 `make clean`，但
`scripts/regress.py` 自身在整批测试前已内建一次 `make clean`），结果
`23/24`：

```
FAIL   m1_02_id_prefix_test SEED=1  [sim process exited nonzero]
```

其余 23 个场景（含刚落地的 `m4_ov01_overlap_test`/`m4_ft01_cfge_test`）全部
PASS。检查 `sim/out/m1_02_id_prefix_test_1.log` 本身：`UVM_ERROR : 0`、
`UVM_FATAL : 0`，无任何 `ASSERT FAILED`/`Error-`/`FATAL` 字样，`$finish`
正常在 1885000ps 结束，`V C S Simulation Report` 尾部横幅完整——日志**内容**
层面看不出任何失败迹象，只有 `scripts/regress.py` 记录的 `make -C sim run`
子进程本身的 shell 退出码非零，触发其 `rc != 0 → 强制 FAIL` 逻辑
（`scripts/make/vcs-2018.mk` 头注释原话："A nonzero `make run` exit should
force FAIL even if the log looks clean — an abnormal process exit is never
evidence of a clean run"，即本设计是有意为之，不是脚本 bug）。
