# BUG-0016 — 事务数上限（MaxMstTrans / MaxSlvTrans 可观测上界）不被守：RTL 实际在飞上限 = 2^ceil(log2(MaxTrans))-1，超出文档"at most MaxTrans"承诺

> 状态：OPEN（suspect DUT，taxonomy DUT_BUG——RTL 输出违反显式 spec/文档条款；
> 按 taxonomy 需 rev 签核方可"确认断言"）。本页为 in-progress 详情页——
> `fix`/`rerun` 段在裁决前如实留白/记待办，非编造。非阻塞：同一批运行里
> scoreboard 路由/数据/响应路由/完成判据全绿（每笔正确路由、数据正确、全部
> 完成），仅"文档承诺的数值上限"不被守。DV M2-TL01/TL02 落地首运行发现。

## symptom

M2-TL01（MaxMstTrans）与 M2-TL02（MaxSlvTrans 可观测上界）落地首运行，自研
`tb/sva/axi_xbar_txlimit_sva.sv` 在 master 端口侧按延迟不敏感口径计在飞数
（AW/AR 接受 +1、B/R-last 离开 -1），首版**断言**"在飞数 ≤ 文档上限"，两方向
均确定性假红/见红：

```
[MaxMstTrans, m2_tl01_txlimit_test SEED=1]  单 slave 端口向单一 master 端口、
  单一低位 ID 桶（跨该桶 4 个兄弟全 ID 铺开、每 ID ≤3）背靠背连发 12 笔写
  （responder 有界拖延 B），全部 12 笔被转发到 master 端口、同时在飞：
  SVA_TXLIMIT: MaxMstTrans reached ... hit 10        @325000ps   ← 达标
  SVA_TXLIMIT_MAXMST_W: ... already had 11 ... (>10) @345000ps   ← 超出
  SVA_TXLIMIT_MAXMST_W: ... already had 12 ... (>10) @365000ps   ← 再超出
  同次运行 scoreboard：route match=144 mismatch=0 | resp 144/0 |
  resp-route 144/0 | pending=0 | worder 72/0 | 全绿

[MaxSlvTrans, m2_tl02_slvtrans_test SEED=1]  单 slave 端口向单一 master 端口
  背靠背连发 8 笔同（前缀后）全 ID、同方向（写、读各一批），全部 8 笔在飞：
  SVA_TXLIMIT: MaxSlvTrans reached ... hit 6                     ← 达标
  SVA_TXLIMIT_MAXSLV_{W,R}: ... already had 7 ... (>6)           ← 超出
  SVA_TXLIMIT_MAXSLV_{W,R}: ... already had 8 ... (>6)           ← 再超出
  同次运行 scoreboard：route 96/0 | resp 96/0 | 全绿
```

即：外部可观测的、延迟不敏感的 master 端口在飞计数**超出**了文档承诺的
`MaxMstTrans=10` / `MaxSlvTrans=6`——分别达到 12（送 12 全放行）/ 8（送 8
全放行），且结构上（见 rca）demux 每桶计数器的真实封顶是
`2^ceil(log2(MaxMstTrans))-1 = 15`。这**不是** BUG-0013/§7.4.5 的"接受边界即时
性 ± spill 深度"效应（那是接受**边界时刻**的延迟不敏感、幅度为 spill 深度
1~2）；本条是延迟不敏感的**计数本身**超出上限，幅度来自计数器位宽取整。

## rca

因果链（first_anomaly → symptom），均基于**可读的 vendor 文档 + RTL 结构**
（未把行为搬进 checker）：

1. **文档承诺**：`vendor/axi/doc/axi_xbar.md` L46「Each slave port can have at
   most this many transactions in flight」（MaxMstTrans）、L47「Each master
   port can have at most this many transactions per ID in flight」
   （MaxSlvTrans）；`vendor/axi/doc/axi_demux.md` L72「Each counter can count
   up to (and **including**) `MaxTrans`」。三处均是**显式、定量**的"≤ MaxTrans"
   承诺。spec §5.4.1/§5.4.2 忠实蒸馏之。
2. **RTL 计数器定宽**：`vendor/axi/src/axi_demux_simple.sv` L69
   `IdCounterWidth = cf_math_pkg::idx_width(MaxTrans)`；`idx_width(N)=
   (N>1)?clog2(N):1`（`vendor/axi/src/../common_cells/.../cf_math_pkg.sv`）。
   MaxTrans=10 ⇒ 位宽 = clog2(10) = **4**，计数域 0..15。
3. **"full" 判定为全一，非 == MaxTrans**：`axi_demux_id_counters`
   （`axi_demux_simple.sv` 内联）L557 `full_o = |cnt_full`，L603
   `cnt_full[i] = overflow | (&in_flight)`——`&in_flight` = 计数器全一 =
   `2^4-1 = 15`。即每桶（AxiLookBits=AxiIdUsedSlvPorts=3 位 ⇒ 8 个计数器）在
   计数达 **15** 前均不 full、不 stall。故 demux 每桶真实在飞上限 = **15**，
   非 MaxMstTrans=10。送 12 同桶 < 15 ⇒ 全放行 ⇒ master 端口见 12。
4. **master 端口侧无 per-ID 计数器（MaxSlvTrans）**：`axi_mux`（每 master 端口
   一个）无按 ID 分桶的事务计数机制（BUG-0011 已核实：mux.md 全篇无对应段落，
   唯一相关 `MaxWTrans` 是 AW→W 前缀 FIFO 深度、语义不同）。故 M2-TL02 里同
   全 ID 同目标事务在 master 端口侧的在飞数**不受 per-ID ≤6 约束**，而是被上游
   demux 每桶上限（15，见 3）主导——送 8 全放行 ⇒ master 端口见 8 > 6。
   这直接**证伪** REV-005 为 M2-TL02 解锁的"每 master 端口×每前缀后 ID×每方向
   ≤ MaxSlvTrans、保守下侧、绝不假红"可观测上界监视器（该监视器确会假红）。
5. **结果**：master 端口延迟不敏感在飞计数超出文档/spec 承诺的 MaxMstTrans /
   MaxSlvTrans；功能面无损（scoreboard 路由/数据/完成全绿），仅数值上限未守。

## fix

**REV-007 裁决 = SPEC_ISSUE（改判 DUT_BUG，DUT_BUG 不予签核）**（rev 独立逐行
亲读 vendored RTL + 文档：`axi_demux_simple.sv` L69/L168/L322 + `axi_demux_id_counters`
L557/L615 + `delta_counter.sv` L54-56 + `cf_math_pkg.sv` L57-58 + `axi_xbar.sv` L141
+ `axi_xbar_unmuxed.sv` L175 + `axi_mux.sv`/mux.md L29；成本阶梯逐级排除 + "清空
一切之后 DUT 仍未被归咎"）：

- **不签 DUT_BUG**——DUT 未产生任何错误输出（同批 scoreboard 路由/数据/响应/完成/
  保序全绿、UVM_ERROR 0，AXI 不规定在飞上限，计数器未真回绕），且 `MaxTrans` 在 RTL
  中**只进 `idx_width` 定宽、从不进值比较器**，"full" 判据为 `&in_flight`（全一满量程）
  ——DUT 对 `MaxTrans` 语义持一个**由结构完全支撑的另一读法（计数器定宽参数）**。据
  `discipline.md` rule 1，不得因"RTL 封顶 15 故 15 即意图"、亦不得因"散文写 ≤MaxTrans
  故 MaxTrans 即硬契约"下断。
- **判 SPEC_ISSUE**——许可来源自身**三方矛盾**（demux.md L72 每桶"up to and including
  MaxTrans" / xbar.md L46-L47 每 slave 端口聚合 & 每 master 端口 per-ID / axi_pkg
  L489-494 每外接 master·slave 聚合），无一与 RTL 吻合；且 2 的幂取值下有效上限**低于**
  MaxTrans（MaxTrans=8⇒7），证明散文"上限"是不精确蒸馏、非硬契约。DUT 与 TB 各在不同
  读法下都站得住 ⇒ SPEC_ISSUE 教科书签名。
- **有效契约**：demux 每桶有效上限 = `2^idx_width(MaxMstTrans)−1 = 2^⌈log₂MaxMstTrans⌉−1`
  （基线 MaxMstTrans=10 ⇒ 15）；`MaxSlvTrans` 经 xbar.sv L141 连到 mux `MaxWTrans`（AW→W
  ID FIFO 深度，mux.md L29）、**非**每 ID 在飞上限，mux 无 per-ID 在飞计数机制——本条
  仿真证据**证伪** REV-005 解锁的"每 ID ≤ MaxSlvTrans 绝不假红"监视器。
- 三条替代解释全部排除：无 MaxTrans 合法性检查（`validate_params` L460-508）⇒ baseline
  MaxMstTrans=10 合法、非误配；无独立于该计数器在 10/6 处限流的上层背压；`overflow`
  为内部计数器最高位（`delta_counter` L54-56）、仅计数达 16 置位、被 `&in_flight`=15
  提前阻止、永不在计数=10 先触发。

**处置**：走 spec 修改记录 + 重 pin（**非** DUT 行为补丁——既判 SPEC_ISSUE，任何把封顶
改到 10 的本地 patch 都是把 TB 字面读法强加给 vendor IP，CLAUDE.md §6 在此加强、禁止）。
精修 spec §5.4.1/§5.4.2/§5.4.3/§7.4.5（+ §2.1 对应字段行）的 MaxMstTrans/MaxSlvTrans
"上限"语义至上述有效契约——**原文/新文/理由 + orch 应用范围见 REV-007 §5**。上游若提
issue 应为**文档澄清（doc-clarification）**、非逻辑 bug（要素见 REV-007 §6），实际登记
动作由 orch 决定、不在 DV/rev 执行范围。**spec 正文编辑 + sha256 重 pin + Change record
+ 状态转 SPEC_CHANGED + suspect DUT→SPEC 已由 orch 应用**（同 REV-005/006 先例，非 rev
落笔）：`doc/spec.md` §2.1 `MaxMstTrans`/`MaxSlvTrans` 字段行 + §5.4.1（有效上限
`2^⌈log₂MaxMstTrans⌉−1`，基线 15）/ §5.4.2（撤销"每 ID ≤ MaxSlvTrans"、收回 REV-005
M2-TL02 监视器）/ §5.4.3（拒收门锚有效上限、MaxSlvTrans 侧升级为"mux 无 per-ID 机制"）
/ §7.4.5（"上限最终被守"绑定有效上限公式），Change record #5，sha `bfe8542b`。详见
`doc/review/REV-007.md`。
