# BUG-0045 — spec §3.2 未载 `addr_decode_dync` 的 `end_addr == '0` 末端哨兵分支

## symptom

无仿真失败触发——这是一条静态阅读发现的 spec-completeness 缺口，不是某次
运行报的红。`vendor/common_cells/src/addr_decode_dync.sv:112` 的组合匹配
条件是 `(addr_i < end_addr) || (end_addr == '0)`，头注释 L60 明确写
"if `end_addr == '0` end of address space is assumed"——即该模块把
`end_addr=='0` 当作"本条 rule 的地址区间一直延伸到地址空间末端"的哨兵值，
是 RTL 自身文档化的受支持行为。`doc/spec.md` §3.2（L117-119）对地址匹配的
描述只有半开区间 `addr>=start && addr<end` 与 `start<=end` 两条，**未提**
这个哨兵分支。`tb/xbar_types_pkg.sv` 参考模型 `decode_mst_port`
（L336-358，命中判据在 L354）同样只实现了半开区间比较，未实现哨兵分支。
