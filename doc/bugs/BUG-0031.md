# BUG-0031 — stall_sva 用编译期地址表译码，运行时可变表对它不可见（误差双向）

## symptom

`tb/sva/axi_xbar_stall_sva.sv` 计算事务目标 master 端口时，地址表取的是
**编译期 localparam**（基线 V0），而 spec §3.4 规定地址表**运行时可变**、
M2-CFG01 场景确实在运行中换过表：

```systemverilog
// tb/sva/axi_xbar_stall_sva.sv:99-100
always_comb aw_hit = decode_mst_port(aw_addr, ADDR_MAP, 1'b0, '0, aw_tgt);
//                                             ^^^^^^^^ 编译期常量
```

`tb/seq_lib.sv:993-996` 的 `do_reconfig()` 把 `addr_map` 换成 V1（rule 0 的
`idx` 由 **0** 改为 **5**）并使能全部 default port。⇒ 重配之后，对命中
region0 的**译码命中**事务，`w_id_tgt` 记录的是 **mst0**，而实际目标是
**mst5**。

**误差方向是双向的**：目标记错既可能让 `w_reorder()` 的"异目标"条件**假
成立**（⇒ **假红**），也可能让它**假不成立**（⇒ 漏检）。这与 BUG-0023 /
0024 / 0025 记载的单向漏检**不同类**。

**今天为何没炸**：M2-CFG01 的激励每个 slave 端口至多一笔在飞，兄弟候选集
恒空，断言恒真空过。量化（REV-011 §5.4 实测 `m2_cfg01_reconfig_test_1.log`）：
`axi_xbar_stall_sva.sv` 的 **84 条 cover 行（14 cover × 6 实例）全部 0 match**
（各 83 attempts）——即本模块在该场景中**结构性空转、贡献零判决**；对照
`m2_or01_stall_test_1.log` 同名 cover 有非零命中，故非日志假象。该掩蔽事实
**只写在 `stall_sva.sv:93-98` 的代码注释里**，未进 `doc/bugs.md`——正是
CLAUDE.md §2 记载的 FB-7 / BUG-0007 形状（变通/限制只落注释），故本条按
`workflow/taxonomy/failure_taxonomy.md` 开篇的无条件登记原则补登。

## rca

1. `doc/design-prompt/sva_bind.md` §3「译码复用」段**明文要求**：该函数当前把
   地址表读作编译期 `localparam`（M1 假设），M2-CFG01 要求地址表运行时可变，
   函数签名须改为把地址表当**输入参数**传入，使 SVA 与 scoreboard 对同一个
   「运行时活值」表译码。
2. 函数签名**已按要求改**（`tb/xbar_types_pkg.sv:148` 已收 `amap` 形参）。
3. 但 `tb/sva/axi_xbar_stall_sva.sv:99-100` 的**调用点仍传编译期 `ADDR_MAP`**
   ——要求只落实了一半。
4. 根因在挂接层：`tb/sva_bind.sv:33-35` 例化 `axi_xbar_stall_sva` 时只接
   `slv_if[k]`，**结构上就拿不到** `cfg_if`；同文件 `:41-47` 的
   `axi_xbar_route_sva` 则接了 `cfg_if.addr_map` / `en_default_mst_port[r]` /
   `default_mst_port[r]`——现成的正确接法就在隔壁 7 行。
5. 净效果：重配后该模块整个判决建立在一张陈旧的地址表上，目标端口可记错，
   误差双向。

### 为什么不是"必须在 M2 内修完"

判据不是修复成本（本条确实只需几行，正确接法就在 `sva_bind.sv:41-47`），
而是：**M2 有没有任何一条证据/结论依赖本条所在的路径**。三条实测依据，均由
本评审人亲跑 grep 取得，不采信任何摘要：

1. **除 CFG01 外的场景根本用不到运行时表。** 全仓只有两处写
   `cfg_vif.addr_map`：`tb/tb_top.sv:59`（复位初始化为 V0）与
   `tb/seq_lib.sv:994`（CFG01 vseq 的 `do_reconfig()`）。⇒ 其余 M0/M1/M2 场景
   的编译期 `ADDR_MAP` **恒等于**活值表，本条在那些运行中不可能起作用。
2. **唯一用到陈旧表的那次运行里，本模块贡献了零判决。**
   `sim/out/m2_cfg01_reconfig_test_1.log` 中 `axi_xbar_stall_sva.sv` 的
   **84 条 cover 行（14 cover × 6 实例）全部 `0 match`**（各 83 attempts）。
   其中 line 360/362（兄弟异目标呈现）与 368/370（兄弟同目标呈现）为 0，
   意味着**全程没有两个同桶完整 ID 同时处于 open**——而
   `w_reorder()`/`r_reorder()` 只枚举 `cand != completing_id` 的兄弟 ⇒ 每次
   完成时候选集必为空 ⇒ 两条 assert（`:345`/`:351`）**结构性空转**。
   对照组：`sim/out/m2_or01_stall_test_1.log` 同名 cover 有非零命中，
   故"全 0"不是日志或 `-assert verbose` 的假象。该运行
   `UVM_ERROR: 0`、`2143 assertions, 870 with attempts, 0 with failures`。
3. **M2-CFG01 的判决锚点本就不含本模块。** `doc/testplan.md` M2-CFG01 行原文
   把判据落在 scoreboard 参考模型（SPEC-3.1/3.2/3.3，按每笔事务 `accept_time`
   生效的表版本译码）+ **独立 SVA C3.1**（`axi_xbar_route_sva`，经
   `tb/sva_bind.sv:41-47` 拿到活值 `addr_map`/`en_default`/`default_mst`），
   **未引用 C3.2**。scoreboard 侧该场景 `route: match=30 mismatch=0`。

另：本条的**假红**方向若真发生，会让运行变红而不是变绿；M2 无一运行失败 ⇒
两个误差方向上都不存在被本条污染的 PASS。

⇒ 判"不阻塞 M2"**不是**为了让 `signoff-check` 条件 3 变绿而放宽门禁
（discipline rule 2 的红线），而是上面三条各自独立、可被任何人用同样的 grep
推翻的事实。若其中任何一条被证伪（例如有人指出某 M2 场景也改表、或 cfg01 的
某条 cover 其实非零），本裁决即失效，本条须改判 M2 内修。
