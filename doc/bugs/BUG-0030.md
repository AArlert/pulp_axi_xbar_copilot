# BUG-0030 — xdebug NPI 初始化对四项环境变量敏感，`LD_LIBRARY_PATH` 尾部空元素即失败

## symptom

补上 FSDB（BUG-0020 修复）之后，`xdebug session.open` 仍然可能失败：
engine lifecycle 显示 `has_fsdb:true` 但 `npi_init.failed`。

逐项对照实测，NPI 初始化对**四项**环境同时敏感：

| 环境项 | 要求 | 不满足时 |
|---|---|---|
| `VERDI_HOME` | 必须有值 | `npi_init.failed` |
| `VCS_HOME` | 必须有值 | `npi_init.failed` |
| `LM_LICENSE_FILE` | 必须有值 | `npi_init.failed` |
| `LD_LIBRARY_PATH` | 必须**恰为** `$VERDI_HOME/share/PLI/VCS/LINUX64` | 尾部空元素（`…LINUX64:`）即失败 |

最后一项是陷阱：`LD_LIBRARY_PATH := $(VERDI_HOME)/share/PLI/VCS/LINUX64:$(LD_LIBRARY_PATH)`
在父变量为空时正好展开成带尾冒号的形态——**这正是 `scripts/make/vcs-2018.mk`
第 36 行的写法**在干净环境下的展开结果。

## first_anomaly

signal: xdebug engine 的 `npi_init` 阶段（`has_fsdb:true` 却仍失败）
time: n/a
how_found: DV 卡（BUG-0020/0022 修复）落地 FSDB dump 后验证 `xdebug session.open`，
发现补上波形并不足够，遂逐项二分环境变量定位。

## taxonomy

TOOL_ENV

## rca

1. xdebug engine 是链接 Verdi C API（`libNPI.so` / `libnpiL1.so` / `libvfs.so`）
   的二进制，其 NPI 初始化会读取上述四项环境。
2. 前三项缺失导致 NPI 无法定位库/许可，失败可理解。
3. 第四项的敏感性超出常规预期：动态链接器对 `LD_LIBRARY_PATH` 中的**空元素**
   解释为「当前目录」，而 NPI 初始化在该形态下拒绝继续。
4. `make` 的 `:=` 拼接惯用法在父变量为空时天然产生尾部空元素 ⇒ 从 Makefile
   继承环境去调 xdebug 时**默认就踩中**。

**与 BUG-0020 的关系：并列，不重合。** BUG-0020 的 rca 断言「根因是项目侧
不产波形、与 Verdi 版本无关」——该断言成立但**不完整**：补上 FSDB 后仍有本条
这堵墙。两条叠着，先撞哪条取决于先补哪个。

## fix

不适用（这是环境使用约束，不是可修的缺陷）。**本条是使用说明的登记**，目的是
让后续每个需要 xdebug 的卡不再重新二分定位。

已落地的缓解：绕法写进 `sim/Makefile` `verdi:` 目标上方的注释与
`doc/bugs/BUG-0020.md` 的 `## rerun` 段——用 `env -i` 起一个干净环境并**显式**
给全四项，避免继承带尾冒号的 `LD_LIBRARY_PATH`。

## rerun

按 `doc/bugs/BUG-0020.md` `## rerun` 的 `env -i` 命令开 session，通过判据 =
响应头 `@xdebug.session.open.v1` 且 lifecycle 含 `"phase":"ensure_session.success"`。
实测已通过，并用 `scope.list path=tb_top` 复核 session 可用（22059 信号，
含 `tb_top.i_xbar_dut.*`）。

## min_repro

```
# 失败形态（继承带尾冒号的 LD_LIBRARY_PATH）
export LD_LIBRARY_PATH="$VERDI_HOME/share/PLI/VCS/LINUX64:"
$XVERIF_ROOT/tools/xdebug <request.json>   # → npi_init.failed
```

（对照：`LD_LIBRARY_PATH` 去掉尾冒号、其余三项齐备 ⇒ `ensure_session.success`。
engine lifecycle 在 `~/.xdebug/engine/sessions/<id>/logs/lifecycle.ndjson`。）
