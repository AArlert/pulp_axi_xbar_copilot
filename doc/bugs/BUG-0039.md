# BUG-0039 — M4 six-type coverage convergence on `axi_atop_filter` FSM directly conflicts with the spec §4 clause 7 BUG-0032 environment constraint

## symptom
`axi_atop_filter`'s W/R FSM sits at 7.14% in the M4 coverage baseline
(`doc/evidence/v0.4.0/M4-coverage-baseline.md` §0①/§2/§4) regardless of
scenario count. Every state/arc beyond `W_FEEDTHROUGH`/`R_FEEDTHROUGH`
requires an AW with `atop != 0` to reach an `axi_err_slv` — i.e. an ATOP
routed to a decode-miss address — which spec §4 clause 7's environment
constraint (BUG-0032 ruling, REV-012/REV-013 final) forbids for all M3
scenarios (and, until this ruling, left silent for M4).

## arbitration
Arbitrated by **REV-017** (`doc/review/REV-017.md`, 2026-07-30) — this is
the BUG-0032 M4 reopening that REV-013 reserved and spec Change record row
#7 named. Full reasoning, per-item verdicts and the verbatim spec text are
in REV-017; summary:

- **Item 1** — all three facts asserted in this bug row (instantiation
  closure, FSM necessary condition, encoding diversity already satisfied)
  independently re-verified true by rev, reading vendor sources directly
  (not trusting any prior summary).
- **Item 2** — the option of reopening to *define* an err_slv×ATOP response
  shape and thereby permit the forbidden stimulus (REV-016 §6.2 options
  a/c) is **rejected**: all five permitted sources remain silent on that
  response shape (REV-012's falsifiable rationale unrebutted), so
  permitting the stimulus would force DV to write checker expectations
  sourced from the RTL under test — a direct violation of CLAUDE.md
  invariant #4.
- **Item 3** — disposition (option b): §4 clause 7's environment constraint
  is **extended from M3 to M3+M4** (same purpose, same silent-source
  reality in both milestones); the `axi_atop_filter` FSM states/arcs
  reachable only via the forbidden stimulus are recorded as
  **environment-constraint-unreachable** and go through §0 item 4's
  existing "has bins but <90% → rev-signed written waiver" branch (NOT the
  "no bins ⇒ N/A" tri-state rule — this FSM has bins, 7.14%). The BUG-0032
  guard is **extended, not lifted**.
- **Item 4** — REV-013 reopening requirement (b) (an M4 config-matrix
  testplan row must carry the extended constraint) is **not yet
  satisfied** — `doc/testplan.md` only carries the constraint in the
  M3-DE01 row, scoped to M3. This is why the overall verdict is
  **CONDITIONAL PASS**, not PASS.

**Overall verdict: CONDITIONAL PASS.** Conditions (must all close before M4
signoff):
1. orch applies REV-017's verbatim §4 clause 7 text + Change record + re-pin
   — **done** (spec Change record row #10, `doc/spec.sha256` re-pinned
   2026-07-30).
2. orch dispatches arch/dv to carry the extended constraint into an M4
   config-matrix testplan row (REV-013 requirement (b)) — **outstanding**.
3. At M4 signoff, rev issues the `axi_atop_filter` FSM written waiver and
   runs the BUG-0032 guard's mechanical spot-check (decode-miss `atop ≡ '0`
   holds, count 0) — **outstanding**, tracked at signoff time.

The underlying SPEC_ISSUE (err_slv×ATOP response shape has no permitted
source) is **not resolved** by this ruling — it persists as BUG-0032's
upstream-confirmation item. If a permitted source is ever found, BUG-0032
can be reopened again per REV-012's falsifiable rationale, the stimulus
permitted, and this waiver retired.
