# BUG-0044 — spec §6 defines ATOP response obligations only for

> **注（0.5.4 重置）**：文中出现的 `doc/evidence|review|design-prompt|archive`、`workflow/`、`doc/guards.md`、`doc/fw-feedback.md` 等路径为重置前产物，工作树已移除；查阅用 `git show v0.5.3-pre-reset:<path>`。
atomic-load; atomicstore/atomicswap/atomiccompare are undefined

## symptom

`doc/spec.md` §6（ATOP 支持）全节 5 条 clause，只有 clause 3（SPEC-6.3）规定
**atomic-load**（`aw.atop` 要求读响应的原子操作）的应答义务："B 与 R 两通道都
返回响应"。`atomicstore`（应仅 B）、`atomicswap`/`atomiccompare`（应 B+R，且
`len`/data 有约束）三个 AXI5 ATOP 子类型的响应通道数/响应码/长度约束，**全节
未列一字**。DUT（`ATOPs=1`）按 AXI5 实际支持这些子类型（`axi_pkg.sv` 的
`ATOP_ATOMICSTORE`/`ATOP_ATOMICSWAP`/`ATOP_ATOMICCOMPARE` 等编码均存在），但
spec 相对 DUT 行为存在真实缺口——若要给这些子类型写 checker，scoreboard 无
spec 可推导的期望值。

## fix

commit: none — 本条是 spec 文本缺口的登记，非代码/spec 修复。**containment
（M5 决策点 2 已落地）**：`atop` 的 `rand` 约束硬性限定在
`{'0} ∪ {合法 atomic-load 编码}`（`doc/design-prompt/verification_maturity.md`
C2.5），构造性挡住"需要 store/swap/compare 应答义务作 oracle"的组合——有界
子集完全由现有 SPEC-6.3 支持，M5 不需要现在放开、不需要现在仲裁 spec 补全。

## orch investigation note（2026-08-03）

非仲裁，仅为 M5 到期复访预置事实，处置维持 ACCEPTED@M5、containment 不变：

- **上游是否已定义三类子类型的应答义务？分层**——spec 唯一许可来源
  （`vendor/axi/doc/axi_xbar.md`/`axi_demux.md`/`axi_mux.md`）通篇只讲清楚
  atomic-load 要 B+R（`axi_demux.md` L81），对 atomicstore/atomicswap/
  atomiccompare 三类只字未提。`vendor/axi/src/axi_pkg.sv`（387-415 行注释）
  倒是写清楚了：atomicstore "a single response is given without data"（仅
  B）、atomicswap/atomiccompare 都要把原值读回（隐含 B+R）——但这段落在
  CLAUDE.md §6 把 `axi_pkg.sv` 的许可范围锁定在 `xbar_cfg_t`/
  `xbar_latency_e`/`xbar_rule_*_t` 这几个类型定义，不含这段 ATOP 语义注释，
  故此处"上游有定义"目前只能算 RTL 来源（若日后要蒸馏进 spec，须按
  CLAUDE.md 惯例标注"来源：RTL——上游文档未载"）。
- **DUT 是否会走到这些行为？会，且是通用机制，非 atomic-load 专判**——
  `vendor/axi/src/axi_demux_simple.sv:162/185` 的 AR 通道 ID 注入判据只看
  `aw.atop[axi_pkg::ATOP_R_RESP]`（第 5 位，`axi_pkg.sv:447`）这一个 bit；
  该 bit 对 `ATOP_ATOMICLOAD`（`2'b10`）、`ATOP_ATOMICSWAP`
  （`6'b110000`）、`ATOP_ATOMICCMP`（`6'b110001`）全为 1，仅
  `ATOP_ATOMICSTORE`（`2'b01`）为 0——RTL 从设计上就是三类统一处理，不是
  只为 atomic-load 特判的窄路径。
- **验证环境是否会驱动到这些行为？目前不会**——M5 决策点 2（已落地）把
  `atop` 的 `rand` 约束硬限定在 `{'0} ∪ 合法 atomic-load 编码`，`store`/
  `swap`/`compare` 三类主动被排除在随机空间外，TB 现状压根不构造这三类
  事务。
- **是否补上：暂不展开**——补齐需 spec §6 新增条款 + 定向场景 + refmodel
  新分支三件套同批落地（同 BUG-0045/0046 的"不可证伪 decoration"红线，
  `workflow/review.md` Q2），这是真正的 M5/M6 新验证工作量，不是本卡能
  顺手做的记账。用户已确认此展开留给 M5 构造随机地址表/新场景阶段一并
  处理，本条继续 ACCEPTED@M5，containment 不变。
