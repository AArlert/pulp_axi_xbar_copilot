# BUG-0044 — spec §6 defines ATOP response obligations only for
atomic-load; atomicstore/atomicswap/atomiccompare are undefined

## symptom

`doc/spec.md` §6（ATOP 支持）全节 5 条 clause，只有 clause 3（SPEC-6.3）规定
**atomic-load**（`aw.atop` 要求读响应的原子操作）的应答义务："B 与 R 两通道都
返回响应"。`atomicstore`（应仅 B）、`atomicswap`/`atomiccompare`（应 B+R，且
`len`/data 有约束）三个 AXI5 ATOP 子类型的响应通道数/响应码/长度约束，**全节
未列一字**。DUT（`ATOPs=1`）按 AXI5 实际支持这些子类型（`axi_pkg.sv` 的
`ATOP_ATOMICSTORE`/`ATOP_ATOMICSWAP`/`ATOP_ATOMICCOMPARE` 等编码均存在），但
spec 相对 DUT 行为存在真实缺口——若要给这些子类型写 checker，scoreboard 无
spec 可推导的期望值。

## fix

commit: none — 本条是 spec 文本缺口的登记，非代码/spec 修复。**containment
（M5 决策点 2 已落地）**：`atop` 的 `rand` 约束硬性限定在
`{'0} ∪ {合法 atomic-load 编码}`（`doc/design-prompt/verification_maturity.md`
C2.5），构造性挡住"需要 store/swap/compare 应答义务作 oracle"的组合——有界
子集完全由现有 SPEC-6.3 支持，M5 不需要现在放开、不需要现在仲裁 spec 补全。
