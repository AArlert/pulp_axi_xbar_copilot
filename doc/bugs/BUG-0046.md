# BUG-0046 — spec §3.2 条 2 `start_addr<=end_addr` 与 RTL 严格 `<` 约束松紧不符

## symptom

无仿真失败触发——静态阅读发现的 doc-vs-RTL 约束松紧不符，不是某次运行报
的红。`doc/spec.md` §3.2 条 2（L119）写"约束：`start_addr <= end_addr`"
（非严格，允许 `start==end` 的空区间）。`vendor/common_cells/src/
addr_decode_dync.sv` 头注释 L26 写"The start address has to be **less
than** the end address"，其 `check_start` ASSUME（L148，
`start_addr < end_addr || end_addr=='0`）用**严格** `<`——对
`start==end`（且 `end≠0`）的 rule，RTL 会触发断言 fatal，而 spec 的
`<=` 却判这类配置合法。

## first_anomaly

signal: `addr_decode_dync.sv:148` `check_start` ASSUME 的严格 `<`
        vs `doc/spec.md` §3.2 L119 的非严格 `<=`
time: n/a（非仿真信号异常——静态阅读比对）
how_found: REV-021（BUG-0045 仲裁卡）逐行独立核验 `addr_decode_dync.sv`
全文以核实哨兵分支相关问题时，顺带读到头注释 L26 与 `check_start` L148
的严格边界，与 `doc/spec.md` §3.2 全文对照，确认约束松紧不符。与
BUG-0045（哨兵沉默）同源于同一次逐行核验，但内容/触发条件/解锁条件均
独立，不合并登记。

## taxonomy

SPEC_ISSUE（候选——doc-vs-RTL 约束松紧不符，spec 允许 RTL 会 fatal 的
配置；**当前无** DUT-vs-TB 期望值分歧，因为现有三张地址表
（`ADDR_MAP`/`ADDR_MAP_V1`/`ADDR_MAP_OV1`）均 `start<end` 严格成立，
无 `start==end` 构造，缺口潜伏无碍）

## fix

无 RTL/TB/spec 改动（现阶段）——本条尚未经 rev/arch 正式仲裁裁决（REV-021
仅在仲裁 BUG-0045 时顺带指出，声明"不越权代开行、不代改 spec"）。待决
路径（供后续裁决卡参考，非本条自行拍板）：

1. 若判定这一约束松紧不符值得现在收紧，走 spec 补/改条款流程——arch
   核实上游许可来源对空区间 rule 的态度，起草 §3.2 条 2 措辞订正（改为
   严格 `<`，与 RTL `check_start` 对齐）+ rev 仲裁通过 + 重 pin；
2. 若判定当前及可预见的测试矩阵都不构造 `start==end` 的地址表，可将其
   记为 residual risk / 显式声明当前 testplan 不覆盖此分支，附理由，
   不必现在改 spec。
