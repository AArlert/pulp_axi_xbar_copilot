# BUG-0046 — 上游内部 doc-vs-RTL 约束松紧矛盾：`axi_xbar.md`（`<=`）vs `addr_decode_dync check_start`（`<`）

> **REV-023 订正提示（读本页前先看）**：本页最初登记时把缺口框成"spec
> 蒸馏遗漏 / spec 允许 RTL 会炸"，经 REV-023 独立补核许可来源
> `vendor/axi/doc/axi_xbar.md` 后**推翻**——spec §3.2 条 2 的 `<=` 其实是
> 该权威文档的忠实蒸馏，spec 侧无误。真实矛盾是**上游文档与 RTL 内部**
> 的松紧不一致。以下 `## symptom`/`## taxonomy`/`## rca` 段已按订正后的
> 框架重写；`## arbitration` 段是完整裁决记录。

## symptom

无仿真失败触发——静态阅读发现的**上游内部** doc-vs-RTL 约束松紧不符，
不是某次运行报的红。`vendor/axi/doc/axi_xbar.md`（L26，spec 许可来源）
写"The start address must be less than **or equal to** the end
address"——**非严格** `<=`。`doc/spec.md` §3.2 条 2（L119）"约束：
`start_addr <= end_addr`"是这条权威文档的忠实蒸馏。而
`vendor/common_cells/src/addr_decode_dync.sv` 头注释 L26 写"The start
address has to be **less than** the end address"，其 `check_start`
ASSUME（L148，`start_addr < end_addr || end_addr=='0`）用**严格** `<`
——对 `start==end`（且 `end≠0`）的 rule，RTL 会触发断言报告。矛盾在
**上游文档与 RTL 之间**，spec 站文档一侧、无误。（另：`addr_decode_dync.sv`
自身头注释 L26"less than"与 L36-38"higher than"表述亦互相矛盾——三方
措辞不齐，见 `## arbitration`。）

## fix

无 RTL/TB/spec 改动（现阶段）——**REV-023 终判：taxonomy 维持 SPEC_ISSUE，

## arbitration

**REV-023 补核许可来源 `vendor/axi/doc/axi_xbar.md`（L26"must be less
than or equal to"）后推翻本页原框架**——spec §3.2 条 2 的 `<=` 是这条
权威文档的忠实、正确蒸馏，**spec 侧无误**；真实矛盾在上游文档与
common_cells `addr_decode_dync.sv` 的 `check_start` 断言（严格 `<`）
之间。

**处置 = ACCEPTED@M5**（与姐妹条 BUG-0045 到期锚点对齐，二者同源于同
一次核验、M5 一并复访避免两次独立 re-pin）。**独立否决"现在收紧 spec 为
`<`"**——该路径的前提"这是一处文字性错误、成本极低"经核实为**假**：
spec 的 `<=` 本身没错，收紧只会让 spec 主动偏离权威文档、转而对齐 RTL 的
更严约束，这正是 spec-from-RTL 红线禁止的方向（期望/约束只从许可文档
来源派生，不从被测 RTL 抄）。排除 WONTFIX（应 M5 复访，"WONTFIX may not
mean 'later'"）。

**可证伪解锁条件**：一旦任何场景/配置（含 M5 地址表随机化）构造
`start_addr==end_addr`（`end≠0`）的 rule，本 ACCEPTED 立即作废。届时
**resolution 不是**悄悄把 spec 改成 `<`、**不是** DV 现场发明该构造下
的期望值，**而是**二选一：(i) 给 DV 地址表生成器加书面环境约束
`start<end`（尊重 RTL 更严边界，环境约束模式同 BUG-0002/0003/0032）；
(ii) 在 spec §3.2 补一条 doc-vs-RTL 不一致的说明注记（保留 `<=` 为权威，
同时告知 RTL 更严）。**M5 到期动作**：M5 签核 rev 二选一自觉再裁决——
若 M5 引入地址表随机化则走上述两件套；若仍不触及则出具具体论证后转
WONTFIX 或再 ACCEPTED（不得自动延期）。

**顺带发现（并入本条上游 issue 线索，不单开行）**：`addr_decode_dync.sv`
头注释自身内部亦不一致——L26"less than"（严格 `<`）vs L36-38"higher
than"（严格 `>`，暗示 `start==end` 合法），与 L148 代码（严格 `<`）
及上游 `axi_xbar.md` L26（`<=`）三方措辞不齐。建议 orch 评估是否作为
上游 doc 一致性 issue 的一部分上报，不在本仓另开 bug 行。

详见 `doc/review/REV-023.md`。
