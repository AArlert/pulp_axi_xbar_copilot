# BUG-0078 — fall-through cover 结构性恒 0（M5-RN03 及 M4-FT01 同源），"显著高于"声称与证据矛盾

## symptom

testplan M5-RN03 行 must-reach 声明"fall-through 分支 cover 命中次数须显著
高于 M4-FT01 定向场景"，该行已 ✅。但证据 `doc/evidence/v0.5.8/M5-RN03.log`
显示 `cg_fallthrough samples=0`；比较基准 M4-FT01 的证据
（`git show v0.5.3-pre-reset:doc/evidence/v0.4.6/M4-FT01.log`）同样
`samples=0`——"0 显著高于 0"字面不成立。M4-FT01 行自身的非空转 cover 声称
（"证明该分支被触达"）历史上也从未兑现。

## first_anomaly

signal: `cg_fallthrough samples=0 inst_cov=0.00%`（两份证据一致）
time: n/a（证据静态复核）
how_found: M5 收口审计的证据链反稀释核查（0.5.15）。

## repro

修复前任意 cfgE 运行。根因是驱动器结构：`slvport_agent.sv` 所有常规写呈现
路径（`drive_write`、`drive_burst` 默认支路、`drive_burst_wopen` 的单线程
交替）都是 AW 握手完成、`aw_valid` 拉低之后才升 `w_valid`——端口边界上
`aw_valid&&aw_ready&&w_valid&&w_ready` 四信号同拍在这些路径下**结构性不可能**；
`drive_write_ft`（M4-FT01 探针）虽同拍呈现自身 AW+首拍 W，但 cfgE 的
`CUT_ALL_AX` AW spill 使 `aw_ready`（spill 空即高）先于 `w_ready`（须路由
决策después）到来，AW 握手先完成、四信号交叠仍不可达。唯一能产生交叠的是
M4-EB01 的 AW/W 解耦 fork（两线程并行），而 M5-RN03 未使用它。

## taxonomy

TB_BUG——非空转 cover 所锚的外部观测角落在既有激励形态下结构性不可达，
场景（RN03 与其基准 FT01）却以该 cover 为 must-reach/非空转声称翻绿。

## fix

1. `tb/axi_txn.sv`：`axi_burst_item` 新增 `aw_w_decoupled` 旋钮（纯呈现
   时序，不动 b_ready）。
2. `tb/slvport_agent.sv`：`drive_burst` 的 EB01 解耦 fork 支路条件放宽为
   `(b_backpressure || aw_w_decoupled) && is_w`——复用已验证原语，无死锁
   （W 线程恒排水、AW 线程位置恒 ≥ W 线程所需）。
3. `tb/seq_lib.sv`：`xbar_soak_cfge_seq/vseq`（写 round 置 `aw_w_decoupled`），
   `m5_rn03_soak_test` 改用之。

## reverify

修复后 `make run TEST=m5_rn03_soak_test SEED=1`：`cg_fallthrough samples=139
inst_cov=100.00%`（对比基准 0——"显著高于"真实成立），UVM_ERROR/FATAL 0，
零 mismatch；多种子回归全绿。M4-FT01 行历史证据不回溯改写（M4 已封存，
其判决门=功能等价性不受影响；本缺陷记录即其非空转声称未兑现的正式登记）。
