# BUG-0037 — COV=1 regress silently merges structurally-different DUT designs into one cov.vdb

## symptom
Running `make regress COV=1` (the mechanical path prescribed by
`scripts/make/vcs-2018.mk`/`sim/Makefile`) followed by `make cov` produces a
`urg` report peppered with hundreds of `Warning-[UCAPI-INSTANCEMISMATCH]`
("Coverage data of this instance won't be merged") and
`Warning-[CMR-VCINF]` ("Instance ... is not found in base design") lines.
Two independent contamination sources, both routed through the *same*
default `-cm_dir out/cov.vdb`:

1. **M0 vs M1+**: `TEST=upstream_sanity` (`TOP=tb_axi_xbar`, flist
   `tb_upstream.f`) and every M1+ UVM test (`TOP=tb_top`, flist `tb.f`) both
   fall through to the *default* `OUT=out`, hence the same
   `-cm_dir out/cov.vdb`, even though they are two structurally unrelated
   designs (different top module, different DUT wrapper). Measured: 2971
   `CMR-VCINF` warning lines when `upstream_sanity` and the 17 M1-M3
   baseline-topology tests share one db.
2. **cfgA-D vs baseline**: `sim/Makefile`'s per-config block
   (`ifneq ($(filter m3_cf01_%,$(TEST)),) ... override OUT := $(OUT)/cfgA`)
   isolates the *build product* (`simv`/`daidir`) into `out/cfgA` as
   documented, but **not** the coverage database: `CM` is computed by
   `scripts/make/vcs-2018.mk` with `:=` (immediate expansion) at include
   time, using whatever `OUT` held *then* (the default `out`) —
   `CM := -cm ... -cm_dir $(OUT)/cov.vdb`. The later `override OUT :=
   $(OUT)/cfgA` in `sim/Makefile` cannot retroactively change the
   already-expanded `CM` string. Result: cfgA/B/C/D (four different
   `xbar_cfg_t` elaborations: 1x8/6x1/4x4-UniqueIds/4x4-sparse) all still
   write coverage into the shared `out/cov.vdb`, alongside the 6x8
   baseline. Measured: 825 `UCAPI-INSTANCEMISMATCH` warning lines in the
   as-designed `make regress COV=1` run (22/22 functional PASS, unaffected
   — this is a coverage-database issue only, not a scoreboard issue).

## rca
```
observed:   urg merge warnings when COV=1 regress covers >1 design elaboration
anomaly:    -cm_dir stays "out/cov.vdb" for every TEST regardless of the
            per-config `override OUT` sim/Makefile applies afterward
chain:      CM defined with `:=` in vcs-2018.mk at include time (OUT=out
            default) → sim/Makefile's `override OUT` for m3_cf0X_%/for
            upstream_sanity's shared default OUT executes too late to
            affect the already-expanded CM string → every COV=1 `make run`
            (any TEST) writes into the one shared out/cov.vdb → urg merge
            across incompatible top-level designs/parameterizations →
            per-instance structural mismatch → VCS drops (does not
            corrupt) the losing side's data for that instance, but emits
            warnings and silently loses whatever incremental coverage that
            test would have contributed to structurally-matching instances
class:      TOOL_ENV (build-script variable-expansion-order defect;
            VCS's own merge behavior is a safety net, not the bug)
guard:      re-running `make regress COV=1` and grepping the `make cov`
            output for `mismatch` is the first thing that goes red again if
            reintroduced
```

## fix
commit: none — DV role may not edit `sim/Makefile` /
`scripts/make/vcs-2018.mk` (CLAUDE.md exclusion zone). Left OPEN for
whichever role owns build scripts.
what (not yet applied — suggestion for the fixer): make `CM` sensitive to
the config-specific `OUT` at the point of use inside `sim/Makefile` (e.g.
recompute `-cm_dir $(OUT)/cov.vdb` after the `override OUT` blocks, or add
a `COV_DIR ?= $(OUT)` indirection resolved at rule-expansion time rather
than at include time), and give `upstream_sanity` (M0) its own default
`-cm_dir` distinct from `tb_top`'s.

## rerun
Not applicable yet (OPEN, not fixed). This card's own measurement worked
around it **without editing any tracked file**, purely via `make`'s
command-line variable precedence (a normal, sanctioned override — not a
script edit):
- Baseline six-type numbers: `make clean` then `make run TEST=<t> SEED=1
  COV=1` individually for the 17 M1-M3 baseline-topology tests (excludes
  `upstream_sanity` and `m3_cf01..04`), then `make cov` → clean
  `out/urgReport`, 0 mismatch warnings.
- M0 alone: `make clean` then `make run TEST=upstream_sanity SEED=1 COV=1`
  then `make cov` → clean, 0 mismatch warnings.
- Each config point: `make run TEST=m3_cf0X_... SEED=1 COV=1
  CM="-cm line+cond+fsm+tgl+branch+assert -cm_dir out/cfgX/cov.vdb"` (CM
  has no `override` in the Makefile, so a command-line assignment wins)
  then `make cov OUT=out/cfgX` → 4 clean, isolated reports, 0 mismatch
  warnings each.
See `doc/evidence/v0.4.0/M4-coverage-baseline.md` for the full numbers this
produced.
