# BUG-0037 — COV=1 regress silently merges structurally-different DUT designs into one cov.vdb

## symptom
Running `make regress COV=1` (the mechanical path prescribed by
`scripts/make/vcs-2018.mk`/`sim/Makefile`) followed by `make cov` produces a
`urg` report peppered with hundreds of `Warning-[UCAPI-INSTANCEMISMATCH]`
("Coverage data of this instance won't be merged") and
`Warning-[CMR-VCINF]` ("Instance ... is not found in base design") lines.
Two independent contamination sources, both routed through the *same*
default `-cm_dir out/cov.vdb`:

1. **M0 vs M1+**: `TEST=upstream_sanity` (`TOP=tb_axi_xbar`, flist
   `tb_upstream.f`) and every M1+ UVM test (`TOP=tb_top`, flist `tb.f`) both
   fall through to the *default* `OUT=out`, hence the same
   `-cm_dir out/cov.vdb`, even though they are two structurally unrelated
   designs (different top module, different DUT wrapper). Measured: 2971
   `CMR-VCINF` warning lines when `upstream_sanity` and the 17 M1-M3
   baseline-topology tests share one db.
2. **cfgA-D vs baseline**: `sim/Makefile`'s per-config block
   (`ifneq ($(filter m3_cf01_%,$(TEST)),) ... override OUT := $(OUT)/cfgA`)
   isolates the *build product* (`simv`/`daidir`) into `out/cfgA` as
   documented, but **not** the coverage database: `CM` is computed by
   `scripts/make/vcs-2018.mk` with `:=` (immediate expansion) at include
   time, using whatever `OUT` held *then* (the default `out`) —
   `CM := -cm ... -cm_dir $(OUT)/cov.vdb`. The later `override OUT :=
   $(OUT)/cfgA` in `sim/Makefile` cannot retroactively change the
   already-expanded `CM` string. Result: cfgA/B/C/D (four different
   `xbar_cfg_t` elaborations: 1x8/6x1/4x4-UniqueIds/4x4-sparse) all still
   write coverage into the shared `out/cov.vdb`, alongside the 6x8
   baseline. Measured: 825 `UCAPI-INSTANCEMISMATCH` warning lines in the
   as-designed `make regress COV=1` run (22/22 functional PASS, unaffected
   — this is a coverage-database issue only, not a scoreboard issue).

## fix
commit: 13cdeda (this card is fixer, not closer; per project precedent for
non-scenario TOOL_ENV/build-script fixes — see BUG-0014/0019/0022 — orch
performed the independent re-verification and mechanical closure itself
via `make evidence BUG=BUG-0037 CMD=... EXPECT=...`, satisfying CLAUDE.md
invariant #3 closer≠fixer without a second dispatched DV instance).
what: two independent, minimal edits, both traced to the two mechanisms in
`## rca`.

1. **`scripts/make/vcs-2018.mk`** — introduced a `COV_DIR` indirection
   (`COV_DIR = $(OUT)/cov.vdb`, default) between `OUT` and the `-cm_dir`
   flag, and changed `CM`'s own binding from `:=` (immediate expansion, the
   root cause) to `=` (recursive/lazy expansion): `CM = -cm
   line+cond+fsm+tgl+branch+assert -cm_dir $(COV_DIR)`. Because
   `include`-d makefile text is fully parsed (all of the including
   `sim/Makefile`'s top-level `override OUT`/`COV_DIR` assignments
   included) before any target's recipe runs, a *recursive* CM/COV_DIR now
   resolves `$(OUT)` at `compile:`/`run:` recipe-execution time — i.e.
   after `sim/Makefile`'s per-config `override OUT` (or per-TEST
   `COV_DIR`) has already taken effect — instead of at `include` time with
   whatever `OUT` held then (the bug). This alone fixes mechanism (2) in
   `## rca` (cfgA-D): their existing `override OUT := $(OUT)/cfgX` now
   transparently carries through to `COV_DIR`'s default formula, with zero
   change needed to the cfg branches themselves, and zero need for the
   manual `CM=` command-line override the `## rerun` workaround previously
   required.
2. **`sim/Makefile`** — added one line inside the existing
   `ifeq ($(TEST),upstream_sanity)` branch: `COV_DIR :=
   $(OUT)/m0/cov.vdb`. This fixes mechanism (1) in `## rca` (M0 vs UVM
   baseline): M0 (`TOP=tb_axi_xbar`) now gets its own coverage database,
   isolated from the 17-scenario baseline UVM merge, *without* touching
   `OUT` itself — deliberately, so that `make clean`'s scope (bare `make
   clean` relies on `TEST`'s default value being `upstream_sanity`, and
   must still wipe the *whole* `$(OUT)` tree, not just an `m0`
   subdirectory) and M0's build-product location (`out/simv`, unchanged,
   guard BUG-0014/0019/0020/0022) are both unaffected. Also added
   `$(dir $(COV_DIR))` to `compile:`'s `mkdir -p` (VCS's `-cm_dir` does not
   reliably create a not-yet-existing *nested* directory like `out/m0/`
   the way it tolerates a flat one already covered by the existing
   `mkdir -p $(OUT)`), and changed the `cov:` target's hardcoded
   `-dir $(OUT)/cov.vdb` to `-dir $(COV_DIR)` so a query for a given
   `TEST`/`OUT` resolves to the exact same database `make run` wrote for
   that domain.

Both edits are annotated inline with `见 doc/fw-feedback.md FB-30`
(pinned-file edit, per CLAUDE.md §5).

Design choices explicitly rejected: (a) duplicating the six-type `-cm`
flag list into a second, `sim/Makefile`-local `CM` override for the M0
branch — rejected as DRY-violating duplication of the yardstick already
owned by `vcs-2018.mk`; the `COV_DIR` indirection avoids it. (b) giving M0
its own `override OUT` (mirroring cfgA-D exactly) — rejected because
`TEST`'s pre-existing default value (`upstream_sanity`) would then make a
*bare* `make clean` (no `TEST=`, as `regress.py` calls it) silently narrow
to only `$(OUT)/m0`, defeating the "avoid stale incremental build
products" guarantee `scripts/regress.py`'s clean-before-regress step
relies on for every other test in the same regression.

One usage caveat this design does **not** eliminate (not a new bug, just a
documented sharp edge): because `TEST ?= upstream_sanity` is `sim/
Makefile`'s pre-existing default, a **bare** `make cov` (no `TEST=` at
all) always resolves to the M0 domain (`out/m0/cov.vdb`), never the
baseline/cfg domains — querying those requires passing an explicit `TEST=`
naming a real baseline/cfg test (which every legitimate caller already
does; `regress.py` never invokes `make cov` bare). Passing `OUT=` manually
*in addition to* a `TEST=upstream_sanity`/default invocation would
double-append `/m0` and must not be done — always pick one axis (`TEST=`
for M0/cfg, or a bare `OUT=` for a domain the branches don't touch).
