# BUG-0020 — 仿真从不产 FSDB，xdebug 波形因果能力在本仓库无法使用

## symptom

CLAUDE.md §4 规定「DV/REV 但凡涉及失配定位……应先用 xverif 工具体系做确定性
查询」，其中波形/RTL 因果维度的入口是 `xdebug`。实际调用即失败：

```
@xdebug.error.v1
action: session.open
code: SESSION_UNHEALTHY
message: Server did not become ready: child_exited
```

即本仓库**没有任何可供 xdebug 打开的波形**，`session.open` 只能给
`daidir`（静态设计信息），而 NPI 初始化在这种输入下失败。

后果：本仓库当前配置下，任何需要"回到波形看实际发生了什么"的溯因工作
（BUG-0018 那类观测相位问题是典型）都没有波形可查，只能退回日志推理——
与 CLAUDE.md §4「优先用 xverif 取事实，而非纯模型推理/手算」的纪律冲突。

## first_anomaly

signal: `has_fsdb` = false（xdebug engine 的 `server.transport_config` 阶段）

## taxonomy

## rca

engine lifecycle 日志给出决定性对照——**同一台 VM、同一个 Verdi 安装**：

```jsonc
// 本仓库，2026-07-28（失败）
"phase":"server.transport_config"  "has_daidir":true, "has_fsdb":false
"phase":"npi_init.begin"
"phase":"npi_init.failed"          // 25ms 后失败，child 以 status 256 退出

// 姊妹仓库 ppa-lite-copilot，2026-07-09（成功）
"phase":"ensure_session.success"   "fsdb":".../ppa-lite-copilot/sim/out/wave.fsdb", "dbdir":""
```

1. `xdebug-engine` 是 C 二进制，链接 Verdi 的 **C API** `libNPI.so` /
   `libnpiL1.so` / `libvfs.so`——`ldd` 全部解析成功，**不经过 BUG-0017 的
   `pynpi` 路径**，故本条与 Verdi 版本无关。
2. 其 NPI 初始化需要 FSDB；只给 `daidir` 而无 `fsdb` 时 `npi_init` 失败。
3. 本仓库 `sim/Makefile` **没有任何目标产生 FSDB**：`verdi:` 目标引用了
   `$(OUT)/wave.fsdb`，但该文件从不被生成；`sim/out/run.ucli` 的全部内容
   是 `run; exit`，无 `fsdbDumpvars`；编译旗标里也没有对应的 dump 配置。
4. 故 xdebug 在本仓库不可用的原因是**项目侧缺口（不产波形）**，而非环境
   能力缺失——2026-07-09 的成功记录证明该 VM 上 xdebug 可正常工作。

## fix

未派发（不在发现本条的那张卡范围内）。

修复方向（不预设实现）：给 `sim/Makefile` 增加一条**可选**的波形 dump 路径
（例如 `make run WAVE=1` 走一份带 `fsdbDumpvars` 的 ucli，产出
`$(OUT)/wave.fsdb`），使 `verdi:` 目标名副其实、同时让 xdebug 可用。

设计约束（供后续卡参考，非实现指令）：
- 波形 dump 有仿真性能与磁盘代价，**不应成为 `make run` / `make regress`
  的默认路径**——证据链主链路的成本不能因调试能力而抬高。
- `sim/Makefile` 不在框架快照内（`make fw-check` 不管），可改。
- 边界不变（CLAUDE.md §4）：波形只是观测"实际发生了什么"的手段，checker
  的**期望值**仍只准从 `doc/spec.md` 推导；xdebug 看到的波形事实不得直接
  抄成期望值。
