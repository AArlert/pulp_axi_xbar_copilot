# BUG-0024 — `w_id_open` 是单 bit 而非计数器，同 ID 合法重叠时跟踪记录被提前清除（漏检）

## symptom

`tb/sva/axi_xbar_stall_sva.sv` 的保序跟踪表用**单 bit** `w_id_open[id]`
表示"该完整 ID 有事务在飞"。spec §5.2.4 明确允许同 ID、同方向、**同目标
master 端口**的多笔事务合法堆积——此时两笔共用同一个 bit：

```
第 1 笔 AW 接受 → w_id_open[id] = 1
第 2 笔 AW 接受 → w_id_open[id] = 1   （同一个 bit，无法区分两笔）
第 1 笔 B 返回  → w_id_open[id] = 0   ← 第 2 笔仍在飞，记录却被清掉
```

自此第 2 笔从跟踪表中消失，针对它的乱序检查静默失效。读侧 `r_id_open`
同构。

~~方向是**漏检（假绿侧）**——不会造成假红，只会让本该被检出的乱序悄然通过。~~

> **订正（REV-011 §2.2，2026-07-28）：上面这句不成立，误差是双向的。**
> 本行摘要、本节原文与 REV-010 §1 三处都写作"只漏检、不会假红"，但没有人
> 对"完成侧读到的是哪一笔的序号"做过对照。实际存在一条**假红**路径：
> 登记侧对同一完整 ID 的每次 AW 接受都**覆写** `w_id_seq[aw_id] <= w_seq_ctr`
> （`stall_sva.sv:129-134`）⇒ 表里留的是该 ID **最新**一笔的序号；而 AXI 同 ID
> 同向按接受序完成 ⇒ 实际完成的是**最老**那笔；`w_reorder()`
> （`stall_sva.sv:273-283`）用 `w_id_seq[cand] < w_id_seq[completing_id]` 判
> "更老"，完成侧用的却是被覆写后的更大序号 ⇒ 门槛被抬高，兄弟 ID 被误判乱序。
> 构造（单 slave 端口，桶 0，完整 ID X=0x0 / Y=0x8）：
> `AW X→tgtA(seq0)` → `AW Y→tgtB(seq1)` → `AW X→tgtA(seq2，§5.2.4 合法堆积，
> 覆写 seq[X]=2)` → `B for X`（实为 seq0 那笔）：此时 `w_id_open[Y]=1`、
> `tgt[Y]=B≠A`、`seq[Y]=1 < seq[X]=2` ⇒ 报 `SVA_OR_W_REORDER`，而真相是 X 在 Y
> **之前**被接受、先完成完全合规。
> 现有 9+1 个场景没撞上它：唯一有堆积的 OR03 只用单一完整 ID（兄弟集恒空），
> TL01/TL02 的兄弟全部同目标（`tgt !=` 恒假）；**M3 的多桶 + 目标切换场景同时
> 具备这两个要素**。
> **结论"对已登记证据无影响"不变**——假红不制造假 PASS，M2 七条证据不受动摇。
> 受影响的是修复方案：(b) 路线因此**不能只写文档**（见 `## regression_guard`
> 的 b-2）。通则见 REV-011 §4 G2：「只漏检」是需要给出构造来证明的性质，
> 不是默认属性。

## rca

1. 跟踪表以「完整 ID → 1 bit 在飞标志 + 目标寄存器 + 序号」建模，隐含
   "每个完整 ID 同时至多一笔在飞"的假设。
2. 该假设与 spec §5.2.4 冲突：同 ID 同方向**同目标**事务不受 §5.2 stall
   约束，可合法堆积（这正是 M2-OR02(a) 与 M2-TL02 构造的情形）。
3. 第二笔接受时只是把已经为 1 的 bit 再写成 1，无新增信息；第一笔完成时
   无条件清 0。
4. 于是"还有几笔在飞"的信息从未被保存 ⇒ 第二笔起的所有事务不在候选集内，
   `w_id_open[cand]` 对它们恒为 0，乱序检查跳过。

与 BUG-0023 的关系：BUG-0023 是**同沿**写冲突（一笔进一笔出撞在同一拍），
已修；本条是**跨沿**的容量不足（两笔同时在飞而只有一个槽位）。两者都源自
同一处数据结构，但成因与修法不同，故独立立项。

### 为什么此刻**不**落 WONTFIX —— 本页"只漏检、不会假红"的断言不成立

`## symptom`、`doc/bugs.md` 行摘要与 REV-010 §1 均称本条"方向是漏检（假绿侧），
不会造成假红"。本卡按结构推演**推翻该断言**：

- 登记侧对同一完整 ID 的每次 AW 接受都**覆写** `w_id_seq[aw_id] <= w_seq_ctr`
  （`tb/sva/axi_xbar_stall_sva.sv:129-134`）⇒ 表内留下的是该 ID **最新**一笔的
  序号；
- 而 AXI 同 ID 同向按接受序完成 ⇒ 实际完成的是该 ID **最老**那笔；
- `w_reorder()`（`:273-283`）用 `w_id_seq[cand] < w_id_seq[completing_id]` 判
  "更老"，**完成侧用的是被覆写后的（更大的）序号** ⇒ "更老"的门槛被抬高。

假红构造（单 slave 端口，桶 0，完整 ID X=0x0 / Y=0x8）：

```
AW X → tgtA (seq0)                     w_id_open[X]=1, seq[X]=0, tgt[X]=A
AW Y → tgtB (seq1)                     （BUG-0013/REV-006：外部接受确实会早于核心判决）
AW X → tgtA (seq2, §5.2.4 合法堆积)     覆写 ⇒ seq[X]=2
B for X（实为 seq0 那笔）              cand=Y: open✓ tgtB≠A✓ seq[Y]=1 < seq[X]=2✓
                                       ⇒ 报 SVA_OR_W_REORDER —— 假红
```

真相是该笔 X 在 Y **之前**被接受，先完成完全合规。现有 10 个场景没撞上它，是
