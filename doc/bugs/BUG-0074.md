# BUG-0074 — §4 clause 7 与 §8 clause 3 的环境约束里程碑作用域未含 M5

## symptom

无仿真失败触发——M5 spec-gap sweep（`doc/review/M5-spec-gap-sweep.md` §4）静态
比对发现的 spec 作用域缺口。两条环境约束逐字只覆盖 M3/M4：

- `doc/spec.md` §4 clause 7（L187）："M3 与 M4 全部场景**不向译码未命中地址
  发起任何 ATOP**"——目的是让 err_slv×ATOP 这一许可来源未定义的应答组合
  构造性不可触发。
- `doc/spec.md` §8 clause 3（L480）："M3/M4 稀疏 `Connectivity`……"

M5 的出口条件（`doc/milestone.md` §M5）要求约束随机层 + soak，其中 `addr`
随机化包含译码未命中地址、`atop` 随机化非零，稀疏 `Connectivity` 亦是 soak
拓扑之一 ⇒ **两个被 M3/M4 约束挡住的组合在 M5 必然被构造出来**，而 spec 对
它们的应答形态仍无许可来源，scoreboard 无 oracle 可判。

## first_anomaly

signal: `doc/spec.md` L187（"M3 与 M4"）/ L480（"M3/M4"）的里程碑枚举
        vs `doc/milestone.md` §M5 出口条件要求的随机化维度
time: n/a（非仿真信号——静态阅读比对）
how_found: M5 spec-gap sweep（arch 卡）核对 7 个未引用小节时，为判断 M5 骨架行
M5-RN01/RN02 的可行性而回溯这两条环境约束的作用域，发现均止于 M4。

## taxonomy

SPEC_ISSUE——spec 条款的适用域与本里程碑的验证意图不匹配，且**分叉已实际存在**：
`doc/design-prompt/verification_maturity.md` C2.2/C2.5 已把该约束当作 M5 随机层
的硬约束写入（DE 会照做），而 DV 若只读 spec 会发现 M5 无此约束——同一约束在
两份文档里状态不同，正是 `workflow/records.md` 点名的 Retention 不一致形态。

**决定性先例（本条不得靠"沿用惯例"默认延展的理由）**：spec Change record #7
记载，REV-013 曾主动把 BUG-0032 提案原文的两处 `M3/M4` **收窄为 `M3`**，明言
"M4 覆盖率收敛若需触发该组合须重开仲裁"；随后 BUG-0039/REV-017（Change record
#10）才把它延展到 M4，且那次延展本身走了完整仲裁并附带"M4 覆盖率后果"段。
同一逻辑逐字适用于 M5——**延展必须是一次显式仲裁的产物，不是记账动作**。
