# BUG-0018 — 写事务 request 观测发在 `w_last`，covergroup 的接受时刻交叉 bin 成盲区

## symptom

F-M2-08 落地的 covergroup 中，两处交叉 bin 在**本该命中它们的场景里**恒为空：

- `cg_stall.x_state_dir` 缺 `[stalled][write]` 与 `[not_stalled_diff_direction][read]`；
- `cg_w_order.multi_source_contended` 在其对口场景 M2-WO01 中未命中（只在
  M1-02/CFG01 里偶然命中，7 个 test 合并后才达 100%）。
- **scope 补入（REV-011 §5.2(3)，2026-07-28）**：`cg_tx_limit` 的**写方向
  在飞计数**同根因——它同样在 `w_last` 采样（`tb/scoreboard_refmodel.sv:421`）
  而非 AW 握手当拍，故该计数系统性**偏低**。本页原 scope 只列了上面两处
  cross bin，漏了这一处；修复卡须一并覆盖，复验时也须逐 test 看它。

同一次运行中，SVA 侧对**同一类情形**有明确命中：M2-OR01 里
`tb/sva/axi_xbar_stall_sva.sv:244` 的写方向 cover（AW 呈现/被接受时存在
不同目标的同桶未决兄弟）在 6 个 slave 端口各命中 1 次；M2-WO01 里
`tb/sva/axi_xbar_worder_sva.sv:107` 的 `compete_start` 在 master 端口 0
命中 46 次。即情形**真的发生了**，只是 covergroup 侧记不到。

判决路径不受影响：同批运行 scoreboard 与全部 SVA 判决均零失配
（`UVM_ERROR:0`，`2143 assertions / 0 failures`）。

## taxonomy

## rca

1. `slvport_monitor` 为了在一条观测里携带完整 `wdata`/`wstrb`，把写事务的
   request 观测发在 **W burst 的 `w_last`**，而非 AW 握手当拍。
2. scoreboard 因此拿不到"AW 被接受"这一时刻的事件流——写事务的记录要晚
   若干拍才进 `or_open_q` / `worder_pend`。
3. M2-OR01（`resp_hold=0`）下，较早那笔写往往在 younger 写的记录入队前
   已经完成，§5.2.1 的前提在 scoreboard 视角里已消失，younger 写被分类成
   `SC_NONE` ⇒ `[stalled][write]` 恒空。
4. M2-OR02(b)（一读一写同低位 ID）下，读被接受时写记录尚不存在 ⇒
   `[not_stalled_diff_direction][read]` 恒空。
5. M2-WO01 下，W burst 起始时刻的"该 master 端口有 ≥2 个不同源 AW 未决"
   计数同样因写记录迟到而偏低 ⇒ `multi_source_contended` 在对口场景恒空。

## fix

未派发（不在 F-M2-08 卡范围——该卡为覆盖采集基建交付卡，本条动的是喂判决的
monitor/env 管线）。

建议方向（由后续卡自行推导落地方式，此处不预设实现）：给 scoreboard 增加
一路 **AW/AR 接受事件**（`slvport_monitor` 在握手当拍额外发一条轻量观测，

严重度低、非阻塞：判决正确性不受影响（判决锚点是完成序，不是接受时刻——
见 `doc/testplan.md` M2-OR01 行与 BUG-0013/REV-006 裁决），且这两类情形的
**assert 维度记录已由 SVA 侧精确覆盖**。代价是 M4 六类覆盖 ≥90% 收敛时，
这几个 cross bin 会以"永远填不满"的形式再次出现——建议在 M3 前解决。

### closer 独立复验的 `cp_stall_state` 订正（REV-011 §3.3）

closer（独立 DV 实例，非本条 fixer；独立重跑 7a1c912 工作树 + 独立推导，
未采信 fixer 的转述或数字）复核后确认：REV-011 §3.3 到期判据中
「`cp_stall_state` 由 33.33% 上升」这一子句对 **M2-OR01 几何不可达**，理由如下
（逐句独立推导，非引用）：

1. `cg_stall.cp_stall_state`（`tb/functional_coverage.sv:87-98`）**只有 3 个
   bin**：`stalled`=SC_STALLED、`not_stalled_same_target`=SC_SAME_TGT、
   `not_stalled_diff_direction`=SC_DIFF_DIR；SC_NONE 有意不设 bin。故其满分需
   三类全触达，任一场景的上限由该场景能触达的 class 数决定。
2. M2-OR01 的构造（`doc/testplan.md` M2-OR01 行）：单 slave 端口连续两笔、低
   `AxiIdUsedSlvPorts=3` 位相同、**同方向对**（同写或同读）、译码命中**不同**
   master 端口。
3. 分类逻辑 `tb/scoreboard_refmodel.sv:502-510`：第二笔被接受时，同向同桶队列
   `or_open_q[k]` 非空（第一笔在内）⇒ 先置 SC_SAME_TGT，再因队内记录的
   `mst_port != exp_port`（命中不同 master 端口）改判 **SC_STALLED**；第一笔
   接受时队列空 ⇒ SC_NONE（无 bin）。
   - **SC_SAME_TGT 被构造排除**：它要求同向同桶的更老记录目标**相同**，而
     M2-OR01 明确命中不同 master 端口，`mst_port != exp_port` 恒真。
   - **SC_DIFF_DIR 被构造排除**：它走 `else if`（同向队列空、仅异方向兄弟
     open）分支，要求异方向兄弟并存；M2-OR01 是同方向对，且经验数据显示读/写
     两对在时序/桶上不重叠（`cp_stall_state=33.33%`=1/3，若 SC_DIFF_DIR 被触达
     则应为 66.67%）。
4. 结论：M2-OR01 只能触达 SC_STALLED（另加无 bin 的 SC_NONE）⇒ `cp_stall_state`
   在本场景的**结构天花板 = 1/3 = 33.33%**。且 SC_STALLED 在读腿修复前就已由
   **读方向**那对命中（读观测本无 `w_last` 迟到问题），故 `cp_stall_state`
   修复前即已达 33.33% 的天花板。写腿修复新增的只是 `cp_dir=write` 侧的 SC_STALLED
   命中，它体现在更细的 **`x_state_dir[stalled][write]`（16.67%→33.33%）**，
   而非 `cp_stall_state`（其 `stalled` bin 早被读腿填过）。

因此 REV-011 §3.3「`cp_stall_state` 由 33.33% 上升」无法实现——**实质到期判据是
`x_state_dir[stalled][write]` 由空转非空**（即 x_state_dir 16.67%→33.33%）。
本订正与 fixer 上报的结论一致，closer 独立复核后采信。

### 症状与"判决路径不受影响"的独立复核（不采信本页原文）

从**已提交证据**逐 test 抽取（未重跑）：`doc/evidence/v0.2.0/M2-OR01.log`
`cp_stall_state=33.33%`、`x_state_dir=16.67%`；`M2-OR02.log` `x_state_dir=33.33%`；
`M2-WO01.log` `cp_w_contention=50.00%`（只填 `single_source` 一格）。症状属实。

判决路径不受影响，本卡自行验（三条独立）：
1. 排序键精确 —— `tb/slvport_agent.sv:376` 在 **AW 捕获处** `a.accept_time =
   $time`，`:418` 在 `w_last` 发观测时原样转抄；
2. 判据键含方向 —— `or_key(port, is_write, bucket)`
   （`tb/scoreboard_refmodel.sv:397`），完成侧只枚举 `or_open_q[k]`（`:649`）
   ⇒ 跨方向相位差不进入判决；
3. 同方向写迟到不漏检 —— 同 slave 端口 W burst 按 AW 次序发出（spec §5.5.1），
   更老的写必先到自己的 `w_last` 先入队；任一写的 B 必晚于它自己的 `w_last`
   ⇒ 任一完成到来时所有更老的同向记录都已在队。

**结论：M2 七条证据不动摇。**

### 为什么定档 M3 而不是 M4

1. **M4 那条机器判据接不住它**：spec §0 #4 的六类是
   `line+cond+fsm+tgl+branch+assert`——**不含 covergroup**。这两处 cross bin
   填不满不会在 M4 触发任何机器红灯；挂到 M4 等于挂到一个不存在的 gate 上
   （discipline rule 4）。真正接住它的是 rubric 第 4 条的**人工抽查**，而那条
   在**每次**签核（含 M2）都要做。
   （附带：`doc/feature-matrix.md` F-M2-08 把 functional 说成"六类之一"，与
   spec §0 #4 的六类清单不符——文档漂移，非本条缺陷，供 M4 规划时一并订正。）
2. **M3 新场景共用同一条 monitor 事件流**：拖过 M3 意味着 M3 期采集的功能覆盖
   带着同一个相位盲区，M4 还要重采；而本条守卫要求"逐 test 看、不看 merged"，
   test 数越多越难做。
3. 修复触及**判决输入管线**（新增一路 AW/AR 接受观测），越晚落地依赖它的场景
   越多、全回归代价越大。

`ACCEPTED@M3` 不阻塞 M2 签核、不阻塞 M3 派发；M3 签核时
`scripts/docs.py:855` 到期拦截。
