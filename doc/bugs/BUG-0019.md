# BUG-0019 — `make lint` 缺 `-top`：默认多顶层枚举撞上 vendor 测试专用 wrapper 模块的未约束参数

## symptom

在 BUG-0014 的修复（`lint:` 目标复用 `VCS_FLAGS_2018`，补上 `-assert svaext`）
落地、`vendor/common_cells/src/clk_int_div.sv` 的 `Error-[SE]` 不再触发之后，
`make lint`（任意会拉入 `flist/dut.f` 的 TEST，含默认的 `upstream_sanity`）在
**同一目标里再暴露出第二个、此前被完全遮蔽的独立阻断点**：编译在到达
`../tb/` 范围前又一次以 `Error-[NOODV]`/`Error-[ZMMCM]`/`Error-[CEPO]`/
`Error-[TCF-ICTC]` 整体中止（`vendor/common_verification/src/stream_watchdog.sv`
`NumCycles` 参数缺省值/覆盖值缺失、`vendor/axi/src/axi_lite_regs.sv` 与
`axi_to_detailed_mem.sv` 里含 `$bits(...)`/`{REG_NUM_BYTES{...}}` 的参数覆盖
在缺失顶层约束下无法求值），命中 VCS 默认 `MAX_ERROR_COUNT`（10）后编译整体
以 exit 255 中止，`lint:` 目标自身"仅 `../tb/` 范围内失败才判不合格"的
grep 过滤逻辑再次从未被执行到。

signal: n/a（工具链编译期报错，非仿真信号）

时对整份 flist 做默认多顶层枚举导致；诊断性追加 `-top $(TOP)` 后同一条
命令编译 0 error/0 warning 并到达 grep 过滤步骤，证实二者互为独立成因。

## taxonomy

TOOL_ENV

## rca

1. `sim/Makefile` 的 `lint:` 目标从未传 `-top $(TOP)`（`compile:`/`run:`
   目标始终传）。
2. 缺省 `-top` 时，VCS 把编译单元里"没有被任何父模块例化"的每个
   module/interface 都当作独立顶层去做默认 elaboration。
3. `flist/dut.f` 拉入完整 vendor/axi 库，其中含大量测试专用 `*_intf`
   便利 wrapper（以及 `common_verification` 的 `stream_watchdog` 等），
   这些模块设计上只应被父模块**带参数覆盖**例化，从不单独顶层展开。
4. `+lint` 编译流程因此尝试独立展开约 100 个孤儿顶层，其中数个因缺失/
   无法求值的参数覆盖当即报错（`NOODV`/`ZMMCM`/`CEPO`/`TCF-ICTC`），撞上
   VCS 默认 10 条报错上限，整体中止——`../tb/` 过滤逻辑再次从未执行到。
5. 该缺陷此前一直被 BUG-0014 更早的中止点（`vendor.f` 内
   `clk_int_div.sv` 的 `Error-[SE]`）完全遮蔽；与 `-assert svaext` 无关，
   是 `lint:` 目标自诞生起就存在的独立问题，本次修 BUG-0014 时才现形。

## fix

同一 diff 内随 BUG-0014 一并落地（`sim/Makefile` `lint:` 目标追加
`-top $(TOP)`，与 `compile:`/`run:` 目标已有模式保持一致）。
commit: 占位——由 orch 收版后回填（同 BUG-0014 处置约定）。
what: `lint:` 的 VCS 调用改为只展开真实 DUT/TB 层级（`TEST=upstream_sanity`
时为 `tb_axi_xbar`，其余 UVM TEST 时为 `tb_top`），不再对全量 flist 做
默认多顶层枚举。

`../tb/` 文件）：`Verdi KDB elaboration done ... 0 error(s), 0 warning(s)`，
输出 `lint clean within ../tb/ scope`。
`make lint TEST=m2_cfg01_reconfig_test`（`FLISTS` 走 `tb.f`，真含 `../tb/`

在真实 `../tb/` 范围内命中若干 `Lint-[SVA-UA]`/`Lint-[NS]`/`Lint-[WMIA-L]`
等既有告警（与本条修复无关，见同批 DV 交付报告，未在本条内处理）。
