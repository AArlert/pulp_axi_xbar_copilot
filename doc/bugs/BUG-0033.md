# BUG-0033 — err_slv 译码错误读响应的数据值与 spec §4.4 矛盾（doc-vs-RTL）

## symptom

M3 错误路径 checker（M3-DE01/DE02/OR04）落地并首次仿真时实测浮出：译码错误
读响应每个 R beat 的数据值与 spec §4.4 不一致。

- **spec §4.4**（蒸馏自 `vendor/axi/doc/axi_xbar.md` L33："The data of each
  read response beat is `32'hBADCAB1E` (zero-extended or truncated to match the
  data width)"）：数据 = `32'hBADCAB1E`，按 `AxiDataWidth=64` **零扩展** =
  `64'h00000000_BADCAB1E`（上 32 位为 0）。
- **DUT 实测**：`r.data = 64'hCA11AB1E_BADCAB1E`（上 32 位 `0xCA11AB1E ≠ 0`）。

resp 码 `DECERR`、beat 数 `AxLEN+1`、`RLAST`、下 32 位 `0xBADCAB1E`、响应回送
到发起端口——**全部与 spec 一致**；唯上 32 位数据违反 §4.4 的"零扩展"。

checker 的期望值按 spec §4.4 推导（`scoreboard_refmodel.sv` 的
`ERR_RDATA = data_t'(32'hBADCAB1E)`，注释引 §4.4），故 `SB_DECERR_RDATA` 见红。
**这是 checker 按 spec 正确捕获的 DUT/文档偏差，不是 checker bug**——依 CLAUDE.md
输入边界，期望值只准来自 `doc/spec.md`，绝不抄 RTL 观测值（spec-from-RTL 红线）。

## first_anomaly

signal: `r.data` 上 32 位 = `0xCA11AB1E`（spec §4.4 要求 `0x00000000`）
time: `m3_de01_decerr_test SEED=1` @ 235000（首笔译码错误读的第 0 拍）
how_found: DV 落地本卡（BUG-0025+BUG-0031 修复 + 四条 M3 场景）时，为 M3-DE01
写 decode-error 参考判据、按 spec §4.4 设 `ERR_RDATA`，`make run` 后 12 处
`SB_DECERR_RDATA` 报红，报文 `got data='hca11ab1ebadcab1e expected data='hbadcab1e`。
随后读许可来源确认偏差真实：`vendor/axi/src/axi_err_slv.sv:25` 的
`parameter RespData = 64'hCA11AB1EBADCAB1E`（`RespWidth=64`，默认，无零扩展），
`vendor/axi/src/axi_xbar_unmuxed.sv:195/238` 例化 `axi_err_slv` **未覆写** `RespData`
⇒ 用默认全 64 位魔数常量，其低 32 位恰为 `0xBADCAB1E`、上 32 位为 `0xCA11AB1E`。
上游文档 L33 的"zero-extended"与其自身 RTL 默认常量**互相矛盾**。

## taxonomy

SPEC_ISSUE（doc-vs-RTL，同 BUG-0016 家族——上游文档与实现散文互相矛盾，
DV 不得单方裁决）

## rca

1. spec §4.4 忠实蒸馏自 xbar.md L33 的"`32'hBADCAB1E` (zero-extended ...)"。
   该措辞描述的是 `axi_err_slv` 的**可参数化**行为：若把 `RespData` 设成
   `32'hBADCAB1E`、`RespWidth=64`，则会零扩展。
2. 但 `axi_xbar`（经 `axi_xbar_unmuxed`）例化 err_slv 时**不设** `RespData`，
   用其默认值 `64'hCA11AB1EBADCAB1E`（一个低 32 位为 `BADCAB1E` 的完整 64 位
   常量），`RespWidth` 默认 64 = `AxiDataWidth` 故 `r.data = RespData` 直取。
3. 净效果：xbar 实际吐出 `64'hCA11AB1EBADCAB1E`，与文档 L33 的"零扩展 32 位"
   在上 32 位不符。文档描述了参数化能力却没描述 xbar 的实际取值。

## fix

**REV-014 终判：SPEC_CHANGED（taxonomy SPEC_ISSUE 成立，不改判 DUT_BUG）。**
处置路径 = 提案 P-REV014-1 校正 spec §4 clause 4（读响应数据值 `32'hBADCAB1E`
零扩展 → err_slv 默认 `RespData=64'hCA11AB1EBADCAB1E` 按 `AxiDataWidth` 零扩展/
截断，宽度参数化，标注来源 RTL）。DUT_BUG 不予签核（错误响应 RDATA 协议上
don't-care、无显式条款被违反、魔数常量为刻意设计、零功能损害）；不走 P-xxx
行为补丁。checker `ERR_RDATA` 随 spec 校正从 pinned §4.4 更新为
`data_t'(64'hCA11AB1EBADCAB1E)`（不抄 RTL），三条场景读侧转绿由 `make
evidence` 背书，闭环卡与本裁决分派不同实例（closer≠fixer）。详见
`doc/review/REV-014.md`。

依据引用：`vendor/axi/src/axi_err_slv.sv:24-25/196`、
`vendor/axi/src/axi_xbar_unmuxed.sv:195-211/238-251`、
`vendor/axi/doc/axi_xbar.md:33` @ v0.39.9 SHA `a256a3b8`；spec §4 clause 4 /
§0 基线 `AxiDataWidth=64`；taxonomy `workflow/bugs.md` SPEC_ISSUE 判据；
先例 REV-007（BUG-0016 doc-vs-RTL→SPEC_CHANGED）、REV-012/013（BUG-0032
沉默→环境约束，本条辨析为不同处置：本条许可来源明确但与 RTL 矛盾，走
"以 RTL 校正 spec"而非"环境约束回避"）。

DV 不得在 checker 里把期望值改成 RTL 观测值来强行转绿（spec-from-RTL 红线 /
discipline rule 1）——校正后的 `ERR_RDATA` 仍须从 **pinned spec §4.4** 推导，
不得引 RTL 行号；亦不得把该失配降级为 warning 求绿（"沉默的通过"失效家族，
REV-011 §4 G1）。
