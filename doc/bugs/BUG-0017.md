# BUG-0017 — `xcov` 在本 VM 不可用（Verdi O-2018 的 pynpi 无 coverage 模块）

## symptom

CLAUDE.md §4 要求「覆盖率核对优先用 xverif 取事实，而非纯模型推理/手算」，
其中覆盖率维度的入口是 `$XVERIF_ROOT/tools/xcov`。DV 卡 F-M2-08（功能覆盖
采集基建落地）首次真正需要按 bin 级核对 covergroup 命中时调用该工具，
`session.open` 直接失败：

```
NPI_INIT_FAILED: cannot import name 'cov' from 'pynpi'
(/home/synopsys/verdi/Verdi_O-2018.09-SP2/share/NPI/python/pynpi/__init__.py)
```

即本 VM 安装的 Verdi O-2018.09-SP2 所带的 `pynpi` 包中不含 `cov` 子模块，
`xcov` 无法初始化 NPI 会话。工具本身可执行（`test -x` 通过），失败发生在
打开 coverage database 的那一步。

## taxonomy

TOOL_ENV

## rca

1. `xcov` 通过 Synopsys NPI（Native Property Interface）的 Python 绑定
   `pynpi` 访问 coverage database。
2. 其 coverage 能力依赖 `pynpi.cov` 子模块。
3. 本 VM 的 Verdi 版本为 O-2018.09-SP2（CLAUDE.md §4 记载的既定环境），
   该版本 `share/NPI/python/pynpi/__init__.py` 未导出 `cov`——coverage NPI
   在该版本尚未提供 Python 绑定。
4. `xcov` README 记载的验证形态为 Verdi V-2023.12，与本 VM 版本存在代际差。
5. 故 `xcov` 在本 VM 上对**任何** vdb 都会以同一签名失败，与被查询的
   coverage database 内容无关。

## fix

未派发（工具体系不在本仓库范围内，`$XVERIF_ROOT` 为外部安装）。本条为
**环境能力缺口登记**，目的是让后续每个需要覆盖率事实的卡不再重新发现：
在本 VM 上 `xcov` 路径不通，直接走下述绕法。

**已验证可用的绕法**（F-M2-08 卡实际采用，产出了第 3 节的 bin 级命中表）：

```
make cov                                    # urg HTML 报告
urg -full64 -dir out/cov.vdb -format text -report out/urgText -metric group
```

后者若直接在命令行调用，需自带 `VCS_HOME` 与 `LM_LICENSE_FILE`；走
`make cov` 则由 `scripts/make/vcs-2018.mk` 代为导出，无需手工设置。
bin 级明细落在 `sim/out/urgText/grpinfo.txt`。

注意边界不变：urg 与 xcov 一样只是**观测"实际发生了什么"**的手段，
checker 的期望值仍只准从 `doc/spec.md` 推导（CLAUDE.md §4 红线）。
