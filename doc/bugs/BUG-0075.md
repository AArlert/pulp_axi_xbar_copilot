# BUG-0075 — 共享译码 oracle 未实现 spec §3.2 clause 3 的 `end_addr=='0` 哨兵语义

## symptom

无仿真失败触发——M5 收口审计（rev 红线 2 合规评审，0.5.15）静态比对发现的
checker-vs-spec 保真度缺口。`tb/xbar_types_pkg.sv` `decode_mst_port()`（被
scoreboard 与 `axi_xbar_stall_sva`/`axi_xbar_route_sva` 三方共用的单一来源
译码函数）的命中判据为：

```systemverilog
if (addr >= amap[r].start_addr && addr < amap[r].end_addr)
```

`doc/spec.md` §3.2 clause 3 规定 `end_addr=='0` 为哨兵：区间延伸至地址空间
末端（`effective_end = 2^AxiAddrWidth`），此时上式应恒真；但 `addr_t` 无符号
下 `addr < 0` 恒假——方向恰好相反（该 rule 将永不命中，而 spec 要求全命中）。

## first_anomaly

signal: `tb/xbar_types_pkg.sv` `decode_mst_port()` 区间比较式
        vs `doc/spec.md` §3.2 clause 3 哨兵条款
time: n/a（静态阅读比对，非仿真信号）
how_found: M5 里程碑收口的红线 2 全量审计逐条核对判据 spec 锚点时发现。

## repro

n/a（休眠缺口，现行激励构造性不可触发）：tb/ 全部地址表
（`ADDR_MAP`/`ADDR_MAP_V1`/`ADDR_MAP_OV1`/cfgD 表）均由
`REGION_SIZE=0x1000_0000 × (i+1)`（i≤7，终址最大 `0x8000_0000`）生成，
从不产生 `end_addr==0`；tb/ 亦无对 addr_map 字段的 randomize()。
静态复核 = 对照 `doc/spec.md` §3.2 clause 3 与
`tb/xbar_types_pkg.sv` `decode_mst_port()` 的区间比较式。

## taxonomy

TB_BUG（休眠）——scoreboard/SVA 期望推导对 spec 条款的实现缺失。当前测试
套件下该分支不可达，不构成任何已登记 PASS 的假通过；但一旦 M6 或后续
随机化引入 `end_addr==0` 边界（或新场景直接构造它），三方 checker 将同时
静默偏离 spec。

## fix plan（M6 处置，二选一，动手前须 rev 评审）

1. 在 `decode_mst_port()` 实现哨兵语义（期望值从 §3.2 clause 3 推导，红线 2
   合规），并注册一个真实触达 `end_addr==0` rule 的场景使修复可证伪；或
2. 走 spec 环境约束路线：§3.2 clause 4 旁增补"env 地址表构造不产生
   `end_addr==0`"条款（构造性不可达，§8.3 先例），checker 维持现状。

任一路线落地前，本缺口保持 OPEN、非阻塞（不影响 M5 已有证据的有效性——
影响面为零，见 repro 节）。
