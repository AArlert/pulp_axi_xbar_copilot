# BUG-0038 — spec §0#4 names addr_decode/axi_demux as mandatory coverage scope, but both are pass-through wrappers with no line/cond/branch/assert content of their own

## symptom
Per the clean baseline (17-test, single 6x8 design) `urg` report
(`doc/evidence/v0.4.0/M4-coverage-baseline.md` §3), the `addr_decode` and
`axi_demux` module pages report **blank** (not 0%, not N/A-but-scored —
literally no bins collected) for LINE, COND, BRANCH and ASSERT; only
TOGGLE is populated. Every other spec-§0#4-named module
(`axi_xbar_unmuxed`, `axi_mux`, `axi_err_slv`) reports all six types (or a
subset with a plausible reason, e.g. no FSM construct).

## fix
commit: none — SPEC_ISSUE requires rev arbitration, not a local
interpretation (discipline.md §1: "a silent pick has a name... it goes in
doc/bugs.md, and rev arbitrates"). Arbitrated by REV-016 (2026-07-30):
taxonomy SPEC_ISSUE upheld, disposition **SPEC_CHANGED**. orch applied
proposals P-REV016-1 / P-REV016-2 verbatim to `doc/spec.md` §0 item 4 / item
5 and re-pinned `doc/spec.sha256`; spec Change record row #9 records the
scope. Ruling in one line: the "等" catch-all **was always an instantiation
closure** (criterion = does the module appear in the `axi_xbar` instance
subtree, independent of which upstream library directory it lives in), so
`addr_decode_dync` / `axi_demux_simple` / `axi_atop_filter` / `axi_multicut`
and the common_cells primitives inside them are all in scope — the change is
a clarification, not a scope expansion. The silence the guard complained
about is answered by a new tri-state rule: a (module, type) pair with no bins
is **N/A** (excluded from both numerator and denominator) and its verified
cause must be written out per entry; blank may never be recorded as 0%, as
100%, or omitted, and a parent's N/A may never stand in for a child's
compliance.
