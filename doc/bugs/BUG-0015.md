# BUG-0015 — atop SVA 属性内直接调函数读跟踪状态，observed region 采样致自触发假红

## symptom

`tb/sva/axi_xbar_atop_sva.sv`（C3.5，本卡 M2-AT01 新增）首版将 §6.4 ID 唯一性
断言写作 `(aw_valid && aw_ready && aw_atop != '0) |-> !id_busy(aw_id)`，其中
`id_busy()` 是直接在 property 表达式里调用的、读取模块内跟踪数组
（`w_cnt`/`r_cnt`/`atop_*_pend`）的函数。首次 bring-up 运行
（`make run TEST=m2_at01_atop_test SEED=1`，修复前版本）中，**每一笔** ATOP AW
握手都触发 `SVA_ATOP_ID_UNIQ`（6 端口 × 3 笔 = 18 次假红）——包括各端口复位后
发出的**第一笔**事务（该端口此前显然零在飞）。同一日志中 scoreboard 判据全绿
（route/resp 零失配、atop(C6.3) pairs=18 全配对），指向 checker 自身而非 DUT。

## first_anomaly

signal: `SVA_ATOP_ID_UNIQ` @ 115000ps（各 slave 端口第一笔 ATOP AW 握手沿，
六端口同沿齐发）
time: 115000 ps（修复前首运行）
how_found: 本卡（M2-AT01）新增 SVA 模块后的第一次 `make run`；"空闲端口的
第一笔事务也报 ID 在飞"这一自相矛盾直接锁定 checker 采样语义问题。

## taxonomy

TB_BUG

## rca

1. SVA property 中**直接引用的信号**在 preponed region 采样（时钟沿前的值）；
   但 property 表达式里**调用的函数**在断言求值时（observed region）执行，
   函数体内部读取的模块变量取的是**当沿 NBA 更新之后**的现值。
2. 本模块的跟踪 `always_ff` 在同一 posedge 用 NBA 把这笔 ATOP AW 自己的登记
   写入 `w_cnt[aw_id]`/`atop_*_pend[aw_id]`；observed region 里执行的
   `id_busy(aw_id)` 于是"看见"这笔事务自己的登记 → 永真触发，与端口先前
   在飞状态无关。
3. 修复：把谓词折叠为 `always_comb` 组合信号（`aw_id_busy_now`/
   `any_inflight_now`），property 直接引用该**信号** → 获得 preponed（沿前）
   采样，即"此笔握手登记之前"的在飞集合——正是 spec §6.4 约束的语义。
   同一修复同时施于"非空在飞集合"cover（否则该 cover 会被 ATOP 自身登记
   假命中、失去非空转证明价值）。

## fix

`tb/sva/axi_xbar_atop_sva.sv`：新增 `aw_id_busy_now`/`any_inflight_now`
两个 `always_comb` 信号，assert 与 cover 改为引用信号；模块内注释已把该
采样语义陷阱写明（含首运行自触发的事实）。修复后同 TEST+SEED 重跑：
UVM_ERROR 0、`Summary: 2137 assertions ... 0 with failures`、两条 cover
均非零命中（"原子读发起"每端口 3 次、"非空在飞集合"每端口 1 次）。
**未改 vendor/RTL。**
