# BUG-0072 — `scripts/docsx.py` §12 executor: quoted `$(...)` command substitution bypasses the token-level denylist

## symptom

`scripts/docsx.py`'s §12 executor gate (`exec_gate`) is supposed to reject any
`check=`/`left=`/`right=`/`doc/guards.md` `check` value that contains a
denylisted word (`rm`/`mv`/`make`/…, `doc/design-prompt/doc_mechanization.md`
C12.2). A value that carries the denylisted word inside a **double-quoted**
`$(...)` command substitution instead passes `exec_gate` clean and would be
handed to `subprocess.run(["sh", "-c", cmd])` for real — the shell evaluates
the substitution (running the embedded destructive command) before `sh`
even gets to whatever the outer command was.

how_found: card 2b (docsx.py batch 2, F3/F4/F5 + guards.md migration),
while evaluating whether one polluted guard's original two-grep-counts
`ref:` (BUG-0064's `doc/bugs/BUG-0064.md`) could be losslessly rewritten as
a single `type: script` `check=` using `test "$(cmd1)" = "$(cmd2)"` —
before adopting that shape, its safety under `exec_gate` was checked
empirically rather than assumed, and the check failed silently (returned
`ok=True` for an injected `rm -rf sim/out`). The migration ultimately did
**not** use this shape (BUG-0064 stayed `type: checklist`), so no shipped
`doc/guards.md` row is affected — but the underlying gate defect is real
and pre-existing (batch 1's own code, `scripts/docsx.py`'s `exec_gate`).

## rca

```
observed:   docsx.exec_gate('test "$(cat doc/bugs.md; rm -rf sim/out)" = "x"')
            -> (True, '')  — accepted, would reach subprocess.run
anomaly:    the exact same denylisted word, unquoted ($(rm -rf sim/out)),
            IS correctly rejected: docsx.exec_gate('echo $(rm -rf sim/out)')
            -> (False, 'denylisted token: rm'). Only the quoted form
            bypasses the gate.
chain:      exec_gate tokenizes the command with
            shlex.shlex(cmd, posix=True, punctuation_chars=True) and then
            (a) flat-scans every token for exact membership in
            DENY_SIMPLE, and (b) walks |/;/&&/|| -separated segments
            checking each segment's first token against the allowlist.
            An UNQUOTED `$(rm -rf sim/out)` happens to get torn apart by
            shlex's own punctuation_chars handling into six separate
            tokens (`$`, `(`, `rm`, `-rf`, `sim/out`, `)`) — `rm` ends up
            as its own token purely as a side effect of how shlex treats
            $/(/) as punctuation, and the flat DENY_SIMPLE scan happens to
            catch it. A QUOTED `"$(rm -rf sim/out)"` — the idiomatic shell
            form for command substitution, and the exact shape KILL-0006's
            own injection (`cat doc/bugs.md && rm -rf sim/out`) takes when
            wrapped this way — is consumed by shlex as ONE opaque
            double-quoted string token. That single token is neither an
            exact match for any DENY_SIMPLE entry (the membership check is
            exact-string, not substring) nor does it land at the head of
            any |/;/&&/||-delimited segment (it is just one argv-position
            token belonging to whatever allowlisted command, e.g. `test`,
            precedes it) — both defense layers look straight through it,
            because neither one understands that a POSIX shell will
            recursively evaluate a `$(...)` (or backtick) substring as a
            nested command, regardless of what quoting surrounds it.
class:      TOOL_ENV/TB_BUG boundary — the gate's design intent (§12,
            "denylist 覆盖 rm/mv/make/…") is sound; the implementation's
            token-exact-match strategy does not account for shell-level
            re-evaluation of quoted substrings, which is a mechanism gap,
            not a data gap (no amount of adding words to DENY_SIMPLE fixes
            this — the fix has to inspect token *contents*, not just
            compare whole tokens).
```

## fix

Not yet dispatched (this page registers the finding; card 2b's own
boundary is docsx.py's F3/F4/F5 delivery, not this executor's own repair —
see `doc/bugs.md` BUG-0072 row `verify_evidence` column for the fixer
scope note). Candidate direction (not authoritative — a fixer card should
evaluate): reject any token whose *content* contains the substring `$(`,
`` ` ``, or `${` outright (before the exact-match/segment-head checks),
since §12's threat model (C12.2: "针对'误写破坏性命令'威胁模型，非对抗性
注入") does not need to support command substitution at all in a
`check=`/`left=`/`right=` value — none of the ten families' worked
`red_when` examples in `doc_mechanization.md` use it, and F3's own
`left=`/`right=` pair is meant to be two independent, simple set-producing
commands, not a single command with embedded substitution.
