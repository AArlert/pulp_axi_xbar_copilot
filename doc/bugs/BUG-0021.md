**F1（真缺陷，严重度：中）——判决 property 内直接调用读跟踪状态的函数，
违反 BUG-0015 已登记的 regression_guard。**
`w_reorder()`/`r_reorder()` 读的是同模块 `always_ff`（120-144 行）维护的
`w_id_open[] / w_id_tgt[] / w_id_seq[]`。property 内直接引用的信号在
**preponed** region 采样，而 property 表达式里调用的函数在 **observed**
region 执行、函数体读到的是**同一时钟沿 NBA 更新之后**的现值——这正是
BUG-0015 已用实测确立的 VCS 行为（`doc/bugs/BUG-0015.md` `## rca` 1./2.）。
BUG-0015 `## regression_guard` 明文禁止该写法；`## similar` 已把本文件点名为
"边界用法、后续动该文件时折叠"，本次分诊把它从"边界用法"升格为**真缺陷**：
判据语义（spec §5.2.3"完成序不得跨 master 端口乱序"要求的是**本次完成登记
之前**的在飞集合）与实现语义（登记之后）不一致，当前的正确性是激励巧合而非
构造保证。

*误差方向（关键，决定证据是否作废）*：设本沿完成 ID = `B`。
- 本沿若有 `aw_id = A ≠ B` 的 AW 握手：post-NBA 使 `w_id_open[A]=1`、
  `w_id_seq[A]=w_seq_ctr`（全局最大）。函数里 `w_id_seq[cand] < w_id_seq[B]`
  对它恒假 ⇒ 既不多报也不漏报。
- 本沿若有 `aw_id = A = B` 的 AW 握手：`w_id_tgt[B]`/`w_id_seq[B]` 被新事务
  覆盖，`w_id_seq[B]` 变成最大值 ⇒ 所有仍开着的异目标兄弟都被判成"更老"，
  **假红**。
- 反向（把真实乱序判成合规）不存在：`w_id_open[cand]` 在本沿只可能被
  "cand 自己的 AW"置 1（每端口每拍至多一笔 AW，且 `cand != completing_id`
  已排除自身），只可能被"cand 自己的 B"清 0（每端口每拍至多一笔 B，而本沿的
  B 就是 `completing_id`，同样被排除）。
⇒ **该缺陷只能造假红，不能造假绿。** 7 条 M2 证据均为 0 assertion failure，
故没有一条 PASS 是被这个缺陷"放过"的。

**F2（真缺陷，严重度：低）——6 条 cover 同样在表达式内调函数。**
同一采样语义问题，但方向亦为单侧：`w_sibling_open()/r_sibling_open()` 里
post-NBA 为真 ⇒ preponed 必为真（置 1 的唯一来源是本沿自身 AW，已被
`cand != id` 排除），故**只会漏计、不会虚计**。已登记证据中引用的 cover 命中
数是保守下界，"非空转"结论仍然成立。

**F3**：三条都是 action block 内直接引用模块变量（而非 `$sampled(b_id)`）。
IEEE 1800 §16.9.3/§16.5.1：并发断言的判决用 preponed 采样值，而 action block
在 **Reactive** region 执行，读普通变量得到的是**当前**值。TB 的通道信号由
驱动器在同一 posedge 用 NBA 更新，因此报错信息里打印的 ID 可能已经是**下一
笔**事务的 ID，与真正触发断言的那一笔不符。
- 与 BUG-0015 的差别：BUG-0015 的错采样在 **property 表达式**里 ⇒ 影响判决；
  本条在 **action block** 里 ⇒ **不影响判决**，只影响报错信息可读性/定位。
- 与 F1 的关系：`axi_xbar_atop_sva.sv:154` 的判决部分已经修好（BUG-0015），
  遗留的只是这条消息保真缺口；`stall_sva` 两条则与 F1 在同一行族。
- 修复：`$sampled(b_id)` / `$sampled(r_id)` / `$sampled(aw_id)`。

#### G. 门禁自身缺陷（分诊中新撞上，非 259 条之一）

`make lint` 在 VCS **增量编译命中**时（`out/simv_lint.daidir/.vcs.timestamp`
存在且源码未变）会打印 "The design hasn't changed and need not be
