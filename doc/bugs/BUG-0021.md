# BUG-0021 — `make lint` 门禁首次可用即恒红：`tb/` 范围内 259 条既有 Lint 告警

## symptom

BUG-0014（缺 `-assert svaext`）与 BUG-0019（缺 `-top $(TOP)`）修复后，
`make lint` 的 `../tb/` 范围过滤逻辑**第一次真正被执行到**——随即在本仓库
交付物范围内命中 259 条既有 Lint 告警并 `exit 1`：

```
$ make lint TEST=m2_cfg01_reconfig_test
（编译/elaboration 0 error）

../tb/sva/axi_chan_sva.sv, 190
...
```

即门禁本身工作正常（true-positive 分支正确拦截），但本仓库当前代码**过不了
它自己的 lint 门**。`make lint` 因此对任何版本恒定失败——失败签名从
BUG-0014/0019 的"编译期中止"变成了"tb/ 范围告警"，但"恒红"这一点未变。

## fix

未派发。**修复前须先分诊**，不得直接"清 lint"：

- 分诊卡（DV）：逐条判定 259 条告警的性质，区分「真缺陷」/「风格」/
  「误报（工具对某构造的保守告警）」。真缺陷部分按 taxonomy 各自登记
  失败记录并单独修复 + 复验；风格部分再谈是否统一清理。
- **硬性红线**：不得通过放宽 `lint:` 目标的过滤范围、加 `+lint` 豁免、或
  从 flist 摘除文件来"让 lint 通过"（`workflow/discipline.md` rule 2 的
  gate 例外条款：门禁是产品本身，不得为了让自己的卡过关而放宽它）。
- 分诊出的任何**真缺陷**若影响已登记的 ✅ 场景判据，须重跑对应场景并重登
  证据——现有 PASS 证据的有效性取决于分诊结论。
