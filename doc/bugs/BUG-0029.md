# BUG-0029 — `make evidence BUG=` 无法承载非仿真类复验，关闭件与实质证据脱节

## symptom

BUG-0014 / BUG-0019 是**编译期**缺陷（`make lint` 的旗标缺失），其复验判据是
`make lint` 的输出——`Error-[SE]` 归零、`Top Level Modules:` 收敛、过滤逻辑
真正执行。但框架规定的机械关闭路径 `make evidence BUG=<ID> TEST=… SEED=…`
**只能读仿真日志**：`svacheck.judge` 对没有 UVM/VCS 运行横幅的日志直接以
`NOSUMMARY` 退出。

于是 REV-010 关闭这两条时，只能拿一次**与缺陷无关**的通过运行
（`m2_or03_guard_test SEED=1`）当关闭件，而真正的复验证据只存在于
`doc/review/REV-010.md` 的正文里。

即：`verify_evidence` 列指向的文件，**不是**证明该 bug 被修好的那份材料。

## taxonomy

TOOL_ENV

## rca

1. `make evidence BUG=…` 的设计前提是「bug 由某个 TEST+SEED 的仿真复现、
   修复后同一 TEST+SEED 跑通」——这覆盖了绝大多数 DUT/TB 缺陷。
2. 但 `TOOL_ENV` 与构建/门禁类缺陷的复验判据是**编译期或工具输出**，不产生
   合规的仿真日志。
3. `svacheck.judge` 两腿制 fail-closed（正确设计），对无横幅日志直接拒收。
4. 关闭路径因此只剩「借一次无关的通过运行」，`verify_evidence` 与实质证据脱节。

本仓库此类 bug 占比很高：BUG-0014/0017/0019/0020/0022/0026/0028 七条的复验
判据都不是仿真结果。

## fix

未派发（`scripts/evidence.py` 是 pinned snapshot，本地不可改）。已登记
`doc/fw-feedback.md` **FB-16** 回流框架。

建议方向（见 FB-16）：让 `make evidence BUG=` 接受非仿真判据——例如
`CMD=<复验命令>` 形式，把命令与其输出一并记入证据文件，判据改为「命令
退出码 + 人工声明的期望签名」；或至少允许 `verify_evidence` 引用一份
rev 评审记录并在 schema 中承认该形态。

## 对已关闭条目的影响

**BUG-0014 / BUG-0019 的关闭结论本身成立**——REV-010 做了实质复验并逐项
记录（错误签名归零、顶层收敛、过滤逻辑 true-positive 分支工作）。受损的只是
**证据的可追溯性**：从 `doc/bugs.md` 的 `verify_evidence` 列点进去看不到那些
事实，必须转读 `doc/review/REV-010.md` §2.1。
