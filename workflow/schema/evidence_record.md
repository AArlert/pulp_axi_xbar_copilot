# Evidence record contract

An evidence record is a **machine-generated excerpt** of a simulation log,
written by `kernel/evidence.py` — never by hand. It is the only thing that
can turn a testplan scenario ✅ or close a bug. Records live in
`doc/evidence/v<version>/<ID>.log` and are the only `*.log` files allowed
into git (enforced by the `.gitignore` template).

## Field contract

| # | Field | Where | Required | Written by | Validated by |
|---|---|---|---|---|---|
| 1 | Replay command | line 1 | yes | evidence.py | docs-check: ✅ rows must point at a record whose line 1 contains `TEST=` and `SEED=` |
| 2 | Generator signature | line 2, `# Generated by scripts/evidence.py on <date>, source log: <path>` | yes | evidence.py | six-questions Q6 (human/rev spot check) |
| 3 | `# spec_ref: <SPEC-x.y[, ...]>` | header comment | convention now, hard check deferred | evidence.py `--spec-ref` | deferred (see docs/deferred.md) |
| 4 | `# coverage_delta: <...>` | header comment | optional | evidence.py (manual value; xcov auto-capture deferred) | deferred |
| 5 | Result excerpt | body | yes | evidence.py | must show zero `UVM_ERROR`/`UVM_FATAL` (UVM logs) or the VCS completion marker with zero `Error`/`Fatal` lines (plain logs) |
| 6 | Coverage summary lines: the tb prints one line per covergroup, `[FCOV_SUMMARY] <cg> samples=<n> inst_cov=<pct>` | body, `## Key check lines` | when functional coverage exists | tb prints, evidence.py captures | canon `KEY_LINE_RE` knows the tag (no project config needed); further project-specific tags ride `key_line_extra` in `iverif.json`. Rationale: the coverage **numbers** must live in the evidence itself, or milestone signoff has to re-open source logs — the self-sufficiency this record exists to provide |

## Hard rules

- **FAIL logs are never evidence.** evidence.py refuses to register a log
  with errors; failures go through the bug loop (`schema/failure_record.md`).
- **The record must be replayable as written.** Copying line 1 into the
  project's `sim/` must reproduce the run: same test, same seed. Tool
  version and DUT version are implied by the repo state at the evidence's
  commit — which is why evidence lands in the same commit as the code it
  certifies.
- **Backfill is the script's job.** evidence.py updates the testplan row
  (status → ✅, evidence path, replay command) itself. Humans and agents
  never edit those three columns.

## Canonical example

```
make run TEST=m2_01_smoke_test SEED=20260719
# Generated by scripts/evidence.py on 2026-07-19, source log: sim/out/m2_01_smoke_test_20260719.log
# spec_ref: SPEC-4.2.1
```
